# 에코에이블 LCA 프로젝트 관리 (가칭)

앱을 열면 **홈** 탭에서 진행 프로젝트 수·자료 수집률·받은 자료 승인률·확인 필요 프로젝트와 우선 할 일을 봅니다. **프로젝트** 탭은 기존 목록·단계·필터 화면입니다. 홈의 비율에는 실제 건수와 집계 범위를 표시하며 프로젝트 전체 진행률로 해석하지 않습니다. 구문·초기 표시만 확인했고 전체 계산·이동 흐름의 실제 시험은 남아 있습니다. [WEB-035 SPEC](docs/04-webapp-spec/WEB-035-home-dashboard.md)을 참고하세요.

할 일의 분류 버튼 아래에 선택한 분류의 뜻을 한 줄로 표시합니다. **최신 기록 확인**은 저장된 기록을 다시 읽어 목록을 계산하는 버튼입니다. [WEB-034 SPEC](docs/04-webapp-spec/WEB-034-task-kind-help.md)을 참고하세요.

주 메뉴의 **할 일**에서 자료 기한 초과·마감 임박·보완·검토, 미종결 고객 의견·검증 지적, 확인할 정보를 모아 봅니다. 유형·담당 연구원·검색으로 고르고 제목을 눌러 관련 기록으로 이동합니다. 별도 할 일 입력·저장 없이 원래 기록으로 계산합니다. 구문·초기 표시만 확인했고 전체 동작의 실제 시험은 남아 있습니다. [WEB-033 SPEC](docs/04-webapp-spec/WEB-033-tasks-tab.md)을 참고하세요.

자료 요청의 **여러 자료 한 번에 등록**과 **자료 하나 등록**은 각각 제목을 눌러 접고 펼칩니다. 처음에는 둘 다 접혀 있고, 접어도 작성 중인 내용은 열린 상세 안에서 유지됩니다. [WEB-032 SPEC](docs/04-webapp-spec/WEB-032-request-form-disclosures.md)을 참고하세요.

자료 요청 탭의 **여러 자료 한 번에 등록**에서 필요한 구분을 골라 기본 문장과 공통 제출 기한으로 일괄 등록합니다. 기존 구분은 건너뛰며 자료 하나 등록과 상태 필터를 함께 유지합니다. 등록은 메일 발송이나 단계 이동을 하지 않습니다. 구문·초기 배치만 확인했으며 실제 저장 흐름의 확인은 남아 있습니다. [WEB-031 SPEC](docs/04-webapp-spec/WEB-031-batch-data-requests.md)을 참고하세요.

보고서·고객 검토·검토·검증·인증·등록의 **기록 담당자**는 이름을 접어 보여주고 필요할 때 펼쳐 수정하거나 등록 연구원에서 선택합니다. 실제 날짜는 **오늘·달력**으로 입력하며 다음 검증 차수에는 이전 기관·담당자를 불러옵니다. 기존 이력과 작성 중인 입력을 유지합니다. 구문·초기 화면 배치만 확인했으며 저장 흐름의 실제 확인은 남아 있습니다. [WEB-030 SPEC](docs/04-webapp-spec/WEB-030-input-assistance.md)을 참고하세요.

상세의 **검토·검증** 탭에서 **미정 / 내부 검토 / 외부 검토(제3자 검증)**를 선택합니다. 내부 확인으로 보고서를 확정하거나 외부 기관의 차수·지적 처리로 이어집니다. 판단 근거와 보고서별 내부 검토 기록을 보관하며 후속 제출의 완료 근거에도 연결합니다. [WEB-029 SPEC](docs/04-webapp-spec/WEB-029-review-route.md)에 범위와 확인 한계를 정리했습니다.

**인증·등록** 탭에서 검증 완료일·결과 문서 이름과 최종 보고서/검증 기록 사본을 보관하고, 별도 확인 후 8→9로 이동합니다. 인증·등록 또는 고객 제출을 선택하고 제출 준비→제출 완료→보완 요청→승인·등록/반려, 번호·날짜·변경 이력을 기록합니다. 9단계 이후 이전 평가·보고서·검증은 읽기 전용이며 만료·갱신·수정 보고서 재제출은 후속입니다. 구문·초기 화면만 확인했으며 실제 저장 흐름 검증은 남아 있습니다. [WEB-028 SPEC](docs/04-webapp-spec/WEB-028-certification-registration.md)을 참고하세요.

**제3자 검증** 탭에서 검증 시작(7→8), 검증기관·담당자, 1차·2차 등 차수별 지적·보완 기한·답변·수정 보고서와 종결 근거를 기록합니다. 검증 중에도 해석과 보고서를 보완하고 이전 차수는 보관합니다. [WEB-027 SPEC](docs/04-webapp-spec/WEB-027-third-party-verification.md)에 조건과 확인 범위를 정리했습니다.

프로젝트 상세의 **고객 검토** 탭에서 보고서 버전별 의견·담당자 답변·수정 반영 버전·처리 이력을 기록합니다. 열림→답변됨→종결과 사유를 남기는 재개를 제공하며, 보고서 새 버전의 변경 기록에 관련 의견을 연결할 수 있습니다. [WEB-026 SPEC](docs/04-webapp-spec/WEB-026-customer-review-comments.md)에 조건과 확인 범위를 정리했습니다.

보고서의 **보고서 내려받기**를 펼쳐 PDF·Word(.docx)·글 파일(.md)을 선택하고 공통 **내려받기**를 누를 수 있습니다. 문서는 저장된 사본을 기준으로 브라우저에서 만들며 글꼴과 도구가 저장소에 포함돼 있습니다. PDF 양식·한글·단위·숫자와 DOCX 본문 구조를 확인했습니다. Word에서의 최종 시각적 배치는 번들 렌더러가 없어 미확인입니다. [WEB-023 SPEC](docs/04-webapp-spec/WEB-023-report-document-export.md)에 범위와 확인 한계를 기록했습니다.

에코에이블컨설팅㈜ 전과정정책본부의 **제품 전과정평가(LCA) 컨설팅** 업무를 돕는 프로젝트 관리 앱입니다. LCA에서 가장 오래 걸리고 자주 막히는 **고객사 데이터 수집**을 중심으로, 프로젝트를 계약부터 사후관리까지 한 화면에서 관리합니다.

> ⚠️ 이 저장소는 박기나가 에코에이블컨설팅 지원을 위해 만든 **포트폴리오용 시연 프로젝트**입니다. 에코에이블컨설팅의 공식 서비스가 아니며, 모든 회사·인물·프로젝트 데이터는 가상입니다.

## 웹앱 실행 (개발 중)

```bash
cd web
python -m http.server 5180 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:5180` 을 엽니다. 배포 후에는 공개 링크로 열 수 있습니다.

**설계서 v02 9-3장의 가상 프로젝트 7개**를 기본 샘플로 제공하며, 새 가상 프로젝트를 직접 등록할 수 있습니다. 10단계 선택 필터와 프로젝트 상세의 개요·범위를 제공합니다.
회사·제품·목적·현재 단계·목표일을 보여주며 휴대폰에서는 카드로 표시합니다.
위쪽의 10단계 버튼으로 단계별 건수를 보고 해당 프로젝트만 골라 볼 수 있습니다. 같은 단계를 다시 누르거나 '전체 보기'로 해제합니다.
프로젝트 번호를 누르면 목적·세부 동인·결과 활용처와 평가 기준량·경계의 설명을 읽을 수 있습니다.
'목록으로' 돌아오면 이전 단계 필터와 보던 위치가 유지됩니다.
'용어사전'에서 40개 용어의 쉬운 뜻·가상 예시·참고 출처를 읽고 한글·영문·약어로 검색할 수 있습니다.
프로젝트와 사전을 오가도 보던 목록·상세와 사전 검색어가 유지됩니다.
상세의 '자료 요청'에서 구분·요청 내용·제출 기한을 등록하고 구분별 지침 참고 근거를 확인할 수 있습니다.
요청은 프로젝트별로 연결해 이 브라우저에 저장하며, 새로고침 후에도 복원합니다. 등록 시 상태는 '요청'이고 실제 메일을 보내지는 않습니다.
각 요청을 삭제하면 현재 목록·건수에서 빠지고, '삭제한 자료 요청'에서 원래 내용으로 복원할 수 있습니다.
제출 기한은 숫자 8자리(예: 20261023)로 입력하면 2026-10-23으로 정리하며 연도는 4자리까지입니다. 달력 선택도 지원합니다.
각 요청의 '받은 자료 기록'에서 값·단위 또는 문서 설명, 자료 기간·증빙 파일 이름을 저장하면 '제출됨'으로 표시합니다. 저장한 받은 자료는 다시 열어 확인·수정할 수 있습니다.
부피 단위는 밀도도 함께 기록하며, 파일 내용 업로드와 환경영향 계산은 포함하지 않습니다.
받은 자료의 '검토 시작'에서 담당자가 요청한 기간·제품/사업장·항목과 증빙을 확인하고 체크·메모를 저장합니다. 세 항목 확인 후 승인하거나, 사유를 적어 보완 요청할 수 있습니다.
받은 자료를 다시 저장하면 이전 체크와 결과를 초기화하고 '제출됨'으로 돌아갑니다. 검토 결과와 보완 사유는 브라우저에 보관합니다.
자료 요청 목록의 전체·요청·제출됨·검토 중·보완 요청·승인 버튼에서 현재 프로젝트의 상태별 건수를 보고 해당 자료만 골라 볼 수 있습니다. 필터는 프로젝트 단계나 자료 상태를 바꾸지 않습니다.
상단 '데이터 수집' 단계를 누르면 그 아래에도 상태별 하위 필터와 수집 단계 프로젝트들의 자료 목록이 나타납니다. 상세에 들어가지 않고 회사·자료·상태·기한을 보고, 필요할 때 '자료 보기'로 해당 요청을 바로 열 수 있습니다. 기존 회사별 상세 필터도 유지합니다.
프로젝트 등록·수정과 나머지 기능은 하나씩 함께 구현합니다.
`web/js/constants.js`·`rules.js`의 나머지 v02 규칙은 해당 기능을 만들 때 반영합니다.

수집 단계의 상세에는 **자료 수집 완료 · 검토 시작** 버튼이 있습니다. 현재 프로젝트의 요청이 최소 한 건이고 모두 제출됐다면 별도 버튼으로 데이터 검토 단계로 이동합니다. 0건이거나 요청·보완 요청이 남으면 부족한 항목을 안내합니다. 단계 이동으로 자료를 자동 승인하지 않으며 목록의 수집 D-day는 자료 수집 완료로 바뀝니다. [WEB-018 SPEC](docs/04-webapp-spec/WEB-018-collection-to-review.md)에 조건과 확인 결과를 기록했습니다.

수집·검토 완료 확인과 단계 이동 버튼은 **자료 요청 탭 상단**에서 요청 폼·목록과 함께 확인합니다. [WEB-025](docs/04-webapp-spec/WEB-025-collection-panel-placement.md)에 배치 교정을 기록했습니다.

검토 단계의 상세에는 **승인 건수와 미승인 자료 목록**을 표시합니다. 현재 프로젝트의 모든 자료를 승인하면 **자료 검토 완료 · 계산 단계로** 버튼으로 계산(모델링) 단계에 들어갈 수 있습니다. 요청이 0건이거나 미승인 자료가 있으면 이동을 막습니다. 실제 환경영향 계산은 아직 포함하지 않습니다. [WEB-019 SPEC](docs/04-webapp-spec/WEB-019-review-to-modelling.md)에 조건과 확인 결과를 기록했습니다.

상세의 **계산 자료·결과**에서는 승인 원자료를 CSV로 내려받고, 외부 도구에서 계산한 지표·값·단위와 도구/DB/평가 방법/할당 근거를 기록합니다. 결과는 계산 단계 이후 모든 자료가 승인됐을 때 저장하며, 당시 승인 자료와 평가 범위를 함께 보관해 근거가 바뀌면 재계산 확인을 안내합니다. CSV는 원래 활동량을 보존하며 제품 기준량당 값으로 자동 환산하지 않습니다. 파일은 이름만 기록합니다. [WEB-020 SPEC](docs/04-webapp-spec/WEB-020-approved-export-external-results.md)에 범위와 확인 결과를 기록했습니다. **앱 내부 LCA 계산은 AI 연결처럼 기획한 기본 기능을 모두 구현한 뒤 검토합니다.**

상세의 **보고서** 탭에서는 최신 계산 결과에 맞는 해석을 확인하고 별도 **보고서 작성 시작**으로 6→7단계에 들어갑니다. 승인 자료·평가 범위·계산 결과·해석을 모으고, 변경 내용·사유·전후 내용·작성자를 적어 **새 버전으로 보관**합니다. 이전 버전과 당시 근거는 그대로 남으며 버전을 선택해 본문과 변경 기록을 읽고 두 버전의 내용 차이를 볼 수 있습니다. 펼침 메뉴에서 PDF·Word·글 파일 형식을 골라 선택 버전을 내려받도록 연결했습니다. 과거 버전은 확인 후 과거 보관본 표시를 붙입니다. 초기 단계는 [WEB-022](docs/04-webapp-spec/WEB-022-report-draft.md), 최신 저장·변경 보호와 실행 검증 제한은 [WEB-024 SPEC](docs/04-webapp-spec/WEB-024-report-version-history.md)을 참고하세요. 고객 검토 의견 엔터티와 정식 제도별 보고서 양식은 후속 범위입니다.

## 기술

- 웹앱: HTML · CSS · JavaScript (프레임워크·빌드 도구 없음), 브라우저 저장(localStorage), 규칙 기반 메일 템플릿
- 시연 앱: Salesforce (Custom Object, Flow, Apex, LWC, Prompt Builder)
- 디자인 참고: 에코에이블컨설팅 홈페이지의 글꼴(Pretendard)과 색 분위기 (로고는 사용하지 않음)


범위 상태는 **미정·고객 요청안·협의 중·확정**으로 별도 표시합니다. 계약·범위 정의 단계 상세에서 범위 정보를 저장하고, 범위 정의 단계의 확정안은 별도 **데이터 수집 시작** 버튼으로 넘깁니다. 확정 저장만으로 단계가 바뀌지는 않습니다. 시연은 해든솔라(범위 정의·협의 중)에서 시작할 수 있습니다. 최소 준비 조건과 검증 한계는 [WEB-010 SPEC](docs/04-webapp-spec/WEB-010-scope-status.md)을 참고하세요.

협의 메모를 범위 정보와 함께 저장할 수 있습니다. 프로젝트 상세의 범위 상태 버튼을 누르면 범위 기록으로 바로 이동합니다. 기존 기록 호환과 확인 한계는 [WEB-011 SPEC](docs/04-webapp-spec/WEB-011-scope-memo-shortcut.md)에 기록했습니다.

목록의 **새 프로젝트 등록**에서 회사명·제품명·목적·목표일을 입력하면 계약·착수 단계와 범위 미정으로 시작합니다. 샘플 다음 번호를 자동 발급하며 기존 범위·자료·검토 기록과 함께 브라우저에 보관합니다. 등록의 범위·예외·확인 한계는 [WEB-012 SPEC](docs/04-webapp-spec/WEB-012-project-create.md)을 참고하세요.

계약 단계 상세 위쪽에서 **고객 담당자·담당 연구원**을 저장한 뒤 **범위 정의 시작**으로 다음 단계에 들어갈 수 있습니다. 등록→담당자→범위 정의→확정→수집 흐름과 기존 기록 호환은 [WEB-013 SPEC](docs/04-webapp-spec/WEB-013-kickoff-to-scope.md)에 정리했습니다.

**담당 연구원** 메뉴에서 가상 연구원을 등록하고 담당 프로젝트를 조회할 수 있습니다. 계약 단계 상세에서 연구원을 고유 번호로 선택하며, 샘플 7개에도 가상 고객 담당자·연구원을 배정했습니다. 기존 이름 기록 보호와 동명이인 구분은 [WEB-014 SPEC](docs/04-webapp-spec/WEB-014-researchers.md)에 정리했습니다.

프로젝트 표 제목 옆에서 회사·제품·번호·연구원을 검색하고 담당 연구원·목적을 단계 필터와 함께 적용할 수 있습니다. 목록에는 담당 연구원을 표시하며 상세의 이름을 누르면 해당 연구원의 담당 프로젝트로 이동합니다. [WEB-015 SPEC](docs/04-webapp-spec/WEB-015-project-search-researcher-link.md)에서 조건 조합과 검증 한계를 확인할 수 있습니다.

목록에는 **프로젝트 목표일 D-day**와 **자료 수집 마감일 D-day**를 함께 표시합니다. 자료 요청이 없어도 수집 마감일이 있으면 계산하며, 아직 협의하지 않은 날짜는 **미정**으로 둡니다. 상세의 자료 수집 일정에서 계약·범위·수집 단계의 날짜를 저장하거나 비울 수 있습니다. 데이터 검토 이후 단계는 **자료 수집 완료**로 표시합니다. 개별 요청의 제출 기한과 승인 여부는 따로 관리합니다. [WEB-017 SPEC](docs/04-webapp-spec/WEB-017-collection-deadline.md)에서 최신 동작과 확인 범위를 볼 수 있습니다.

상세의 **결과 해석**에서는 최신 승인 자료와 일치하는 외부 계산 결과를 확인하고 별도 버튼으로 5→6단계를 시작합니다. 담당자가 주요 결과·영향이 큰 원인·개선 검토안·가정과 한계를 직접 기록합니다. 계산 결과가 바뀌면 이전 해석을 보존하고 재확인을 안내합니다. 해석 저장으로 보고서 단계가 시작되지는 않습니다. [WEB-021 SPEC](docs/04-webapp-spec/WEB-021-result-interpretation.md)에 구현 범위와 실제 UI 확인 내용을 기록했습니다. 이번 변경은 자동 테스트 추가·실행 없이 구문 검사와 실제 화면으로 확인했습니다.
