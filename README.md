# LCA 프로젝트 관리

가상 고객사의 LCA 업무를 연습하기 위해 만든 **학습용 프로젝트 관리 프로그램**입니다.
평가 범위를 협의하고, 필요한 자료를 요청·검토하며, 결과와 보고서를 정리하는 흐름을 익히고자 제작했습니다.

**[프로그램 바로 열기](https://lca-project-manager-kina2002.flowy-pony-5289.chatgpt.site)**

설치나 로그인 없이 사용할 수 있습니다. 고객사와 기본 프로젝트는 가상 시나리오이며, 에코에이블컨설팅 지원을 위한 개인 포트폴리오입니다.

## 왜 만들었나요?

낯선 업무를 문서로 조사하는 데서 나아가, 직접 고객사 상황을 설정하고 프로그램을 사용하며 이해하고 싶었습니다.
고객에게 무엇을 확인하고 어떤 자료와 판단 근거를 남겨야 하는지 정리하면서 기능을 구성했습니다.

## 무엇을 할 수 있나요?

| 주요 기능 | 할 수 있는 일 |
| --- | --- |
| 프로젝트·담당자 관리 | 프로젝트를 등록하고 현재 단계, 담당 연구원, 기한 확인 |
| 평가 범위 협의 | 기준량·평가 범위·자료 기간·적용 기준과 상태별 메모 기록 |
| 자료 요청·검토 | 필요한 자료 목록, 받은 값·단위·출처, 보완 요청·승인 기록 |
| 결과·보고서 정리 | 외부 도구에서 산정한 결과 등록, 보고서 버전과 검토 의견 보관 |
| 업무 확인 | 인증 관련 기록·일정, 먼저 확인할 일, 용어 검색 |

## 먼저 이렇게 둘러보세요

1. 프로그램에서 **프로젝트**를 눌러 가상 고객사 목록과 업무 단계를 확인합니다.
2. 프로젝트 번호를 눌러 **개요·범위**에서 제품과 고객 요청 내용을 살펴봅니다.
3. **자료 요청**에서 요청 목록과 받은 자료를 기록·검토하는 화면을 확인합니다.
4. 낯선 용어는 **용어사전**에서 검색합니다.

입력한 기록은 현재 브라우저에 저장됩니다. 다른 기기로 옮길 때는 **설정 → 백업 내려받기·복원**을 사용합니다.

## 직접 맡은 일과 개발 도구

- **본인:** 관련 업무 조사, 가상 프로젝트 흐름과 기능 요구사항 정리, 프로그램 사용 중 불편 발견, 수정 결과 확인.
- **Codex:** 요구사항에 따른 코드 작성·수정과 문서화 지원.
- **사용 기술:** HTML, CSS, JavaScript. 서버 없이 브라우저에서 실행하는 방식으로 제작했습니다.

## 사용하며 제안한 개선 사례

가상 프로젝트를 사용하고 화면을 확인하는 과정에서 발견한 불편과, 요구사항으로 정리해 반영한 내용입니다.

| 불편했던 점 | 제안하고 반영한 내용 |
| --- | --- |
| 고객의 최초 요청과 추가 협의 내용이 같은 메모에 섞였습니다. | [범위 상태별 메모](docs/04-webapp-spec/WEB-070-scope-status-memos.md)를 따로 보관하고, 상태를 바꾸면 해당 메모를 보여주도록 했습니다. |
| 자료 상태를 보려면 프로젝트 상세까지 여러 번 들어가야 했습니다. | [데이터 수집 단계 안에 상태별 건수와 필터](docs/04-webapp-spec/WEB-009-request-status-filter.md)를 추가했습니다. 한 회사의 많은 자료를 살펴볼 때 쓰도록 기존 상세 필터도 유지했습니다. |
| 기한이 지난 것과 검토·보완 중인 것, 업무가 끝난 것을 어떻게 구분할지 혼동됐습니다. | [기한과 업무 상태를 구분](docs/04-webapp-spec/WEB-016-deadlines.md)해 D-day와 상태를 함께 표시했습니다. 기한이 지난 미완료 항목은 D+로 계속 세고, 자료는 승인, 프로젝트는 완료일 때 숫자 표시를 멈추도록 했습니다. |
| 낯선 LCA 용어 때문에 화면의 항목을 이해하기 어려웠습니다. | 쉬운 뜻과 가상 예시를 확인할 수 있는 [검색 가능한 용어사전](docs/04-webapp-spec/WEB-004-glossary-search.md)을 추가했습니다. |

## 현재 진행 상황과 다음 계획

프로그램을 공개 배포했으며, 가상 고객사 시나리오로 기능을 점검하고 UI를 개선하고 있습니다.
기능별 확인 범위와 남은 점검은 [SPEC](docs/04-webapp-spec/README.md)과 [체크리스트](CHECKLIST.md)에 기록합니다.

앞으로는 다음 기능을 검토할 계획입니다.

- 메일·첨부자료에서 필요한 항목을 정리하고 사람이 확인하는 AI 입력 보조.
- 여러 기기에서 같은 기록을 이어 사용할 수 있는 서버 저장.

<details>
<summary>코드와 로컬 실행 방법</summary>

화면과 기능 코드는 [web](web/) 폴더에 있습니다. 조사·설계·기능 명세는 [docs](docs/)에 정리했습니다.

Python이 설치되어 있다면 프로젝트 폴더에서 아래 명령으로 실행할 수도 있습니다.

```bash
python -m http.server 5180 --bind 127.0.0.1 --directory web
```

브라우저에서 [http://127.0.0.1:5180](http://127.0.0.1:5180)을 엽니다. 공개 주소의 기록과 로컬 주소의 기록은 각각 따로 저장됩니다.
