# 에코에이블 인증 관리 앱

> **전과정정책본부 연구원**이 사용하는 앱이며, **고객사 제품의 EPD·환경성적표지 인증 컨설팅 진행과 데이터 수집**을 처리하고, **데이터 수집률과 기한을 넘긴 데이터 요청**을 확인합니다.

에코에이블컨설팅(주) 전과정정책본부의 LCA(전과정평가)·EPD 인증 컨설팅 업무를 참고해 만든 Salesforce101 미니 프로젝트입니다. 모든 회사·인물 데이터는 가상입니다.

## 왜 만들었나
LCA를 산정하려면 고객사에서 원료 투입량, 전력 사용량, 운송 정보 같은 활동 데이터를 받아야 합니다. 데이터가 늦거나 빠지면 산정 착수가 밀리는데, 어떤 항목이 남았는지 사람이 일일이 확인해야 했습니다. 이 앱은 **연구원이 "받았다 / 다시 요청한다"만 표시하면 수집률 계산, 기한 초과 표시, 다음 단계 전환을 Salesforce가 자동으로 처리**하도록 합니다.

## 구성
| 구분 | 이름 | 설명 |
|---|---|---|
| 앱 | 에코에이블 인증 관리 | 에코에이블 홈 · 프로젝트 · 요청 항목 · 할 일 · 고객사 · 고객 담당자 · 직원 탭 |
| 홈 | **에코에이블 홈** 탭 (`EcoAble_Home` 앱 페이지 + LWC `ecoableHome` + Apex `EcoAbleHomeController`) | 숫자 칸 7개(진행 중 프로젝트, 전체 데이터 수집률, 기한 초과, 3일 안에 마감, 보완 요청, 정보가 빈 프로젝트, 열린 메일 할 일, 누르면 해당 목록으로 이동), 단계별 프로젝트 수(누르면 그 단계만), 프로젝트 현황표(손이 많이 가는 순서, 수집률 막대, 주의 표시, 다음 마감, 목표 인증일, 추천 메일), 주의가 필요한 요청 항목, 열린 메일 할 일. **프로젝트가 많아져도 보기 쉽게:** 거르기 줄(주의 필요만 기본 켜짐, 담당 연구원, 검색, 인증 완료도 보기. 검색어를 치면 숨겨 둔 프로젝트까지 모두에서 찾음), 목록마다 10개씩 + "10개 더 보기" + 전체 목록 바로가기. 숫자 칸은 집계 쿼리(COUNT)로 세어 데이터가 많아도 정확. 메일 추천은 AI 메일 초안 버튼과 같은 규칙 사용 |
| ★ 오브젝트 | 인증 컨설팅 프로젝트 (`EPD_Certification_Project__c`) | ECP-0001~. 인증 종류, 진행 단계(접수 → 데이터 수집 → LCA 산정 → 검증 심사 대응 → 인증 완료), 목표 인증일, 데이터 수집률 |
| ★ 오브젝트 | 데이터 요청 항목 (`Data_Request_Item__c`) | DRQ-0001~. 프로젝트의 하위(주종 관계). 데이터 구분, 상태(요청 / 수령 / 보완 요청), 제출 기한, 수령일 |
| 기존 오브젝트 | Account / Contact / 직원(`Employee__c`) | 고객사 / 고객사 데이터 담당자 / 담당 연구원 |
| 화면 | **진행 단계 막대(Path)** `EPD_Project_Stage` + 프로젝트 화면 `EPD_Project_Record_Page` | 프로젝트 화면 맨 위에 접수 → 데이터 수집 → LCA 산정 → 검증 심사 대응 → 인증 완료 막대 표시. 단계마다 꼭 볼 칸(예: 접수 = 고객 담당자·목표 인증일·확인 필요 정보)과 "이 단계에서 할 일" 안내 제공. 기본 화면과 같은 구성의 전용 화면을 만들어 조직 기본 화면으로 지정 |
| 화면 | 고객사 화면의 **인증 컨설팅 프로젝트** 목록 | 고객사(Account Layout)에서 그 회사의 프로젝트를 제품·인증 종류·단계·수집률·목표 인증일·담당 연구원과 함께 한눈에 확인 |

```
고객사 ─┬─ 고객 담당자
       └─ 인증 컨설팅 프로젝트 ── 담당 연구원(직원)
              └─ 데이터 요청 항목 (1:N, 주종 관계)
```

## 자동으로 처리되는 것
| 기능 | 방식 | 동작 |
|---|---|---|
| 요청 항목 수 / 수령 완료 수 | 롤업 요약 | 요청 항목을 자동 집계 |
| **요청 항목 만들기 버튼** | **LWC 빠른 작업** `ecoableDataRequestCreator` + Apex `EcoAbleDataRequestController` (프로젝트 화면) | 버튼을 누르면 **데이터 구분** 목록(기본 6개: 원료·에너지·용수·운송·폐기물·포장재)이 체크된 채로 나오고, 필요 없는 자료는 체크 해제, 요청 내용은 기본 문장을 제품에 맞게 바로 수정, **제출 마감일**은 달력에서 선택(기본 14일 뒤). 이미 있는 구분은 "이미 있어요 · 건너뜀"으로 표시하고 만들지 않음. 만들면 "접수" 단계 프로젝트는 "데이터 수집"으로 자동 전환. 구분 목록을 그때그때 읽어 오므로 설정에서 구분 값을 추가하면 창에 자동으로 나타남(기본 문장: "[구분] 관련 연간 데이터(수량·단위 포함)") |
| 데이터 수집률 | 수식 | 수령 ÷ 전체 (예: 4/6 = 67%) |
| 기한 초과 | 수식 + 리스트 뷰 "기한 초과 요청" | 수령 전인데 기한이 지나면 매일 자동 표시 |
| **데이터 수집 완료 시 단계 전환** | **Record-Triggered Flow** `Advance_Project_When_Data_Collected` | 요청 항목이 "수령"으로 바뀌고 미수령 항목이 남지 않으면, 프로젝트 단계를 "데이터 수집" → "LCA 산정"으로 변경 |
| 수령일 필수 | 유효성 검사 규칙 `Received_Date_Required` | 상태가 "수령"인데 수령일이 비어 있으면 저장 차단 |
| 마감까지 남은 날 / 마감 임박 안내 | 수식 `Days_To_Due__c`, `Due_Soon_Notice__c` + 리스트 뷰 "마감 임박 요청 (3일 이내)" | 미수령 항목의 기한까지 남은 날을 매일 계산하고, D-3·D-1이면 "D-3 안내 / D-1 안내" 표시 |
| **안내·독촉 할 일 자동 생성** | **예약 Flow** `Create_Data_Request_Reminder_Tasks` (매일 16:50 KST) | 미수령 항목이 D-3, D-1이면 "[D-3]/[D-1] … 마감 임박 안내 메일 보내기", 기한이 지났으면 "[기한 초과] … 독촉 메일 보내기"(중요도 높음) 할 일을 프로젝트 소유자에게 생성. 같은 제목의 열린 할 일이 있으면 만들지 않음(중복 방지). 할 일 설명에 사용할 메일 템플릿 안내 |
| **보완 요청 할 일 자동 생성** | **Record-Triggered Flow** `Create_Revision_Request_Task` | 요청 항목의 상태가 "보완 요청"이 되는 **즉시** "[보완 요청] … 보완 요청 메일 보내기 (DRQ-…)" 할 일 생성(설명에 보완 사유 포함). 같은 제목의 열린 할 일이 있으면 만들지 않음 |
| **정보 확인 할 일 자동 생성** | **예약 Flow** `Create_Info_Request_Tasks` (매일 16:50 KST) | 인증 완료 전 프로젝트 중 **확인 필요 정보**가 "없음"이 아니면 "[정보 확인] … 프로젝트 정보 확인 메일 보내기" 할 일 생성(설명에 비어 있는 정보 포함). 같은 제목의 열린 할 일이 있으면 만들지 않음 |
| **마감 임박 사전 안내 메일 초안** | **Prompt Builder (Flex 템플릿)** `EcoAble_Due_Soon_Notice` | 기한이 0~3일 남은 미수령 항목만 골라 친절한 사전 안내 메일 초안 작성. 대상이 없으면 "[프로젝트 번호] [고객사] / [제품]: 3일 이내에 마감되는 미제출 자료가 없습니다."만 출력 |
| **AI 메일 초안 버튼** | **LWC 빠른 작업** `ecoableEmailDraft` + Apex `EcoAbleEmailDraftController` (프로젝트 화면·할 일 화면) | 버튼을 누르면 미수령 자료를 세어 메일 종류를 추천(기한 초과·보완이 있으면 임박 자료까지 담는 **독촉 메일 한 통**, 임박 자료만 있으면 **마감 임박 안내**, 없으면 "보내지 않아도 됨"). 선택한 Prompt Builder 템플릿을 호출해 초안을 보여 주고, 수정 후 **AI 메일 초안** 칸에 저장(검토 상태 "미검토"). 할 일 화면에서 열면 연결된 프로젝트를 자동으로 찾고 **📂 프로젝트 열기** 바로가기 제공. **"메일을 보냈어요"를 체크한 경우에만** 이 메일에 포함된 열린 안내·독촉 할 일을 함께 완료 처리(저장만으로는 자동 완료하지 않아 미발송 누락 방지). 실제 메일 발송은 하지 않음. **고객 담당자가 비어 있으면** AI가 빠뜨려도 버튼이 초안 맨 위에 "※ 고객 담당자 미지정 - 수신자 확인 필요"를 붙임(네 가지 메일 모두, "보낼 내용 없음" 한 줄 응답 제외, 중복 없음) |
| **메일 발송 완료 체크** | 체크박스 `Email_Sent__c` + **Record-Triggered Flow** `Close_Reminder_Tasks_When_Email_Sent` | 프로젝트 화면에서 "메일 발송 완료"를 체크하면, 저장된 **메일 종류**(`Draft_Type__c`)에 맞춰 그 메일에 포함된 열린 할 일만 완료(독촉 메일 → [기한 초과]·[D-3]·[D-1]·[보완 요청], 마감 임박 안내 → [D-3]·[D-1], 보완 요청 → [보완 요청], 정보 확인 → [정보 확인])하고 메일 검토 상태 "검토 완료", **발송 완료 시각** 기록. 버튼으로 새 초안을 저장하면 체크가 풀림(새 메일은 발송 전). 버튼 창의 "메일을 보냈어요" 체크도 같은 칸을 사용 |
| **자료 보완 요청 메일 초안** | **Prompt Builder (Flex 템플릿)** `EcoAble_Revision_Request` | 상태가 "보완 요청"인 항목만 골라, 자료를 보내 준 데 대한 감사로 시작해 보완 사유와 추가로 필요한 내용을 정중히 요청. 대상이 없으면 "[프로젝트 번호] [고객사] / [제품]: 보완을 요청할 자료가 없습니다."만 출력. 이 메일을 보내면 [보완 요청] 할 일만 닫고 기한 기반 할 일은 그대로 둠 |
| **프로젝트 정보 확인 메일 초안** | **Prompt Builder (Flex 템플릿)** `EcoAble_Info_Request` | 어떤 정보가 비었는지는 AI가 추측하지 않고 수식 `Missing_Info__c`(확인 필요 정보)가 계산(인증 완료 제외, 다 채워지면 "없음"). 비어 있는 항목만 번호 목록으로 문의하고, 메모는 질문을 구체화할 때만 사용(예: 평가 범위를 셀·모듈·팩으로). 고객 담당자가 비면 맨 위에 "※ 고객 담당자 미지정 - 수신자 확인 필요". "없음"이면 "[프로젝트 번호] [고객사] / [제품]: 추가로 확인할 프로젝트 정보가 없습니다."만 출력 |
| **메일 종류 추천 규칙** | `EcoAbleEmailDraftController.getDraftContext` | 기한 초과가 있거나 보완+임박이 함께 있으면 🔴 독촉 메일(한 통에 모두 포함) → 보완만 있으면 🟠 보완 요청 → 임박만 있으면 🟡 마감 임박 안내 → 자료 문제는 없고 기본 정보가 비면 🔵 정보 확인 → 그 외 "보내지 않아도 됨" |
| **데이터 제출 요청 메일 초안** | **Prompt Builder (Flex 템플릿)** `EcoAble_Data_Request_Reminder` + Apex | AI는 인사말·안내 문장·맺음말만 쓰고 목록 자리에 `[자료 목록]` 표시를 남김. 버튼(Apex)이 그 자리에 미수령 항목을 **메일 분류** 순서(제출 기한이 지난 자료 → 보완이 필요한 자료(+보완 사유) → 아직 기한 전인 자료)로 정확히 채움. 미수령 항목이 없으면 AI를 부르지 않고 "[프로젝트 번호] [고객사] / [제품]: 현재 요청할 미제출 자료가 없습니다." 한 줄 |
| **메일 분류** | 수식 `Mail_Group__c` (데이터 요청 항목) | 수령 전 항목을 "기한 지난 자료"(기한 초과 우선) / "보완이 필요한 자료" / "아직 기한 전인 자료"로 분류. 요청 항목 관련 목록에도 표시 |
| **보낼 내용이 없을 때** | Apex `nothingToWriteMessage` | 고른 메일 종류에 해당하는 자료·정보가 없으면(예: 보완 요청 자료 0건) AI를 부르지 않고 한 줄 안내만 표시. AI가 없는 자료를 지어내는 것을 막고 AI 호출 비용도 절약 |
| 에코에이블 데이터만 보기 | 체크박스·수식 + 리스트 뷰 | 공용 오브젝트(고객사·담당자·직원)에서 이 앱의 데이터만 필터 |

| ECP-0002 한빛케미칼 / 수성 친환경 도료 | 1건 남음 → 시연용 (수령 처리 시 LCA 산정으로 자동 전환) |
| ECP-0003 누리철강 / 냉연 강판 | 보완 요청 1건 + 기한 초과 1건 |
| ECP-0004 새봄식품 / 500mL 생수 PET병 | 데이터 수집 완료, LCA 산정 중 |
| ECP-0005 다온배터리 / ESS 배터리 팩 | 정보 부족 (담당자·목표일 미정, 요청 항목 없음) |
| ECP-0006 한빛케미칼 / 유성 산업용 도료 | 인증 완료 |

## 시연 순서
1. 앱 실행기 → **에코에이블 인증 관리** → **에코에이블 홈**에서 전체 현황(숫자 칸, 단계별 프로젝트, 프로젝트 현황표, 주의 항목, 메일 할 일) 확인 → "기한 초과 요청" 칸을 눌러 목록으로 이동
2. **ECP-0001** 열기 → 고객사·담당자·연구원 연결과 요청 항목 6건, 데이터 요청 항목 탭의 **기한 초과 요청** 목록
3. **ECP-0002**의 DRQ-0011을 수령일 **없이** "수령"으로 저장 → 차단 메시지 확인
4. 수령일을 넣고 다시 저장 → ECP-0002 수집률 100%, 단계 **LCA 산정**으로 자동 전환
5. **할 일** 탭 → "에코에이블 안내·독촉 할 일"에서 [기한 초과]/[D-1]/[D-3]/[보완 요청]/[정보 확인] 할 일 확인 (기한·정보 확인은 예약 Flow가 16:50에, 보완 요청은 상태를 바꾸는 즉시 생성)
6. 할 일 하나를 열고 **AI 메일 초안** 버튼 → 추천(⭐) 확인 → 독촉 메일 생성 → 수정 → "메일을 보냈어요" 체크 후 저장 → 관련 할 일이 목록에서 사라지는 것 확인
7. **📂 프로젝트 열기**로 이동 → **AI 메일 초안** 칸에 저장된 초안, **메일 검토 상태**를 "검토 완료"로 변경
8. **ECP-0005** 열기 → **확인 필요 정보** 칸 확인 → **AI 메일 초안** 버튼 → 🔵 정보 확인(⭐ 추천) → 맨 위 "※ 고객 담당자 미지정 - 수신자 확인 필요"와 빈 정보 3개만 묻는 질문 확인
9. **ECP-0005**에서 **요청 항목 만들기** 버튼 → 필요한 자료만 체크, 요청 내용 수정(예: "셀·모듈 부품 연간 투입량(kg)"), 마감일 선택 → 만들기 → 요청 항목 생성과 단계 막대가 **데이터 수집**으로 넘어가는 것 확인 (시연 후 되돌리려면 만든 요청 항목을 직접 삭제하고 단계를 "접수"로 변경)

### 데이터 구분 늘리는 방법 (코드 수정 없음)
설정 → 개체 관리자 → **데이터 요청 항목** → 필드 및 관계 → **데이터 구분** → 값 **[새로 만들기]** → 이름 입력 후 저장. 다음에 **요청 항목 만들기** 창을 열면 새 구분이 자동으로 나타납니다.

### 메일 초안 프롬프트를 다듬은 과정
| 시도 | 문제 | 해결 |
|---|---|---|
| 1 | 고객사·담당자·제품 값이 모두 빈칸 | 입력 이름이 소문자 `project`인데 병합 필드를 `Project`로 써서 대소문자 불일치 → `{!$Input:project...}`로 통일 |
| 2 | 요청 내용이 빠짐 | 관련 목록은 페이지 레이아웃의 관련 목록 열을 가져옴 → `Request_Detail__c`를 Text(255)로 바꾸고 관련 목록 열에 요청 내용·보완 사유 추가 |
| 3 | 기한 지난 항목을 "기한 전"으로 분류 | 관련 목록은 API 이름(`Is_Overdue__c` 등)으로 전달됨 → 규칙에도 API 이름으로 조건을 명시 |
| 4 | 빈 묶음에 "없음"을 출력, 미제출 없음 문구에 대상 표시 없음 | 출력 모양 예시 추가, 빈 묶음 금지 규칙 강화, "없음" 문구에 프로젝트 번호·고객사·제품 포함 |
| 5 | 마감 임박 자료가 없는데도 메일을 씀 | 템플릿 맨 위에 **[먼저 확인]** 단계를 두고, 대상이 없을 때의 한 줄 출력 예시를 따로 제시 |
| 6 | 정보 확인 메일에서 AI가 빈칸을 잘못 판단(채워진 정보를 묻거나 빈 정보를 놓침) | 판단을 AI에게 맡기지 않고 수식 `Missing_Info__c`로 Salesforce가 계산해 전달. 빈 값 대신 "없음"을 출력해 오해 방지 |
| 7 | 메모 내용으로 목록에 없는 질문을 추가 | "질문은 확인할 정보 항목만" 규칙 추가, 메모는 질문을 구체화할 때만 사용 |
| 8 | "※ 고객 담당자 미지정" 줄을 빠뜨림 | 규칙에는 있었지만 **예시 편지에 없어서** AI가 예시를 따라감 → 예시 1 맨 위에 ※ 줄을 넣고 [먼저 확인]에 "첫 줄은 반드시 ※" 명시. 추가로 Apex가 담당자 없는 프로젝트의 초안에 ※ 줄을 보장(이중 안전장치) |

| 9 | 최종 점검: 버튼 방식에서 독촉 메일이 오늘 마감 자료를 "보완 필요"로 묶고 없는 보완 사유를 지어냄, 다른 자료는 빠뜨림. 보완할 자료가 없는데 보완 요청 메일을 씀 | AI가 받는 데이터는 정확했지만 매번 결과가 달랐음(미리보기는 맞고 버튼 방식은 2번 모두 틀림). → 보낼 내용이 없으면 Apex가 AI 없이 한 줄 안내. 독촉 메일 목록은 AI가 `[자료 목록]` 표시만 남기고 Apex가 메일 분류 수식대로 채움. 2번씩 다시 뽑아 4번 모두 정확 |

> 배운 점: **AI는 규칙보다 예시를 더 잘 따라 한다.** 그리고 "빈 정보가 무엇인지", "수신자가 있는지"처럼 틀리면 안 되는 판단은 AI가 아니라 수식·Apex가 정하고, AI는 문장 다듬기만 맡기는 것이 안전하다. **목록처럼 정확해야 하는 부분은 AI에게 베껴 쓰게 하지 말고, 빈칸 표시만 남기게 한 뒤 시스템이 채운다.** 미리보기에서 한 번 맞았다고 끝내지 말고, 실제 호출 방식으로 여러 번 뽑아 확인한다.

## 남은 문제와 다음 개선
- **Org 시간대:** 이 Developer Edition의 기본 시간대가 America/Los_Angeles라, 예약 Flow를 한국 오전에 돌리면 "오늘" 날짜가 하루 어긋날 수 있습니다. 날짜가 일치하는 16:50 KST로 예약했고, 실제 운영에서는 Org 시간대를 Asia/Seoul로 맞춘 뒤 오전 실행으로 바꾸는 것이 좋습니다.
- **할 일 담당자:** 할 일은 Salesforce User에게만 배정할 수 있어 프로젝트 소유자에게 만듭니다. 담당 연구원(직원 레코드)과 User를 연결하면 연구원별 배정이 가능합니다.
- **실제 메일 발송 연동:** 지금은 초안 작성·저장까지만 합니다. 고객 담당자 이메일 주소 관리와 Salesforce 이메일 발송(발송 기록 남기기)을 붙이면 "보냈어요" 체크를 발송 결과로 대신할 수 있습니다. Agentforce 대화로 초안을 요청하는 것도 다음 단계입니다(Day3 실습 3 응용).
- **프롬프트 템플릿 소스:** 조직에는 템플릿 4개(독촉·마감 임박·보완 요청·정보 확인)가 활성화되어 있고, 그중 독촉·마감 임박 2개를 `force-app/main/default/genAiPromptTemplates`에 받아 두었습니다(배포 시에는 조직의 활성 버전과 충돌하지 않게 주의). 보완 요청·정보 확인 템플릿은 Prompt Builder 화면에서 직접 만들었습니다.
- **AI 출력의 흔들림:** 같은 프로젝트라도 생성할 때마다 문장이 조금씩 다를 수 있습니다. 그래서 반드시 지켜야 하는 것(빈 정보 판단, 수신자 경고)은 수식·Apex로 정하고, 초안은 저장 후 사람이 검토하도록 "미검토" 상태로 둡니다.
- **할 일 반복 생성 주기:** 기한 초과·정보 확인 할 일을 완료해도, 다음 날 16:50에 여전히 미수령이거나 정보가 비어 있으면 다시 생성됩니다. 매일 알림이 부담스러우면 주기(예: 3일마다)를 조정할 수 있습니다. 보완 요청 할 일은 상태가 바뀔 때 한 번만 생성됩니다.
- **단계 되돌림 미지원:** 보완 요청으로 데이터가 다시 빠져도 LCA 산정 단계를 자동으로 되돌리지는 않습니다.
- **산정 결과 기록:** 탄소발자국(kgCO₂e) 등 LCA 결과값과 검증 심사 이력을 담는 오브젝트 추가
- 기존 데이터 DRQ-0011은 규칙 추가 전에 수령일 없이 저장된 상태입니다.
