# 롤플레이 실습 기록을 이어 쓰는 방법

2026-10-20 사용자는 지금까지 진행한 롤플레이의 화면·입력 이유·가상 메일·기타 설명을 자세히 기록하고, 앞으로도 누적하여 나중에 PDF로 만들도록 요청했다. 이는 실습 기록 요청이며 새 앱 기능이나 즉시 PDF 발행 요청이 아니다.

## 원본 위치

사용자가 2026-10-20 취침 전에 백업을 아침에 챙기지 않아도 되도록 GitHub에 함께 올려 달라고 명시했다. 이번 가상 실습 원본의 최신 위치는 저장소의 `handoff/roleplay/hanbit-LCA-2026-009/`이며, 앱에 가져올 최신 업무 백업은 `handoff/latest-backup.json`이다. 최신 main을 받으면 원문과 화면도 함께 온다. 이 요청이 이전의 저장소 밖 보관 방침보다 우선한다. [아침 복원 안내](../handoff/README.md)를 따른다.

- `실습기록.md`: 가상 문의/회신, 단계별 입력, 선택 이유, 사실과 미완료 상태, 배운 점과 다음 할 일을 누적한다.
- `실습기록-미리보기.html`: Markdown과 같은 내용의 읽기/인쇄용 미리보기. PDF는 별도 요청 시 제작한다.
- `기록양식.md`: 사건별 공통 양식.
- `화면목록.md`, `images/`: 번호가 있는 실제 화면과 캡션.
- `evidence/`: 화면 텍스트·입력값·원본 출처·파일 목록·개인 업무 백업 사본.

저장소가 비공개임을 확인하고 사용자가 요청한 이번 가상 실습 묶음을 GitHub에 함께 보관했다. 공개 데모의 정적 배포물은 변경하지 않는다. 백업을 Git에서 받은 것과 브라우저에 실제 복원한 것은 구분한다.

## 기록할 때 지킬 것

1. 가상 메일 원문/요약 → 알아낸 사실/미정 사항 → 입력과 조작 → 이유 → 실제 화면 근거 → 저장 결과 → 다음 할 일 순서를 유지한다.
2. 사용자 조작이 있는 실습 진행 뒤에는 실제 화면을 확인하고 가능하면 입력 전/저장 후 화면을 보관한다. 단순 설명도 해당 사건의 이유·배운 점에 추가한다.
3. 사용자 진행 보고, 화면에서 읽은 값, 실제 저장 확인, 다음에 하도록 제안한 일을 구분한다. 캡처를 위해 대신 기준·메모·단계를 바꾸거나 저장하지 않는다.
4. 과거 캡처가 없으면 없다고 적는다. 현재 화면을 과거 저장 순간처럼 표시하지 않는다. 확인할 수 없는 시각을 추정하지 않는다.
5. 새 이미지와 사건 번호를 추가하고 기존 근거를 덮어쓰지 않는다. 촬영 시점·출처·그림 설명과 한계를 함께 남긴다.
6. 다음 노트북/대화에서는 handoff 폴더의 실습기록과 이 안내를 먼저 읽는다. 실제 사용자 기록과 미저장 입력을 보존하고, 이미 요청된 기록 누적을 매번 다시 승인받지 않는다.

## 현재 기록 범위

한빛포장 실습의 최초 요청 요약·프로젝트 등록·범위 입력·적용 기준 설명·담당자 변경·관련 UI 개선·Chrome 공개 사이트 백업 복원·추가 고객 회신 안내를 1차 정리했다. 취침 전 최신 백업 화면을 추가하여 새 캡처 10장과 과거 자료 6장, 총 16장이다. 전체 기능 실행 시험이나 실제 LCA 산정/인증 완료로 해석하지 않는다.

기록 시점에는 범위 정의/고객 요청안이며, 추가 회신 메모와 협의 중 저장은 아직 진행 전이다. 다음 실습 사건 번호는 **R08**부터 사용하고 실제 진행에 따라 기록을 갱신한다. 앱 기능 번호 WEB-070을 기록 문서에 소모하지 않는다.

## 2026-10-22 복원 기록 추가

ChatGPT 앱 내 브라우저에서 최신 백업의 실제 복원·새로고침을 확인했다. 선백업 누락으로 버튼이 비활성화된 원인과 해결 과정을 실습기록 16절에 기록했다. 전날 Chrome 미완료 시도 1장과 이번 복원 3장을 추가하여 실제 캡처 14장·과거 6장, 총 20장이다. 범위 정의/고객 요청안·추가 회신 반영 전 상태를 유지하며 R08은 아직 진행 전이다. Chrome에 이번 기록을 동기화한 것으로 설명하지 않는다.
