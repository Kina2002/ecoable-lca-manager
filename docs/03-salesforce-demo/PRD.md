# 에코에이블 인증 관리 PRD (Salesforce 시연판)

2026-10-15 · 박기나 · 원본: Claude Docs 「에코에이블 인증 관리 PRD」

> 이 문서는 Salesforce Developer Edition으로 먼저 만든 시연 앱의 제품 요구사항이다. 이후 실제 제출용은 Salesforce 없이 웹앱으로 다시 설계했다(`docs/02-design`).

## 개요

에코에이블 인증 관리는 전과정정책본부 연구원이 EPD·환경성적표지 인증 컨설팅 프로젝트의 고객사 데이터 수집을 한곳에서 관리하는 Salesforce 앱이다. 연구원이 자료를 "받았다 / 다시 요청한다"만 표시하면 수집률, 기한 초과, 다음 단계 전환, 알림 할 일, 메일 초안이 자동으로 이어진다.

**배경.** LCA 산정에는 고객사의 원료 투입량, 에너지 사용량, 운송 정보 같은 활동 데이터가 필요하다. 자료가 늦거나 빠지면 산정 착수가 밀리지만, 남은 항목 확인과 독촉 메일 작성은 연구원이 직접 해 왔다.

**해결하려는 문제.**

- 프로젝트별로 받을 자료와 받은 자료를 한눈에 보기 어렵다
- 마감 임박과 기한 초과를 놓치기 쉽다
- 독촉·보완·정보 확인 메일을 매번 새로 쓴다
- 고객 담당자, 목표 인증일 같은 기본 정보가 비어도 프로젝트가 진행된다

## 목표와 성공 지표

목표는 네 가지다. 수집 현황을 보이게 하고, 기한을 놓치지 않게 하고, 메일 작성 시간을 줄이고, 기본 정보 누락을 막는다. 모든 지표는 앱 안의 필드와 리스트 뷰로 측정할 수 있다.

| 목표 | 성공 지표 | 측정 방법 |
| --- | --- | --- |
| 데이터 수집 현황 가시화 | 프로젝트별 데이터 수집률 | 데이터 수집률 필드(수령 완료 수 ÷ 요청 항목 수) |
| 기한 누락 방지 | 미수령 항목 중 기한 초과 비율 | 리스트 뷰 "기한 초과 요청" 건수 ÷ 미수령 건수 |
| 기한 누락 방지 | 자동 생성 할 일 처리율 | "에코에이블 안내·독촉 할 일" 중 완료 비율 |
| 메일 작성 시간 단축 | 초안을 크게 고치지 않고 발송한 비율 | 메일 검토 상태(미검토 / 수정 필요 / 검토 완료) |
| 수집 기간 단축 | 착수일부터 LCA 산정 전환까지 걸린 날 | 착수일과 진행 단계 변경 일자 |
| 기본 정보 완결성 | 확인 필요 정보가 남은 진행 중 프로젝트 수 | 확인 필요 정보 ≠ "없음"인 프로젝트 |

목표치는 정하지 않았다. 실제 도입 시 처음 4주 값을 기준값으로 잰 뒤 정한다.

## 대상 사용자

주 사용자는 담당 연구원이다. 고객사 담당자는 앱에 접속하지 않고 메일로만 요청을 받는다.

| 사용자 | 역할 | 주요 니즈 | 앱에서 하는 일 |
| --- | --- | --- | --- |
| 담당 연구원 (주 사용자) | 프로젝트별 고객사 데이터 수집과 LCA 산정 | 남은 자료와 기한을 빠르게 파악, 메일 작성 시간 단축 | 요청 항목 생성, 수령·보완 표시, 할 일 처리, AI 메일 초안 검토·저장 |
| 본부 팀장 / PM | 프로젝트 포트폴리오와 일정 관리 | 지연 프로젝트와 기한 초과 고객사를 한눈에 확인 | 프로젝트 목록·진행 단계 막대, 기한 초과 리스트 뷰, 고객사별 프로젝트 목록 조회 |
| 고객사 데이터 담당자 (간접 사용자) | 자사 공장의 활동 데이터 제출 | 무엇을 언제까지 보내야 하는지 분명한 안내 | 연구원이 보낸 요청·독촉·보완 메일을 받음 (앱 접속 없음) |
| Salesforce 관리자 | 앱 설정과 운영 | 코드 수정 없이 기준 정보 변경 | 데이터 구분 값 추가, 프롬프트 템플릿 관리, 권한 설정 |

## 핵심 업무 흐름

```
1. 프로젝트 접수 (확인 필요 정보를 수식으로 자동 계산) ──빈 정보 있음──▶ 정보 확인 할 일과 메일
2. 요청 항목 만들기 (구분·요청 내용·마감일 선택)
3. 데이터 수집 (수집률과 마감까지 남은 날 자동 계산) ──미수령 자료──▶ 할 일 자동 생성 ▶ AI 메일 초안 ▶ 발송 기록
        ▲                                                                               │
        └──────────────────────── 자료 제출 후 수령 처리 ◀─────────────────────────────────┘
4. 모든 항목 수령 시 LCA 산정으로 자동 전환
```

왼쪽 줄은 프로젝트의 진행 단계이고, 오른쪽 줄은 자료가 남아 있는 동안 반복되는 알림과 메일이다.

**대표 시나리오**

1. 신규 프로젝트: 접수 후 고객 담당자가 비어 있으면 정보 확인 할 일과 메일로 문의하고, 요청 항목 만들기로 자료를 요청하면 데이터 수집 단계로 넘어간다
2. 마감 관리: D-1 할 일을 열어 AI 메일 초안 버튼으로 마감 임박 안내를 만들고, 보낸 뒤 체크하면 해당 할 일만 완료된다
3. 보완 요청: 받은 자료에 누락이 있어 보완 요청으로 바꾸면 할 일이 즉시 생기고, 보완 요청 메일로 감사 인사와 보완 사유를 전한다
4. 수집 완료: 마지막 요청 항목을 수령 처리하면 진행 단계가 LCA 산정으로 바뀐다

## 기능 요구사항

17개 기능은 모두 구현되어 Developer Edition 조직에 배포되었다. 우선순위는 업무 효과 기준이며, 구현 방식은 SPEC 문서에 있다.

| ID | 기능 | 요구사항 | 우선순위 |
| --- | --- | --- | --- |
| FR-01 | 프로젝트·요청 항목 관리 | 프로젝트(ECP-0001~)와 하위 데이터 요청 항목(DRQ-0001~)을 주종 관계로 관리하고 고객사·고객 담당자·담당 연구원과 연결한다 | P0 필수 |
| FR-02 | 수집률·기한 초과 자동 계산 | 요청 항목 수, 수령 완료 수, 데이터 수집률, 마감까지 남은 날, 기한 초과 여부를 자동 계산한다 | P0 필수 |
| FR-03 | 수령일 필수 | 상태가 "수령"인데 수령일이 없으면 저장을 막는다 | P0 필수 |
| FR-04 | LCA 산정 자동 전환 | 데이터 수집 단계에서 모든 요청 항목이 수령되면 진행 단계를 LCA 산정으로 바꾼다 | P0 필수 |
| FR-05 | 마감·기한 초과 할 일 | 매일 16:50(KST)에 미수령 항목이 D-3, D-1, 기한 초과이면 프로젝트 소유자에게 할 일을 만든다. 같은 제목의 열린 할 일이 있으면 만들지 않는다 | P0 필수 |
| FR-06 | AI 메일 초안 | 독촉, 마감 임박 안내, 보완 요청, 정보 확인 4종 초안을 프로젝트·할 일 화면 버튼에서 만들고, 연구원이 고쳐 저장한다(검토 상태 "미검토"). 자료 목록은 Apex가 채우고, 보낼 내용이 없으면 한 줄 안내만 보여 준다 | P0 필수 |
| FR-07 | 메일 종류 추천 | 기한 초과 또는 보완+임박 → 독촉, 보완만 → 보완 요청, 임박만 → 마감 임박 안내, 자료 문제 없이 기본 정보 누락 → 정보 확인 순으로 추천한다 | P1 중요 |
| FR-08 | 수신자 미지정 경고 | 고객 담당자가 없는 프로젝트의 초안 맨 위에 "※ 고객 담당자 미지정 - 수신자 확인 필요"를 반드시 붙인다 | P1 중요 |
| FR-09 | 발송 기록과 할 일 완료 | "메일을 보냈어요" 또는 "메일 발송 완료"를 체크하면 그 메일에 포함된 할 일만 완료하고 발송 시각을 기록한다 | P1 중요 |
| FR-10 | 보완 요청 할 일 | 요청 항목이 "보완 요청"이 되는 즉시 보완 요청 메일 할 일을 만든다 | P1 중요 |
| FR-11 | 확인 필요 정보·정보 확인 할 일 | 비어 있는 기본 정보(고객 담당자, 목표 인증일, 평가 범위·데이터 요청 항목)를 수식으로 계산하고, 남아 있으면 매일 정보 확인 할 일을 만든다 | P1 중요 |
| FR-12 | 요청 항목 만들기 | 데이터 구분 목록(기본 6개)에서 필요한 자료를 고르고 요청 내용·제출 마감일을 정해 한 번에 만든다. 이미 있는 구분은 건너뛰고, 접수 단계면 데이터 수집으로 넘긴다 | P1 중요 |
| FR-13 | 데이터 구분 확장 | 설정에서 데이터 구분 값을 추가하면 코드 수정 없이 요청 항목 만들기 화면에 나타난다 | P2 편의 |
| FR-14 | 진행 단계 막대 | 프로젝트 화면 맨 위에 5단계 막대와 단계별 핵심 필드·안내를 보여 준다 | P2 편의 |
| FR-15 | 고객사별 프로젝트 목록 | 고객사 화면에 그 회사의 프로젝트를 단계·수집률과 함께 보여 준다 | P2 편의 |
| FR-16 | 업무용 목록 | 기한 초과 요청, 마감 임박 요청(3일 이내), 안내·독촉 할 일, 에코에이블 고객사·담당자·연구원 리스트 뷰를 제공한다 | P2 편의 |
| FR-17 | 홈 현황 화면 | 앱 첫 탭에서 진행 중 프로젝트, 평균 수집률, 기한 초과·임박·보완 요청 건수, 정보가 빈 프로젝트, 열린 메일 할 일, 단계별 프로젝트 수, 프로젝트별 현황과 추천 메일, 주의 항목을 한 화면에 보여 준다. 프로젝트가 많아져도 거르기(주의 필요만·단계·담당 연구원·검색)와 10개씩 더 보기로 필요한 것만 보고, 숫자는 집계 쿼리로 정확하게 센다 | P1 중요 |

## 비기능 요구사항

틀리면 안 되는 판단은 Salesforce 수식과 Apex가 하고, AI는 문장만 쓴다. 이 원칙이 아래 요구사항 전체에 적용된다.

**AI 사용 원칙**

- 빈 정보, 기한, 수신자 유무는 수식·Apex가 계산해 AI에 넘긴다. AI가 빈칸을 추측하지 않는다. 자료 목록도 AI는 [자료 목록] 표시만 남기고 Apex가 메일 분류 수식대로 채운다
- 기록에 없는 내용을 지어내지 않는다. 보낼 내용이 없으면 Apex가 AI를 부르지 않고 한 줄 안내만 보여 준다
- 초안은 저장 시 "미검토" 상태가 되고, 실제 발송은 연구원이 직접 한다
- 메모 속 문장은 데이터로만 다루고 작성 규칙을 바꾸지 않는다

**권한과 보안**

- Apex는 with sharing과 사용자 모드(USER_MODE)로 동작해 사용자 권한 안에서만 조회·수정한다
- 고객사 자료를 외부 AI에 보낼 때는 회사 보안 정책을 따른다

**데이터 품질**

- 같은 제목의 열린 할 일, 같은 구분의 요청 항목은 중복 생성하지 않는다
- 수령 처리에는 수령일이 필수다
- 메일을 보내지 않은 채 초안만 저장하면 할 일을 닫지 않는다

**품질과 운영**

- Apex 테스트 22개, 코드 커버리지 96~99%(배포 기준 75% 이상)
- 모든 배포는 검증 배포(dry-run) 후 실제 배포
- 데이터 구분 추가처럼 자주 바뀌는 기준 정보는 코드 수정 없이 설정에서 바꾼다

## 범위 밖

이번 버전은 데이터 수집 관리까지만 다룬다. 아래 항목은 하지 않는다.

- 실제 이메일 발송: 초안 작성과 저장까지만 하고, 발송은 연구원이 직접 한다
- 고객사 포털: 고객사가 앱에 접속해 자료를 올리는 기능은 없다
- LCA 계산과 결과 저장: 탄소발자국(kgCO₂e) 등 산정 결과는 관리하지 않는다
- 검증 심사 이력 관리
- 연구원별 할 일 배정: 할 일은 프로젝트 소유자에게 배정한다
- 보완 요청 시 진행 단계 자동 되돌림
- 모바일 전용 화면

## 가정, 제약, 리스크

가장 큰 리스크는 AI 출력의 흔들림이며, 수식·Apex 안전장치와 사람 검토로 대응한다.

| 구분 | 내용 | 대응 |
| --- | --- | --- |
| 가정 | SeSAC Salesforce101 미니 프로젝트로, 회사·인물·프로젝트 데이터는 모두 가상이다 | 실제 도입 시 에코에이블의 표준 데이터 수집 양식과 제품군별 작성 지침을 반영한다 |
| 가정 | 요청 내용 기본 문장은 일반적인 LCA 활동 데이터 항목 기준이다 | 연구원이 제품에 맞게 수정한다 |
| 제약 | Developer Edition은 연습용이며, 운영에는 사용자 라이선스와 Prompt Builder용 추가 라이선스가 필요하다 | 도입 전 비용을 검토한다 |
| 제약 | 조직 시간대가 America/Los_Angeles라 예약 실행 시각과 날짜가 한국과 어긋날 수 있다 | 날짜가 일치하는 16:50 KST로 예약했고, 운영에서는 시간대를 Asia/Seoul로 바꾼다 |
| 리스크 | 같은 프로젝트도 AI 문장이 매번 조금씩 다르고, 규칙을 빠뜨릴 수 있다 | 빈 정보는 수식으로 계산, 수신자 경고는 Apex가 보장, 초안은 "미검토"로 저장 |
| 리스크 | 기한 초과·정보 확인 할 일이 매일 다시 생겨 알림 피로가 쌓일 수 있다 | 필요하면 생성 주기를 3일 등으로 조정한다 |
| 리스크 | 고객사 자료가 AI 모델로 전송된다 | 회사 보안 정책 확인 후 사용한다 |

## 향후 로드맵

다음 개선은 운영 부담이 작고 효과가 큰 순서로 진행한다. 일정은 정하지 않았다.

1. 요청 내용 기본 문장을 설정 화면(사용자 지정 메타데이터)에서 관리
2. 보완 요청으로 자료가 다시 비면 진행 단계를 데이터 수집으로 되돌림
3. 담당 연구원(직원)과 Salesforce 사용자를 연결해 할 일을 연구원에게 직접 배정
4. Salesforce 이메일 발송 연동으로 발송 기록 자동화
5. 고객사 포털(Experience Cloud)에서 고객사가 자료를 직접 업로드
6. LCA 산정 결과와 검증 심사 이력 오브젝트 추가
7. Agentforce 대화로 초안·현황 요청
