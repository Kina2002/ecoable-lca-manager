# 에코에이블 LCA 프로젝트 관리 웹앱 설계서

작성일: 2026-10-15 · 버전: v02 (공개 데이터 적용 계획 추가, 인증·사후관리를 1차로 변경) · 대상: 에코에이블컨설팅㈜ 전과정정책본부 · 작성: 박기나

> 제품 전과정평가(LCA) 컨설팅의 가장 큰 병목인 **고객사 데이터 수집**을 중심으로, 프로젝트를 계약부터 사후관리까지 한 화면에서 관리하는 웹앱이다. 별도 설치나 로그인 없이 링크 하나로 열리며, 시연용 가상 데이터가 들어 있다.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 앱 이름 | 에코에이블 LCA 관리 (가칭) |
| 한 줄 정의 | 전과정정책본부 연구원이 LCA 프로젝트의 범위·데이터 수집·검토·검증·인증을 한곳에서 관리하는 웹앱 |
| 업무 범위 | 제품 LCA 수행 — 고객사 요구 대응, 규제 대응, 제품 환경성 진단. PCF·환경성적표지·해외 EPD는 "결과 활용처"로 기록 |
| 제외 범위 | 온실가스 인벤토리, CDP, SBTi, ISCC, 물발자국, LCC 등 본부의 다른 업무 |
| 제출 형태 | 공개 웹 링크(GitHub Pages) + 본 설계서 + 자료조사 보고서 |

### 1-1. 해결하려는 문제

자료조사(「에코에이블_LCA업무_자료조사_2026-10-15_v02」)에서 확인한 사실을 근거로 했다.

- **데이터 수집이 가장 길고 자주 막힌다.** 첫 LCA는 수집에만 2~3개월, 전체 3~6개월이 걸린다. 공급망이 복잡하고, 무응답과 수작업 독촉이 많다.
- **받은 자료가 곧 쓸 수 있는 자료는 아니다.** 단위, 기간(보통 12개월), 증빙, 1차/2차 구분, 품질 등급이 갖춰져야 검증을 통과한다.
- **검증은 "보완 요청 ↔ 보완 제출"을 여러 번 반복한다.** 몇 번째 라운드인지, 무엇이 열려 있는지 추적이 필요하다.
- **결과 활용처마다 요구가 다르다.** 환경성적표지(유효 3년, 처리 90일), International EPD(유효 5년, 매년 점검), 고객사 PCF 양식(PACT·Catena-X), EU 배터리법·CBAM의 방법론·데이터·마감이 모두 다르다.

### 1-2. 목표와 성공 지표

| 목표 | 지표 |
|---|---|
| 수집 현황을 한눈에 | 프로젝트별 수집률(제출 기준)·승인률(검토 완료 기준) |
| 기한 누락 방지 | 기한 초과 요청 수, 3일 내 마감 요청 수 |
| 검증 준비도 향상 | 증빙·기간·1차/2차 정보가 모두 채워진 항목 비율 |
| 검증 반복 단축 | 프로젝트별 검증 라운드 수, 열린 검토 의견 수 |
| 인증 만료 관리 | 만료 6개월 이내 인증 수 |

## 2. 사용자와 주요 시나리오

| 사용자 | 하는 일 |
|---|---|
| 담당 연구원 (주 사용자) | 범위 정의, 데이터 요청 생성, 제출 자료 검토·승인, 독촉·보완 메일 작성, 검증 대응 |
| 본부장·팀장 | 전체 프로젝트 단계·지연 현황, 연구원별 업무량 확인 |
| 고객사 담당자 | 1차 버전에서는 앱을 쓰지 않고 메일로 요청을 받는다. 3차 버전에서 제출 포털 검토 |

**대표 시나리오**

1. **신규 프로젝트**: 연구원이 프로젝트를 만들고 목적(예: 고객사 요구 — Catena-X), 결과 활용처, 기능단위·시스템 경계·기준기간을 입력한다. 빈 칸은 "확인 필요 정보"로 표시되고 정보 확인 메일 초안이 추천된다.
2. **데이터 요청**: "요청 항목 만들기"에서 11가지 데이터 구분 중 필요한 것을 고르고 요청 내용·마감일을 정해 한 번에 만든다. 단계가 "데이터 수집"으로 바뀐다.
3. **수집·검토**: 고객사가 보낸 값을 항목에 입력(수량·단위·기간·증빙·1차/2차)하면 "제출됨"이 된다. 연구원이 검토해 승인하거나 보완 요청한다.
4. **독촉**: 홈의 "오늘 할 일"에 D-3·D-1·기한 초과·보완 요청이 뜬다. 메일 초안 창에서 추천 메일을 열면 정확한 자료 목록이 채워진 초안이 나온다.
5. **검증 대응**: 검증인 지적사항을 "검토 의견"으로 등록하면 라운드가 올라가고, 모두 종결되면 인증·등록 단계로 넘어갈 수 있다.
6. **사후관리**: 인증서 만료 6개월 전, International EPD 매년 점검 시점에 할 일이 뜬다.

## 3. 업무 프로세스 (10단계)

자료조사의 13단계를 실무 단위로 묶었다. 스크리닝은 범위 정의에, 현장방문은 데이터 수집에, 납품은 완료에 포함한다.

| # | 단계 | 주요 활동 | 다음 단계로 가는 조건 (게이트) |
|---|---|---|---|
| 1 | 계약·착수 | 계약, 킥오프, 담당자 지정 | 고객 담당자·담당 연구원 지정 |
| 2 | 범위 정의 | 적용 기준, 기능단위, 시스템 경계, 기준기간, 컷오프, 할당, 대상 제품, 스크리닝 | 범위 필수 칸 입력 완료 |
| 3 | 데이터 수집 | 요청 항목 생성·발송, 현장방문, 독촉 | 모든 항목이 "제출됨" 이상 (해당 없음 제외) |
| 4 | 데이터 검토 | 물질수지·누락 점검, Q&A, 승인/보완 요청 | 모든 항목 "승인" → 다음 단계 자동 제안 |
| 5 | 계산(모델링) | 배경 DB 연결, 영향평가 | 연구원이 완료 표시 |
| 6 | 결과 해석 | 기여도·민감도·시나리오, 핫스팟 | 연구원이 완료 표시 |
| 7 | 보고서 | 초안 작성, 고객 검토 의견 반영 | 고객 검토 의견 모두 종결 |
| 8 | 제3자 검증 | 검증인 지적 ↔ 보완 제출 (라운드 반복) | 검증 지적 모두 종결 |
| 9 | 인증·등록 | 환경성적표지 심사, EPD 등록, 고객사 포털 제출 | 인증·등록 번호와 인증일 입력 |
| 10 | 완료·사후관리 | 납품, 매년 점검, 만료 전 갱신, 10% 이상 변화 시 재산정 | — |

- 게이트를 만족하지 않아도 연구원이 직접 단계를 옮길 수 있다. 이 경우 사유를 남긴다.
- 단계마다 화면 상단에 "이 단계에서 할 일" 안내와 핵심 칸을 보여 준다.

## 4. 기능 요구사항

| ID | 기능 | 내용 | 차수 |
|---|---|---|---|
| F-01 | 프로젝트 관리 | 생성·수정, 목적·동인·활용처·적용 기준, 범위 칸, 10단계 진행 막대 | 1차 |
| F-02 | 확인 필요 정보 | 고객 담당자, 목표 완료일, 범위 필수 칸, 요청 항목 0개를 자동 계산해 표시 | 1차 |
| F-03 | 요청 항목 일괄 생성 | 11가지 구분 체크, 기본 요청 문장 수정, 마감일 선택, 이미 있는 구분은 건너뜀, 단계 자동 전환. 구분마다 작성지침 근거 표시 | 1차 |
| F-04 | 데이터 항목 관리 | 상태 6단계, 수량·단위·데이터 기간·증빙·1차/2차·획득 방법 입력, 보완 사유. 2차 계수는 데이터셋 이름·버전까지 기록(예: 국가 LCI DB 전력 2022) | 1차 |
| F-05 | 기한 관리 | 남은 날, D-3·D-1 안내, 기한 초과 표시, 메일 분류 자동 계산 | 1차 |
| F-06 | 오늘 할 일 | 기한 초과·임박·보완 요청·정보 확인·열린 검토 의견·만료 임박을 규칙으로 계산해 목록화 | 1차 |
| F-07 | 메일 초안 | 독촉·마감 임박·보완 요청·정보 확인 4종, 추천 메일 표시, 자료 목록은 시스템이 채움, 복사 버튼, "보냈어요" 기록 | 1차 |
| F-08 | 검토 의견 | 자료 질의·고객 검토·제3자 검증 지적 구분, 라운드 자동 증가, 열림/답변됨/종결 | 1차 |
| F-09 | 홈 대시보드 | 숫자 칸, 단계별 프로젝트, 프로젝트 현황표(거르기·검색·더 보기), 주의 항목 | 1차 |
| F-10 | 데이터 보관 | 브라우저 저장, 샘플 데이터 초기화, JSON 내보내기·가져오기, 자료 출처 표기 | 1차 |
| F-12 | 인증·사후관리 | 활용처별 인증·등록 번호, 인증일, 만료일 자동 계산(환경성적표지 인증일 + 3년 − 1일, EPD 5년), 버전 이력, 매년 점검일, 갱신 알림. 공개 데이터가 가장 잘 드러나는 기능이라 1차로 앞당김 | 1차 |
| F-11 | 대상 제품 | 프로젝트별 여러 제품, 제품별 요청 항목 연결 | 2차 |
| F-13 | 마감일 성격 | 고객 마감일을 확정/조건부/확인 필요로 구분. 조건부는 "법정일"과 "위임법 발효일 + N개월" 중 늦은 날, 발효일이 없으면 "미정" (예: EU 배터리법) | 2차 |
| F-14 | 데이터 품질 | 1차 데이터 비중, 증빙 완비율, 기준기간 12개월 여부 경고 | 2차 |
| F-18 | 공개 인증 참고 | 익명화한 환경성적표지 인증 표본으로 제품군별 기능단위·결과값 범위·유효기간 보기, 출처·기준일 표기 | 2차 |
| F-15 | 핫스팟 기록 | 단계·소재별 기여도, 누적 80%, 개선 시나리오 대비 % | 3차 |
| F-16 | 협력사 PCF | PACT v3 필드(선언단위, 기준기간, PCF, PDS, DQR, 검증) 기록, Catena-X 그룹 구조로 화면 구성 | 3차 |
| F-17 | 고객사 제출 포털 | 고객사가 직접 값·증빙을 올리는 화면 (서버 필요) | 3차 |

| 제공 부서 | 선택 | 구매, 생산, 환경안전, 물류, 재무·ERP, 협력사 |

## 6. 업무 규칙

| 규칙 | 내용 |
|---|---|
| 수집률 | (제출됨 + 검토 중 + 승인) ÷ (전체 − 해당 없음) |
| 승인률 | 승인 ÷ (전체 − 해당 없음) |
| 남은 날 | 상태가 요청·보완 요청이고 기한이 있으면 기한 − 오늘 |
| 기한 초과 | 상태가 요청·보완 요청이고 기한 < 오늘 |
| 마감 임박 안내 | 남은 날 3 → "D-3", 1 → "D-1", 0 → "오늘 마감" |
| 메일 분류 | 기한 초과 → "기한 지난 자료", 보완 요청 → "보완이 필요한 자료", 그 외 미제출 → "아직 기한 전인 자료" |
| 메일 추천 | 기한 초과가 있거나 보완과 임박이 함께 있으면 독촉 → 보완만 있으면 보완 요청 → 임박만 있으면 마감 임박 안내 → 확인 필요 정보가 있으면 정보 확인 → 그 외 "보낼 메일 없음" |
| 보낼 내용 없음 | 고른 메일 종류에 해당하는 자료가 없으면 초안 대신 한 줄 안내 |
| 단계 자동 제안 | 모든 항목 승인 시 "계산(모델링)으로 넘어갈까요?" 표시 |
| 검증 라운드 | 제3자 검증 지적을 새 라운드로 등록하면 +1 |
| 기준기간 경고 | 프로젝트·항목의 기간이 12개월이 아니면 경고 |
| 만료일 계산 | 환경성적표지·저탄소제품은 인증일 + 3년 − 1일, International EPD·EPD Norway·UL EPD는 등록일 + 5년 |
| 만료 알림 | 만료 6개월 전 "갱신 준비"(UL EPD는 60일 전 "갱신 요청"), 매년 점검일 30일 전 "점검" 할 일 |
| 확인 필요 정보 | 완료 단계가 아니고 고객 담당자·목표 완료일·범위 필수 칸·요청 항목 중 비어 있는 것 |

## 8. 기술 설계

| 항목 | 결정 | 이유 |
|---|---|---|
| 형태 | 정적 웹앱(한 페이지 앱). HTML·CSS·JavaScript, 빌드 도구 없음 | 서버 없이 링크 하나로 열리고, 누구나 소스를 볼 수 있다 |
| 데이터 저장 | 브라우저 저장(localStorage). 첫 방문 시 가상 샘플 데이터 자동 입력, "샘플로 초기화" 버튼, JSON 내보내기·가져오기 | 회원가입·서버 없이 시연 가능. 실제 고객 데이터는 다루지 않는다 |
| 배포 | GitHub Pages (무료 공개 링크). 대안: Netlify | 자소서에 링크로 첨부. 저장소를 함께 보여 줄 수 있다 |
| 메일 초안 | 규칙 기반 템플릿 + 시스템이 채우는 자료 목록 | Salesforce 시연에서 AI가 목록을 빠뜨리거나 잘못 묶는 문제를 확인했다. 정확해야 하는 목록은 시스템이 만든다. API 키 노출·비용 문제도 없다 |
| 날짜·계산 | 업무 규칙(6장)을 순수 함수로 분리하고 테스트 페이지로 검증 | 규칙이 화면과 섞이지 않아 검증·수정이 쉽다 |
| 화면 | 반응형(PC·태블릿·휴대폰), 밝은/어두운 화면 | 면접관이 휴대폰으로 열어도 보이도록 |
| 차트 | 직접 그린 SVG | 외부 라이브러리 없이 가볍게 |
| 공개 데이터 | 1차: 규칙·형식·선택 목록만 코드에 넣고 샘플은 직접 만든다. 2차(F-18): 공공데이터 CSV에서 필요한 칸만 뽑고 기업명을 지운 표본 수십 건을 JSON으로 넣는다. 원본 파일은 저장소에 넣지 않는다 | 가볍고, 실제 기업명이 앱에 남지 않는다 |

| 원칙 | 내용 |
|---|---|
| 계산이 아니라 관리를 실제처럼 | 앱은 데이터 수집·검토·인증을 관리한다. 배출계수로 탄소를 계산하는 기능은 만들지 않고 참고값으로만 보여 준다. 계산은 LCA 툴(LCABLE, SimaPro 등)의 역할 |
| 실제 제품 종류 + 가상 회사 | 제품 종류·기능단위·경계는 공개 사례와 에코에이블 포트폴리오를 따르고, 회사 이름은 가상으로 만들어 옆에 "가상"을 표시한다 |
| 규칙과 형식은 가져오고 기록은 복사하지 않는다 | EPD 등록 사이트 약관은 기록 복제·재배포를 금지한다. 유효기간·번호 형식·버전 규칙만 쓴다 |
| 출처와 확인 상태를 보인다 | "자료 출처" 화면에 출처·기준일·이용 조건을 적고, 원문을 확인하지 못한 값에는 "확인 필요"를 붙인다 |

## 10. Salesforce 시연에서 배운 점과 반영

같은 업무를 Salesforce로 먼저 만들어 보며 얻은 교훈을 반영했다.

| 배운 점 | 반영 |
|---|---|
| AI는 같은 자료를 받아도 매번 다르게 쓰고, 목록을 빠뜨리거나 다른 묶음에 넣을 수 있다 | 메일의 자료 목록은 규칙으로 만든다 |
| 보낼 내용이 없는데 메일을 지어낼 수 있다 | 해당 자료가 없으면 초안 대신 한 줄 안내 |
| 틀리면 안 되는 판단(빈 정보, 기한, 수신자)은 계산으로 정해야 한다 | 확인 필요 정보·메일 분류·추천을 모두 규칙으로 계산 |
| 같은 할 일이 여러 번 생기면 혼란스럽다 | 할 일을 저장하지 않고 매번 규칙으로 계산 |
| 프로젝트가 많아지면 표가 길어진다 | 주의 필요만·검색·단계 거르기·더 보기 |
| "받았다"와 "써도 된다"는 다르다 | 상태를 제출됨·검토 중·승인으로 나눔 |

## 12. 향후 확장

- 고객사 제출 포털과 증빙 파일 업로드 (서버·로그인 필요)

- 승인된 데이터를 LCA 소프트웨어(SimaPro, openLCA 등) 입력 양식으로 내보내기
- 서버를 둘 경우 AI로 메일 문장 다듬기 (목록은 계속 규칙으로)

## 13. 확인이 필요한 사항

- 에코에이블의 표준 데이터 수집 양식과 제품군별로 달라지는 항목 (KEITI 표준 양식도 공개본을 찾지 못함)
- 실제 업무에서 쓰는 단계 구분과 단계별 평균 기간
- 자체 LCA 툴 LCABLE과의 역할 구분 (이 앱은 프로젝트·데이터 수집 관리, 계산은 LCA 툴)
- 환경성적표지 공통지침의 데이터 수집기간·컷오프 세부 규칙 (작성지침 제2025-165호 별표)
- EPD Norway·UL EPD 유효기간의 최신 규정(조사 자료는 2019·2018년판), Carbon Trust 라벨 유효기간
- EU 배터리법 탄소발자국 위임법 채택일 (채택 전까지 해당 마감일은 "조건부")
- 국가 전력 배출계수의 정부 원문, 국가 LCI DB 다운로드 조건
