# WEB-035 별도 홈 탭과 업무 대시보드

작성일: 2026-10-18

## 1. 사용자 합의와 배치 교정

사용자가 추천한 홈 대시보드 구현을 승인했다. 작업 중 사용자가 프로젝트 탭 안이 아니라 **홈 탭을 별도로 만들어야 한다**고 정정했다. 주 메뉴에 홈을 독립적으로 추가하고 앱을 처음 열면 홈을 표시한다. 프로젝트 탭은 기존 프로젝트 목록·단계·검색·두 자료 필터를 유지한다. 할 일·용어사전·연구원도 독립 메뉴로 유지한다.

추가 자료 입력이나 새 저장 키 없이 실제 저장 기록에서 요약을 계산한다. 백업·복원, 메일, 사후관리와 계산 엔진은 이번 범위가 아니다.

## 2. 숫자 카드와 비율 기준

집계 대상은 완료·사후관리(10)를 제외한 진행 프로젝트다. 프로젝트 탭에서 선택한 단계·검색·연구원·목적 필터와 별개인 전체 기준이다.

| 카드 | 계산/표시 |
| --- | --- |
| 진행 프로젝트 | 단계 1~9 프로젝트 수 |
| 자료 수집률 | 받은 자료 수 / 등록된 자료 요청 수 × 100, 반올림 |
| 자료 승인률 | 승인 자료 수 / 받은 자료 수 × 100, 반올림 |
| 확인 필요 프로젝트 | 아래 주의·확인 조건 중 하나 이상인 프로젝트 수, 중복 제외 |

- 삭제 요청과 완료 프로젝트의 요청은 집계에서 제외한다.
- 받은 자료는 receipt가 있고 요청 상태가 아닌 기록이다. 제출됨·검토 중·보완 요청·승인을 포함한다. 보완 자료도 이미 한 번 받은 기록이라는 뜻이며 완비/승인됐다는 뜻이 아니다.
- 각 비율 옆에 실제 분자·분모를 문장으로 표시한다. 비율은 프로젝트별 퍼센트의 평균이 아니다.
- 등록 요청 0건이면 수집률, 받은 자료 0건이면 승인률을 `—`로 표시하고 이유를 안내한다. 0/0을 100%로 표시하지 않는다.
- 자료 요청이 등록된 프로젝트 수/진행 프로젝트 수를 별도로 표시한다. 등록 요청 기준 100%가 모든 프로젝트의 자료가 준비됐다는 뜻은 아니다.
- 두 비율은 프로젝트 전체 진행률과 다르다고 표시한다.

## 3. 주의·확인할 프로젝트

- 진행 프로젝트 중 목표 완료일이 오늘~3일 후이거나 지난 경우, 데이터 수집(3)의 수집 마감이 같은 범위인 경우, 할 일 기록이 있는 경우를 모은다.
- 기한·보완·검토·고객 의견·검증 지적·정보 확인 건수를 이유로 표시한다. 회사/번호/제품/담당자/현재 단계를 함께 보여준다.
- 자료가 제출됐는지는 기존 할 일 규칙을 따르며 검토 대기를 고객 미제출로 단정하지 않는다.
- 프로젝트 목표/수집 마감 경과, 기한 지난 검증 지적, 자료 기한 초과를 우선하고 보완·임박·의견·정보 확인 순으로 정렬한다. 같은 우선순위는 기한·프로젝트 번호로 정렬한다.
- 전체 건수를 표시하되 상위 3개 프로젝트만 보여준다. 회사·번호 버튼은 프로젝트 상세 개요·범위로 이동한다. 상세의 홈으로 버튼은 홈의 원래 스크롤·프로젝트 초점으로 돌아간다.
- 일반 검토·정보 확인도 포함하므로 확인 필요 수를 모두 위험/지연 프로젝트 수로 해석하지 않는다.

## 4. 우선 확인할 일

- 할 일 탭과 같은 실제 조회 결과·분류·정렬을 사용한다. 상위 3건과 전체 건수를 표시하고 할 일 전체 보기로 기존 할 일 탭을 연다.
- 홈의 목표일/수집 마감 안내는 별도 프로젝트 주의 근거다. 그 이유만 있는 프로젝트가 반드시 기존 할 일 탭에 항목으로 생성되는 것은 아니다.
- 홈에서 따로 업무를 저장·완료·삭제하지 않는다. 원래 기록의 상태가 다음 계산에 반영된다.

## 5. 갱신·오류·기존 기능 보호

- `getWorkflowState`가 프로젝트·범위·요청·고객 의견·검증 기록을 읽고, 할 일 탭과 홈이 같은 조회 경로를 사용한다. 보고서/범위 연결의 순환 조회를 추가하지 않는다.
- 홈 진입, 홈이 보이는 동안 60초 간격, 화면 복귀, 다른 탭 저장 이벤트에 갱신한다. 계산 결과가 같으면 홈 DOM을 다시 만들지 않는다.
- 프로젝트/단계를 확인할 수 없으면 홈 숫자를 만들지 않고 오류를 표시한다. 저장된 최신 상태 대신 가상 기본값으로 통계/주의를 생성하지 않는다.
- 요청을 읽지 못하면 두 비율을 확인 필요로 표시한다. 의견 등 일부 출처를 읽지 못하면 확인 가능한 기록이라는 경고를 표시하고 부분 건수를 정상 전체 건수로 설명하지 않는다.
- 프로젝트 탭의 단계·검색·담당자·목적·수집 단계 하위 상태·상세 자료 상태 필터와 폼 초안을 유지한다. 메뉴로 홈을 보고 프로젝트로 돌아올 때 상세 폼을 다시 만들지 않는다.
- 같은 프로젝트를 홈에서 다시 열 때도 기존 상세를 재사용한다. 다른 프로젝트를 열면 기존 상세 종료 정책을 따른다. 새로고침 시 미저장 입력의 보관을 보장하는 기능은 아니다.
- 서버/새 저장 키/공개 배포/인증 정책 변경은 없다.

## 6. 구현과 확인 범위

- `web/js/dashboard.js`: 집계·주의 이유·상위 3개 계산.
- `web/js/views/dashboard.js`: 카드·분모 설명·주의/업무 요약·초점.
- `web/js/app.js`: 홈 메뉴·초기 진입·상세 이동/복귀·공통 조회·활성 화면 갱신.
- `web/index.html`, `web/css/app.css`: 독립 홈 영역·메뉴·화면 스타일.
- JavaScript 구문·Git 공백 검사를 확인했다. 별도 localhost에서 초기 홈 메뉴·프로젝트 메뉴 분리, 진행 6개·등록 요청 1/1 수집·받은 자료 1/1 승인·확인 필요 4개와 각 상위 3건 표시를 확인했다. 사용자 탭·저장 기록은 변경하지 않았다.
- 테스트 추가·실행은 하지 않았다. 0건/오류/완료 제외/보완 포함/각 날짜 경계의 전체 계산, 메뉴 왕복·상세 이동·복귀·입력 유지·다른 탭 갱신·작은 화면/키보드의 실제 동작 시험은 하지 않았다. 이전 미확인 흐름도 그대로 남아 있다.
