# WEB-061 보충 정보와 누락 안내 확대

## 목적과 화면

기본정보 수정 창의 접힌 보충 정보에서 고객 담당 부서·직책·이메일, 제품 코드·단위 중량/단위·연간 생산량/단위, 착수일·고객 요청 마감일, 컷오프·할당·배경 DB 계획을 적는다. 날짜는 네 자리 연도 입력과 달력 보조를 사용한다. 수량은 단위와 함께 기록하는 설명이며 자동 계산값이 아니다. 고객 마감일은 직접 받은 날짜의 기록이고 조건부 규제일 자동 계산은 2차로 남긴다.

컷오프는 작은 투입을 평가에서 제외할 기준과 근거, 할당은 여러 제품에 공동 영향을 나누는 방법과 근거, 배경 DB는 외부 계산에서 참고할 데이터셋 모음이다. 이 세 가지는 연구원이 결정·검토하는 방법 계획이므로 누락됐다고 고객에게 자동으로 판단을 맡기지 않는다. 실제 계산에 적용한 방법은 계산 결과에 별도로 기록한다.

## 누락과 업무 연결

개요의 범위 설명과 할 일에 추가 권장 정보 누락을 모은다. 고객에게 확인할 연락처·제품 코드·중량·생산량·요청 일정만 정보 확인 안내문 대상으로 추가한다. 새 필드의 빈칸은 기존 단계 이동을 막지 않는다. 기존 필수 조건과 구분한다. 1~8단계 편집, 이후 조회 규칙과 변경 전후 이력을 유지한다.

프로젝트의 선택 information을 기존 profileHistory에 포함하고 새 보고서에도 사본을 남긴다. 이전 보고서는 고치지 않는다. 컷오프·할당·배경 DB 계획이 기록되거나 바뀌면 기존 외부 계산 기준도 달라져 재확인이 필요하다. 연락처 변경만으로 계산 활동량을 바꾸지는 않는다. 백업/삭제는 기존 프로젝트 이력 경로를 사용한다.

## 검증

전체 자동검사 267개 통과. 보충 정보 저장/이력·날짜/이메일/길이 검사, 권장 누락·고객 질문 대상 확대, 방법 계획 변경에 따른 계산 사본 보존/재확인을 확인했다. 구문·공백 검사 통과. 실제 브라우저의 입력·스크롤·복귀는 미확인이다.

## 쉽게 말하면

“제품 평가를 시작하기 전에 적는 상담 기록을 보충했습니다. 상담에서 정한 방법을 바꾸면 예전 계산이 새 방법과 맞는지 다시 확인해야 하므로, 옛 결과를 지우지 않고 재확인을 표시합니다.”
