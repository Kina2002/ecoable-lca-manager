# 웹앱 기능별 SPEC

기준: [웹앱 설계서 v02](../02-design/lca-webapp-design.md).

SPEC은 '이 기능이 무엇을 하고, 어떤 규칙으로 움직이며, 무엇을 확인했는지' 적은 설명서다.
작은 기능 하나를 구현·확인한 뒤 기록하고 GitHub에 올린다. 사용자와 이해한 내용을 확인한 다음 다음 기능을 정한다.

| 순서 | 기능 | 설계서와의 관계 | 문서 |
|---|---|---|---|
| 1 | 7개 가상 프로젝트 목록 조회 | F-01의 목록 조회 부분, F-10의 샘플 일부 | [WEB-001](WEB-001-project-list.md) |

## 다음 기능을 정하는 방법

현재 기능을 사용자가 확인한 뒤 다음 기능을 함께 정한다. 등록·수정·상세·검색·저장 등은 각각 별도의 작업 범위다.

## 사용자 제안 대기 목록

1. **바로 다음 구현 요청: 단계별 프로젝트 건수와 단계 선택 필터.** 목록 위에 설계서 v02의 10단계와 각 단계의 프로젝트 수를 표시한다. 단계를 누르면 해당 프로젝트만 보여준다. 사용자가 제공한 예전 5단계 화면은 모양·동작 참고다. WEB-001 용어 설명 후 동작 범위를 함께 확인한다. 아직 구현하지 않았다.
2. 가상 데이터로 핵심 시연을 완성한 다음, 실제 공개 데이터의 작은 표본을 적용한다. 적용 시 출처·기준일·이용 조건을 함께 표시한다.

단계 선택 기능에서 정리할 세부 동작: 선택한 단계 강조, 전체 목록으로 돌아가기, 0건 단계 안내, 필터와 무관하게 전체 명단 기준으로 단계별 건수 유지. 기능별 SPEC은 구현 범위를 합의할 때 작성한다.
