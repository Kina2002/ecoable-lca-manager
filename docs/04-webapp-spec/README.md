# 웹앱 기능별 SPEC

기준: [웹앱 설계서 v02](../02-design/lca-webapp-design.md).

SPEC은 '이 기능이 무엇을 하고, 어떤 규칙으로 움직이며, 무엇을 확인했는지' 적은 설명서다.
작은 기능 하나를 구현·확인한 뒤 기록하고 GitHub에 올린다. 사용자와 이해한 내용을 확인한 다음 다음 기능을 정한다.

| 순서 | 기능 | 설계서와의 관계 | 문서 |
|---|---|---|---|
| 1 | 7개 가상 프로젝트 목록 조회 | F-01의 목록 조회 부분, F-10의 샘플 일부 | [WEB-001](WEB-001-project-list.md) |
| 2 | 단계별 건수와 단계 선택 필터 | F-09의 단계별 현황, F-01의 단계 필터 부분 | [WEB-002](WEB-002-stage-filter.md) |
| 3 | 프로젝트 상세 보기 | F-01의 한 건 조회, 상세의 개요·범위 부분 | [WEB-003](WEB-003-project-detail.md) |
| 4 | 용어사전과 검색 | 사용자 추가 요청: 업무 용어 학습 보조 | [WEB-004](WEB-004-glossary-search.md) |

## 다음 기능을 정하는 방법

현재 기능을 사용자가 확인한 뒤 다음 기능을 함께 정한다. 등록·수정·검색·저장 등은 각각 별도의 작업 범위다.

## 사용자 제안 대기 목록

1. 가상 데이터로 핵심 시연을 완성한 다음, 실제 공개 데이터의 작은 표본을 적용한다. 적용 시 출처·기준일·이용 조건을 함께 표시한다.
