# 웹앱 기능별 SPEC

최신: [WEB-031 자료 요청 일괄 생성](WEB-031-batch-data-requests.md) — 11개 구분 복수 선택·기본 문장 수정·공통 기한·중복 건너뛰기·한 번의 저장. 기존 개별 등록과 두 필터를 유지한다.

최신: [WEB-030 반복 입력 줄이기](WEB-030-input-assistance.md) — 기록 담당자 접기·연구원 선택, 오늘·달력, 이전 검증기관·담당자 활용. 기존 업무 조건과 보관 형식을 유지한다.

기준: [웹앱 설계서 v02](../02-design/lca-webapp-design.md).

SPEC은 '이 기능이 무엇을 하고, 어떤 규칙으로 움직이며, 무엇을 확인했는지' 적은 설명서다.
작은 기능 하나를 구현·확인한 뒤 기록하고 GitHub에 올린다. 사용자와 이해한 내용을 확인한 다음 다음 기능을 정한다.

업무 설명과 후속 논의는 [업무 이해·논의 기록](WORKFLOW-DISCUSSION.md)에 정리한다. 받은 자료·검토의 의미, 자료 상태와 프로젝트 단계의 구분, 고객사와 컨설팅 회사의 범위 합의 역할을 포함한다.

## 다음 기능을 정하는 방법

현재 기능을 사용자가 확인한 뒤 다음 기능을 함께 정한다. 등록·수정·검색·저장 등은 각각 별도의 작업 범위다.

## 사용자 제안 대기 목록

1. 가상 데이터로 핵심 시연을 완성한 다음, 실제 공개 데이터의 작은 표본을 적용한다. 적용 시 출처·기준일·이용 조건을 함께 표시한다.
2. 기획한 기능을 완성한 뒤 AI 요청문·메일 작성 보조와, 받은 메일에서 자료를 추출해 받은 데이터 항목에 채우는 기능을 검토한다. 자동 반영의 확인 절차·범위는 구현 전에 함께 정한다.
3. 같은 AI 확장 단계에서 증빙 파일만 넣으면 값·단위·자료 기간·증빙 파일 이름을 추출해 ‘받은 자료’ 입력칸을 채우는 기능을 검토한다. 추출 결과 확인·저장 흐름, 파일 형식과 요청 연결 방법은 함께 정한다.
4. 받은 자료의 상세 기록과 증빙 연결은 나중에 구현한다. 월별·사업장별·공정별 및 전력·연료별 여러 기록, 각 기록과 증빙 연결, 누락·중복·합계 근거 확인을 후속 후보로 남긴다. 현재는 요청당 기록 한 건인 WEB-007을 유지하며, 범위·순서는 시작 전에 함께 정한다. 논의 배경은 [WEB-007 10절](WEB-007-received-data.md#10-후속-논의-기록-상세-자료와-증빙)을 참고한다.
5. 자료 상태별 건수·필터는 사용자의 승인으로 WEB-009에 구현했다. 실제 화면 확인은 SPEC의 제한을 참고한다.
6. 범위 상태 구분과 별도 수집 시작은 [WEB-010](WEB-010-scope-status.md)으로 구현했다. 실제 화면 확인 후 다음 기능을 정한다. 수집 이후 범위 재협의·이력·단계 되돌리기는 별도 후속 작업이다. 계약→범위 이동은 WEB-013에서 구현했다.
7. 앱 내부 LCA 계산은 AI 연결처럼 기획한 기본 기능을 모두 구현한 뒤 검토한다(2026-10-17 사용자 지시). 현재는 WEB-020의 승인 원자료 내보내기와 외부 계산 결과 등록까지 구현했다. 내부 계산의 대상 지표·방법·DB·단위 환산·검증 범위는 해당 확장 시작 전에 함께 정한다.
