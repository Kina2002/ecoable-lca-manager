# WEB-004 용어사전과 검색

- 요청: '용어들이 어려우니 용어사전 탭과 검색 기능을 만들어 달라.'
- 기준: 설계서 v02와 WEB-001·003의 화면 용어. 사용자가 추가 요청한 학습 보조 기능이다.
- 범위: 40개 용어의 쉬운 뜻·가상 예시·출처 조회와 사전 안의 검색.
- 상태: 구현·검증 완료. 코드와 이 문서를 같은 커밋으로 관리한다.

## 1. 왜 만드는가

업무 화면에 낯선 약어가 많으면 버튼을 사용할 수 있어도 업무의 의미를 이해하기 어렵다.
프로젝트를 읽다가 사전에서 뜻을 확인하고, 원래 보던 업무로 돌아올 수 있게 한다.
면접에서도 암기한 약어만 말하는 대신 뜻과 실제로 쓸 상황을 함께 설명할 수 있도록 가상 예시를 붙였다.

사전 원고 40개를 미리 정리했다. 검색은 그 원고에서 맞는 카드를 골라 보여주는 기능이다.

## 2. 화면과 사용 흐름

1. 주 메뉴에서 '용어사전'을 누른다. 작은 화면에서는 브랜드 아래 두 메뉴를 나란히 표시한다.
2. 검색창에 초점이 오고 전체 40개 카드가 보인다.
3. '요람', 'PCF', '기능 단위' 등을 입력하면 즉시 해당 카드와 결과 건수가 보인다.
4. 카드에서 이름·영문명·쉬운 뜻·가상 예시를 읽고 참고 원문을 새 탭으로 열 수 있다.
5. 일치하는 항목이 없으면 0건과 검색 방법 안내가 보인다.
6. '검색 지우기'를 누르면 전체 40개로 돌아오고 검색창에 초점이 온다.
7. '프로젝트' 메뉴를 누르면 사전을 열기 전의 목록 또는 상세 화면으로 돌아온다.

## 3. 사전 내용

| 구분 | 개수 | 수록 용어 |
|---|---:|---|
| 기본 개념 | 5 | LCA, PCF, 핫스팟 분석, 에코디자인, 비교 평가 |
| 범위·단위 | 9 | kgCO₂e, 평가 기준량, 기능단위, 선언단위, 시스템 경계, 요람~문, 요람~무덤, A1–A3, kg·t |
| 업무에서 쓰는 말 | 9 | 업무 목적, 고객사 요구 대응, 규제 대응, 제품 환경성 진단, 세부 동인, 결과 활용처, 프로젝트 유형, 현재 단계, OEM 자체 양식 |
| 기준·제도 | 13 | EPD, 환경성적표지, 저탄소제품, International EPD, PCR, ISO 14040·14044, ISO 14067, EN 15804, EU CPR, EU 배터리법, PACT, Catena-X, TfS |
| 자료·검토 | 4 | 기준기간, 1차·2차 데이터, 증빙, 제3자 검증 |

각 원고의 필드:

| 필드 | 역할 |
|---|---|
| `id` | 카드의 고유 이름 |
| `term`, `english` | 한글·약어 이름과 영문명 |
| `category` | 용어의 분류 이름. 별도 분류 필터는 제공하지 않음 |
| `aliases` | 같은 용어를 찾을 때 쓸 다른 표기·검색어 |
| `meaning`, `example` | 직접 풀어쓴 쉬운 설명과 가상 예시 |

전문 용어의 설명은 아래 참고 자료와 대조해 직접 풀어썼다.
앱의 목적·유형·현재 단계 등은 '이 앱의 업무 용어'로 표시해 국제표준의 정의와 구분한다.
예시는 실제 기업의 측정값·인증 기록이 아니다. 기준일은 내용 확인일이며 앱을 여는 날짜로 자동 갱신하지 않는다.
이번 기능은 실제 공개 데이터 표본 적용이나 설정의 '자료 출처' 화면 구현을 대신하지 않는다.

## 4. 검색 규칙

- 검색 대상은 용어 이름·영문명·분류·다른 표기·뜻·예시다.
- 입력할 때마다 결과를 갱신한다. 검색창을 다시 만들지 않아 입력 초점이 유지된다.
- 검색어와 원고 양쪽에 Unicode NFKC 정규화, 소문자 변환, 공백·구두점·기호 제거를 적용한다.
- 예: `PCF`와 `pcf`와 `ＰＣＦ`, `CO₂e`와 `CO2e`, `기능단위`와 `기능 단위`, `cradle-to-gate`와 `cradle to gate`는 각각 같은 결과다.
- 이 처리는 컴퓨터가 글자 모양·구분 기호의 차이를 같은 표기로 맞춰 보는 것이다.
- 맞춘 검색어가 원고에 포함되어 있는지 `includes()`로 확인한다. 입력을 정규식 명령으로 실행하지 않는다.
- 여러 단어도 공백을 없애 이어진 문구로 찾는다. 임의의 단어들을 각각 찾는 AND/OR 검색은 제공하지 않는다.
- 빈 검색어와 공백만 있는 검색어는 전체를 보여준다. 기호만 쓴 검색어는 0건이다.
- 예시와 뜻도 찾으므로 '요람'은 두 경계 용어와 그 말이 나오는 TfS까지 3개가 표시된다.
- 결과는 원고의 기본 순서를 유지한다. 제목 일치 우선 정렬·유사어 추측·자동완성은 이번 범위가 아니다.
- 검색은 새로운 배열을 돌려주며 원고나 프로젝트 값을 바꾸지 않는다.
- 결과 건수는 `role="status"`, `aria-live="polite"`로 안내한다.
- 지우기 버튼은 입력이 없으면 비활성화된다. 브라우저 기본 검색창 지우기 동작도 `input` 이벤트로 반영한다.
- 문장은 `textContent`로 넣는다. 검색어나 원고에 HTML처럼 보이는 글자가 있어도 명령으로 실행하지 않는다.

## 5. 화면 전환 규칙

- 주 메뉴는 기존 '프로젝트'와 새 '용어사전'으로 구성한다. 선택 메뉴를 `aria-current="page"`와 색으로 표시한다.
- '용어사전'을 열면 프로젝트 영역을 숨기고 사전 영역을 펼친다. 검색창에 초점을 옮기고 화면 위쪽을 보여준다.
- 사전을 열기 전 목록 또는 상세 중 어느 화면을 보고 있었는지와 스크롤 위치를 기억한다.
- '프로젝트'를 누르면 그 화면과 위치를 복원하고 해당 제목에 초점을 옮긴다. 단계 필터와 상세 데이터도 유지한다.
- 다시 사전을 열면 검색어와 결과는 유지하고 검색창으로 이동한다.
- 프로젝트 화면 안에서 '프로젝트' 메뉴를 누르는 기존 동작(상세 → 목록)은 유지한다.
- 주소·방문 기록은 추가하지 않는다. 새로고침은 전체 프로젝트 목록에서 시작하고 사전 검색어는 초기화한다.
- 브라우저 영구 저장이나 서버 연결은 추가하지 않는다.

추후 용어를 고칠 때 원고와 출처를 함께 검토하고 실제 확인한 날짜로 `CHECKED_ON`을 갱신한다.

## 9. 면접 설명

**왜 만들었나요?**

사용자가 낯선 LCA 용어 때문에 업무 화면을 이해하기 어려워했습니다.
사전에서 쉬운 뜻과 예시를 확인하고 보던 프로젝트로 돌아오도록 만들었습니다.

**검색은 어떻게 동작하나요?**

미리 작성한 원고의 이름·설명·예시를 검색합니다. 표기 차이를 같은 글자로 맞춘 다음 포함 여부로 결과를 고릅니다.
그래서 PCF와 pcf, 기능단위와 기능 단위도 같은 결과가 나옵니다.

**설명의 근거는 무엇인가요?**

전문 용어는 ISO·GHG Protocol·제도 운영기관 등의 자료와 대조해 풀어썼고 카드마다 원문 링크를 붙였습니다.
이 앱에서 정한 항목의 의미와 가상 예시는 별도로 표시했습니다.

**사전을 보고 돌아오면 왜 기존 업무가 남아 있나요?**

원래 프로젝트 화면과 자료를 보관하고 영역만 잠시 숨깁니다. 돌아오면 같은 화면을 펼치고 스크롤 위치도 복원합니다.

다음 기능은 사용자가 이 사전과 설명을 확인한 뒤 함께 정한다.
