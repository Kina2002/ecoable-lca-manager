# WEB-006 자료 요청 삭제·복원과 날짜 입력 개선

- 기준: 설계서 v02 DataRequest, WEB-005의 등록·저장 기능.
- 사용자 요청: 자료 요청 삭제 추가, 제출 기한의 연도를 최대 4자리로 제한하고 숫자 입력을 쉽게 하기.
- 상태: 구현·자동 검사·브라우저 확인 완료. 확인일 2026-10-16.

## 1. 왜 만드는가

잘못 등록하거나 필요 없어진 요청을 현재 업무 목록에서 뺄 수 있어야 한다.
실수로 눌렀을 때 되돌릴 수 있도록 휴지통과 비슷한 삭제 방식을 사용한다.
날짜는 숫자를 이어 입력할 때 연도에 여섯 자리까지 들어가던 불편을 줄인다.

## 2. 삭제와 복원

1. 프로젝트 상세의 '자료 요청' 탭에서 각 요청 오른쪽의 '삭제'를 누른다.
2. 브라우저 저장에 성공하면 현재 목록과 탭 건수에서 빠진다. 해당 자료 구분을 다시 선택할 수 있다.
3. 목록 아래 '삭제한 자료 요청 N건'을 펼치면 삭제한 요청의 번호·내용·기한·근거를 볼 수 있다.
4. '복원'을 누르면 원래 번호와 내용으로 현재 목록에 돌아온다.
5. 같은 프로젝트에 같은 구분의 현재 요청이 있으면 복원하지 않고 이유를 표시한다. 두 요청을 자동으로 합치거나 덮어쓰지 않는다.

삭제와 복원은 프로젝트 ID와 요청 ID를 함께 확인한다. 다른 프로젝트의 요청을 바꾸지 않는다.
삭제한 번호는 새 요청에 재사용하지 않는다. 예를 들어 DRQ-0002를 삭제하고 다시 등록하면 DRQ-0003으로 이어진다.
새로고침해도 삭제 여부가 유지된다. 삭제·복원 뒤에는 목록 제목으로 초점을 옮기고 결과를 상태 영역으로 안내한다.

## 3. 저장 방법과 예외

기존 저장 키 `ecoable-lca-manager.requests.v1`과 내부 `version: 1`을 유지한다.
기존 요청을 지우거나 초기화하지 않고, 삭제한 요청에만 선택 항목 `deletedAt`을 추가한다.

```json
{
  "id": "DRQ-0002",
  "projectId": "project-001",
  "deletedAt": "2026-10-16T03:00:00.000Z"
}
```

위 예시는 변경 부분만 나타낸 것이다. 실제 기록에는 원래 내용·기한·상태·근거도 그대로 남는다.

- `deletedAt`이 없는 요청은 현재 목록, 있는 요청은 삭제 목록으로 나눈다.
- 복원은 `deletedAt`만 제거한다. 업무 상태 '요청'과 삭제 여부는 별개다.
- 기존 WEB-005 저장본도 그대로 읽는다. 중복 구분 검사는 현재 요청끼리 적용한다.
- 매번 최신 저장본을 읽고 쓰기에 성공한 뒤 화면을 갱신한다.
- 읽기 실패·손상된 기록·저장 공간 부족에서는 실패를 안내하고 기존 저장본을 덮어쓰지 않는다.
- 영구 삭제·휴지통 비우기는 제공하지 않는다. 같은 브라우저·사이트 주소에 저장하며 서버 동기화와 여러 탭의 동시 쓰기 잠금은 기존처럼 없다.

## 4. 날짜 입력

- 입력칸은 숫자 키보드를 요청하는 텍스트 입력으로 바꾼다. 숫자를 치면 연도 4자리, 월 2자리, 일 2자리로 정리한다.
- 예: `20261023` → `2026-10-23`. 구분 기호를 직접 칠 필요가 없다.
- 연도는 최대 4자리, 전체는 구분 기호 포함 최대 10자리다. 월·일의 최대 길이는 각각 2자리다.
- 완성된 `2026-10-23`, `2026/10/23`, `2026.10.23` 붙여넣기도 정리한다. 실제 입력칸의 최대 길이는 10자다.
- 숫자를 고치던 위치에 커서를 유지한다. Backspace·Delete가 구분 기호를 만나면 기호를 건너뛰어 월·일이 연도에 붙지 않게 한다.
- 자동 정리는 날짜가 실제 존재하는지 확인하는 것과 다르다. 저장할 때 기존 달력 검증을 다시 거친다. `2026-02-29`는 거부하고 `2024-02-29`는 허용한다.
- 연도 0000, 미완성 날짜와 빈 날짜는 저장하지 않는다. 과거 기한은 기록할 수 있다.
- '달력' 버튼은 브라우저 날짜 선택창을 연다. 선택값은 같은 입력칸에 반영한다. 선택 범위는 0001-01-01~9999-12-31이다.
- `showPicker()` 미지원 브라우저에서는 버튼을 숨기고 숫자 입력을 사용한다. 호출이 차단되면 숫자 입력 안내를 표시한다.

기술 근거: 기본 날짜 입력의 표현은 브라우저에 따라 다르고 `min`·`max`는 날짜 범위 제약이다. 입력 길이를 일관되게 다루기 위해 표시 입력과 달력 입력을 연결했다. [MDN 날짜 입력](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/date), [MDN showPicker](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/showPicker).

## 5. 파일과 처리 순서

| 파일 | 변경 |
|---|---|
| `web/js/requests.js` | 삭제 시각 검증, 현재·삭제 목록 분리, 삭제·복원·중복 방지, 날짜 정리 |
| `web/js/views/requests.js` | 삭제·복원 버튼, 결과 안내, 건수 갱신, 날짜 입력과 달력 연결 |
| `web/index.html` | 삭제 목록·오류 영역·날짜 입력 템플릿, 변경 자산 버전 |
| `web/css/app.css` | 날짜 입력·달력 버튼·삭제와 복원 배치 |
| `web/tests/requests.test.cjs` | 삭제·복원·손상·쓰기 실패·날짜 검사 추가 |

삭제 클릭 → 최신 기록 읽기 → 프로젝트·요청 확인 → 삭제 시각 추가 → 브라우저 저장 → 현재·삭제 목록과 건수 다시 표시.
화면의 카드를 없애는 것만으로는 새로고침 때 다시 나타나므로, 삭제 여부를 저장하는 단계가 필요하다.

| 확인 | 결과 |

| 자동 검사 | 요청 14개·사전 6개·단계 4개, 총 24개 통과 |
| 삭제·새로고침 | 포장재 요청 삭제 후 현재 건수 2→1, 새로 열어도 삭제 목록 유지 |
| 복원 | 동일 번호·내용·기한 복원, 현재 건수 1→2, 구분 '등록됨' 복귀 |
| 프로젝트 왕복 | 다른 프로젝트 상세를 열었다 돌아온 뒤에도 삭제·복원 정상 |
| 번호와 중복 | 삭제 후 같은 구분 재등록 시 새 번호, 기존 요청 복원 시 중복 차단 |
| 기록 보호 | 다른 프로젝트·없는 번호·이미 처리된 요청과 쓰기 실패에서 변경 거부 |
| 숫자 입력 | 실제 키 입력 `20261023` → `2026-10-23`, 추가 숫자 제한 |
| 부분 수정 | 연도 일부 삭제 시 월·일 유지, 구분 기호에서 Backspace 시 커서 이동 |
| 달력 | 버튼으로 열고 10월 24일 선택, 입력칸에 `2026-10-24` 반영 |
| 잘못된 날짜 | `20260229` 등록 시 날짜 오류, 기존 2건 유지 |
| 배치 | 브라우저 뷰포트 1440px·320px에서 가로 넘침 없음 |
| 브라우저 로그 | 오류·경고 없음 |

브라우저 확인에 사용한 기존 포장재 요청은 복원했다. 확인 목적으로 새로운 요청을 남기지 않았다.
기기 크기 확인은 브라우저 뷰포트 검사이며 실제 휴대폰 하드웨어 검사는 아니다.

```bash
node --check web/js/requests.js
node --check web/js/views/requests.js
node --test web/tests/requests.test.cjs web/tests/glossary.test.cjs web/tests/stage-filter.test.cjs
```

## 7. 면접에서 설명하기

**삭제인데 왜 기록이 남나요?**

잘못 삭제한 업무를 되돌릴 수 있게 휴지통처럼 만들었습니다. 삭제 시각이 있는 요청은 현재 목록에서 제외하고, 복원하면 원래 정보로 돌아옵니다.

**화면에서 지우면 끝나는 것 아닌가요?**

화면만 지우면 새로고침 때 저장된 원본이 다시 보입니다. 삭제 여부를 먼저 저장하고, 성공했을 때 목록을 바꿉니다.

**날짜 입력과 날짜 검사는 왜 따로 하나요?**

입력 정리는 숫자에 구분 기호를 넣어 주는 편의 기능입니다. 2월 30일 같은 날짜는 모양만 맞아도 사용할 수 없으므로 저장 전에 실제 날짜인지 다시 확인합니다.

요청 내용 수정·제출 값 입력·검토·상태 변경은 이번 작업에 포함하지 않는다. 다음 기능은 사용자가 확인한 뒤 함께 정한다.
