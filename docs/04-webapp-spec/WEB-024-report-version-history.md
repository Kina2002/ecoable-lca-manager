# WEB-024 보고서 버전별 보관과 변경 이력

## 1. 사용자 합의

2026-10-18 사용자는 보고서가 1차·2차·3차로 바뀔 수 있으므로 각 버전과 무엇을 왜 어떻게 바꿨는지 남길 공간을 제안한 뒤 구현을 요청했다. PDF·Word 내보내기 WEB-023과 연결하며 고객 검토 의견 관리와 7→8 이동은 이번 범위에 넣지 않는다.

## 2. 새 버전 저장

- 보고서 단계(7)의 기존 제목·작성 메모 아래에 이번 변경 기록을 추가한다.
- **변경 내용**(필수 1~1,000자), **변경 사유**(필수 1~1,000자), **변경 전**(최초 버전만 선택, 이후 필수 최대 2,000자), **변경 후**(필수 1~2,000자), **작성자**(필수 1~100자), **관련 고객 의견**(선택 최대 200자)을 기록한다.
- 관련 고객 의견은 현재 자유 메모이며 실제 의견 엔터티와 연결하지 않는다. 작성자 이름은 직접 적는 기록이며 로그인·본인 인증 정보가 아니다.
- **보고서 새 버전 저장**은 이전 버전을 수정하지 않고 새 번호를 추가한다. 당시 제목·작성 메모·프로젝트·계산·승인 자료·해석·변경 기록과 저장 시각을 함께 보관한다. 수치의 문자열 표기는 유지한다.
- 최신 자료 최소 한 건·전부 승인, 최신 근거의 외부 계산 결과와 해석, 같은 기준 확인, 보고서 단계 조건을 다시 검사한다. 단계나 자료 상태를 자동 변경하지 않는다.
- 저장 중 중복 클릭을 막는다. 성공하면 변경 입력칸과 확인 체크를 초기화하고 제목·메모는 유지한다. 실패하면 초안과 기존 버전을 보존한다.

## 3. 버전 열람과 비교

- **버전별 보관·변경 이력**에 최신 순으로 버전·저장 시각(한국 시간)·작성자·변경 내용을 나열한다.
- **보관 버전**을 선택하면 해당 보고서 본문과 변경 기록을 표시한다. 이전 버전을 선택해도 새 버전 작성칸을 자동으로 덮어쓰지 않는다.
- 두 개 이상이면 **비교 기준 버전**을 선택하고 접기/펼치기로 본문 내용 차이를 볼 수 있다. 제목·작성 메모·프로젝트 정보·평가 범위·승인 자료와 검토 기록·계산 결과와 산정 근거·담당자 해석을 항목별로 비교한다.
- 비교는 보관된 표시 내용의 차이다. 변경 사유의 진위·계산의 정확성·환경영향의 증감 원인을 자동 분석하지 않는다.
- 이전 버전의 수정·삭제·되돌리기는 제공하지 않는다. 내용을 고쳐야 하면 변경 설명을 남긴 새 버전을 저장한다.

## 4. 선택 버전 내려받기

- WEB-023의 접기/펼치기 안에서 PDF·Word·글 파일 형식을 골라 공통 내려받기를 누른다. 현재 선택한 버전의 사본으로 만든다.
- 최신 보고서는 기존처럼 현재 자료·계산·해석과 근거가 일치해야 내려받는다. 최신 근거가 바뀌면 새 버전 저장이 필요하다.
- 실제 이전 버전은 **과거 보관본임을 확인**한 뒤 내려받을 수 있다. 이력 확인 목적이므로 현재 자료와 달라도 허용하되 본문에 과거 보관본 안내를 넣고 파일명에 버전 번호와 과거보관본 표시를 붙인다.
- 문서 생성 전후 선택 버전과 근거를 다시 읽는다. 생성 도중 최신이었던 버전이 다른 화면의 저장으로 과거 버전이 되면, 과거 보관본 확인 없이 자동 내보내지 않는다. 생성 중 버전·형식 선택을 잠근다.
- 변경 기록도 보고서 본문·파일에 포함한다. 브라우저 밖의 파일을 다시 수정한 이력까지 추적하는 기능은 아니다.

## 5. 기존 저장본과 자료 보호

기존 키 `ecoable-lca-manager.report.v1`을 유지하며 내부 형식을 `{version:2, records:{프로젝트ID:[버전들]}}`로 확장한다. 기존 다른 여섯 키는 바꾸지 않는다.

- 이전 `{version:1, records:{ID:단일초안}}`은 읽기만으로 재저장하지 않는다. 현재 남은 한 건을 이전 앱 보관본으로 표시한다.
- 새 버전 저장에 성공할 때 기존 보관본과 다른 프로젝트 기록을 함께 유지하여 형식 2로 기록한다. 기존 번호가 v3이었다면 v3을 보관하고 다음은 v4다. 없는 v1·v2를 만들어내지 않는다.
- 이력 도입 전에 덮어써진 보고서와 기록하지 않은 작성자·변경 설명은 복구하지 못한다. 해당 항목은 미기록으로 표시한다.
- 각 저장본의 형식·프로젝트 ID·번호 연속성·변경 필수값·근거 사본을 검사한다. 손상된 저장본을 지우거나 부분 복구로 덮어쓰지 않는다.
- 예상 최신 번호와 근거를 비교해 다른 화면의 변경을 확인한다. Web Locks API가 있는 브라우저에서는 같은 출처의 보고서 저장 전체를 직렬화하여 다른 프로젝트와 다른 탭의 이력 쓰기도 보호한다. 미지원 환경은 기존 번호 비교에 의존하며 동시 쓰기의 완전한 원자성은 보장하지 않는다.
- 저장 공간 부족·쓰기 실패 시 기존 버전을 지우지 않는다. 자동 압축·정리·삭제와 전체 JSON 백업은 이번에 추가하지 않는다.
- 현재 계산·해석 기록에 문제가 있어도 유효한 과거 보고서의 조회와 명시적인 과거 보관본 다운로드를 허용한다. 최신본 생성과 다운로드는 막는다.
- 이력은 이 브라우저에 보관된다. GitHub·다른 컴퓨터로 자동 동기화하거나 변경 불가능한 서버 감사 기록을 제공하는 기능은 아니다.

## 6. 확인 범위

- 변경 JavaScript 구문과 Git 공백을 확인했다. 이번에 테스트를 추가·실행하지 않았으며 이전 166개를 이번 통과 수로 주장하지 않는다.
- 기존 localhost 가상 보관본 v1이 변경 설명·작성자 미기록으로 표시되고 당시 계산 결과·해석·본문을 그대로 보여주는 것을 확인했다. 새 변경 입력칸과 보관 버전 선택 화면도 표시했다. 사용자 127.0.0.1 입력 자료는 변경하지 않았다.
- 새 버전의 실제 추가·형식 2 쓰기·새로고침·두 버전 비교·동시 탭 저장·과거 보관본 파일 생성·쓰기 실패의 실행 검증은 남아 있다. 해당 사항은 구현과 코드 검토 범위다.
- PDF·Word 생성 자체의 확인 범위와 렌더링 제한은 WEB-023에 기록한다.

## 7. 쉬운 설명
