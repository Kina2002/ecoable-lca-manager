# WEB-071 로그인한 계정별 서버 저장

> 2026-10-27 사용자 요청으로 이 연결을 해제했습니다. 아래는 과거 구현 기록입니다. 현재 동작은 [WEB-072](WEB-072-disconnect-server-storage.md)를 따릅니다.

## 목적과 합의

2026-10-27 사용자가 롤플레이를 미루고 서버 저장을 요청했으며 ‘로그인한 사람마다 자기 기록 저장’을 선택했다. 기존 업무 규칙을 바꾸거나 팀 공동 편집을 시작하지 않는다. 로그인하지 않은 회사 담당자는 공개 체험을 계속 사용할 수 있다.

지금까지는 브라우저마다 별도 공책이었다. 이번 기능은 로그인한 사람마다 서버에 공책 한 권을 보관하고, 같은 계정으로 다른 기기에서 다시 여는 것이다.

## 사용 흐름

1. 공개 주소는 유지한다. 로그인하지 않으면 기존 브라우저 체험을 사용한다.
2. 상단 ‘로그인하고 내 기록 저장’을 누르면 Sites의 ChatGPT 로그인을 거친다.
3. 인증된 계정의 기록만 읽으며, 없으면 기본 가상 프로젝트로 시작하고 기준일을 서버에 처음 보관한다.
4. 업무 화면의 저장은 기존 검사를 거쳐 기기의 계정별 임시 사본을 갱신한다. 600ms 동안 변경을 모아 서버로 전송한다.
5. 대기/저장 중/서버 저장 완료/실패를 구분한다. 폼에 적기만 하고 저장하지 않은 입력은 전송하지 않는다.
6. 다른 기기에서는 같은 계정으로 로그인해 최신 기록을 연다. 열어 둔 화면의 실시간 공동 편집은 아니다.
7. ‘브라우저 체험’은 기존 기기 기록을 다시 연다. 서버 기록을 그 위에 합치거나 덮어쓰지 않는다.

## 기존 기록과 롤플레이 보호

- 기존 `ecoable-lca-manager.*` 기록은 자동 이전하거나 수정하지 않는다.
- 서버 화면은 계정 ID별 `lca-cloud-cache.v1.*` 임시 저장을 사용한다. 공통 저장 어댑터로 기존 업무 검사를 재사용한다.
- 기존 기록 이전은 ‘체험에서 백업 → 로그인한 화면의 설정에서 미리보기·선백업·확인 후 복원’ 순서다. 복원된 전체 기록은 서버로 전송된다.
- 원래 사용자 탭, 미저장 R08 메모와 최신 인수인계 백업은 이번 작업에서 대신 저장·복원·수정하지 않는다.

## 서버 구성

- `server/`: Sites Vinext 통합, TypeScript API, Cloudflare Workers, D1 `DB` 바인딩.
- 로그인/콜백/로그아웃은 Sites 기본 경로를 사용한다. 비밀번호를 직접 받거나 별도 OAuth를 구현하지 않는다.
- `GET /api/session`: 로그인 여부, 표시 이름, 계정 ID, 저장 한도.
- `GET /api/workspace`: 로그인과 현재 계정 확인 후 본인 기록 조회.
- `PUT /api/workspace`: 실제 로그인 계정과 요청 계정의 일치, 동일 출처·JSON, 크기·형식·버전 검사 후 저장.
- D1 `lca_workspaces`: `user_id` 기본키, `payload`, `revision`, `updated_at`, `last_write_id`. 소유자는 서버가 인증 신원에서 얻으며 클라이언트 지정 소유자로 조회하지 않는다.
- 프로젝트·자료·보고서 등 11개 저장 키와 기준일을 백업 v1 형식의 한 묶음으로 저장한다. 연결된 기록을 같은 버전으로 보관하기 위한 선택이며 개별 항목 검색용 테이블 확장은 아니다.
- 계정 응답은 `private, no-store`다. 다른 사용자 기록 목록/열람 API는 없다.
- Drizzle 생성 SQL로 스키마를 관리한다. 요청 중 테이블을 만들지 않으며 실제 기록·로컬 DB는 Git/배포물에 넣지 않는다.

## 실패와 다른 기기의 변경

- 서버 버전과 읽었을 때의 버전이 같을 때만 원자적으로 갱신한다. 다른 기기가 먼저 저장하면 409로 거절한다.
- 응답을 잃은 동일 요청은 같은 `writeId`와 내용을 확인해 중복 저장을 막는다. 새로 열 때 서버와 임시 내용이 같으면 이미 저장된 것으로 연결한다.
- 최신 서버와 미전송 임시 기록이 다르면 자동 병합/덮어쓰기 없이 화면을 잠근다. 기기 기록 다운로드·저장 전 입력 보관 확인 후 최신 서버 기록을 다시 연다.
- 같은 브라우저의 다른 창에서 임시 기록이 바뀌면 기존 창을 잠근다. 쓰기 전에도 임시 사본이 그대로인지 비교한다.
- 네트워크 실패 시 기기 사본을 보관하고 재시도/다운로드를 제공한다. 미전송 상태로 떠나면 브라우저 경고를 요청한다.
- 전체 복원/초기화/프로젝트 삭제의 저널이 있는 동안 전송하지 않는다. 교체 중 다운로드는 저널의 변경 전 기록을 보관한다.
- 로그인 계정이 도중에 바뀌면 계정 확인 헤더와 서버 신원이 달라져 저장을 거절한다.

## 범위와 한계

- 서버 요청 최대 1,000,000바이트(1MB). 파일 백업의 20MB 한도와 별도다. 초과 시 기기 기록은 보관하고 서버 저장 실패를 알린다.
- 첨부파일 원본 업로드, 팀 공유, 자동 충돌 병합, 서버 버전별 되돌리기, 메일·AI는 포함하지 않는다.
- 계정 임시 사본은 브라우저에도 남는다. 자동 삭제 정책/실제 고객 기밀자료 운영은 이번 학습용 범위가 아니다.
- 서버 저장과 업무 승인·프로젝트 완료는 별개다. 기존 단계 조건을 바꾸지 않는다.
