# WEB-067 진행 중 담당 연구원 변경과 이력

## 요청과 사용법

기존 배정 입력은 계약·착수에만 있어 범위 정의 이후 담당자를 바꿀 수 없었다. 프로젝트 상세 상단의 **담당 연구원 변경 → 새 연구원 선택 → 변경 사유 → 변경 저장**으로 연결한다.

- 유효한 현재 단계 1~9에서 등록 연구원을 선택한다. 같은 ID의 연구원과 빈 사유는 저장하지 않는다. 사유는 1,000자까지다.
- 10단계는 **담당 연구원 변경 이력**으로 표시하고 조회만 제공한다. 명시적 보완 재개 프로젝트는 실제 재개된 유효 단계를 따른다.
- 이전/새 담당자의 고정 ID와 당시 이름, 저장 시각(표시는 한국 시간), 단계, 사유를 누적한다. 도입 전 과거 변경을 만들어 내지 않는다.
- 계약·착수의 기존 담당자 저장도 연구원 값이 달라졌다면 같은 이력에 기록한다. 이 입력에서만 기존 미정 저장을 허용한다.

## 저장과 연결

- 새 저장 키 없이 scope.v1의 선택 `researcherHistory[projectId]` 배열을 사용한다. 기존 records와 백업을 읽으며 최신 이력의 담당자를 화면에 합성한다. 8·9단계 프로젝트를 범위 records의 낮은 단계로 저장하지 않는다.
- 최신 담당자·범위·유효 단계·이력 개수를 다시 비교하고 공통 Web Lock 안에서 등록 명단과 프로젝트 존재를 확인한다. 충돌/저장 실패 때 입력을 유지한다. 복원/삭제의 공통 epoch 보호를 재사용한다.
- 상세 요약·목록·연구원별 담당 건수·홈/할 일을 갱신한다. 요청문 생성 시 기존 최신 담당자/소속 조회를 사용한다. 이미 작성 중인 메일을 자동으로 바꾸지 않는다.
- 범위 입력 DOM을 유지하고 기대값의 담당자 부분만 갱신한다. 범위·자료 폼과 필터를 다시 만들지 않는다. 계약 배정에 별도 초안이 있으면 선택을 유지하고 다음 명시적 저장을 따른다.
- 과거 보고서/발송/제출/인증 사본은 고치지 않는다. 새 보고서는 최신 담당자를 사용하며 기존 보고서의 담당자 정보가 다르면 기존 최신성 확인 규칙이 작동한다. 계산 근거에는 담당자가 없어 계산 수치를 바꾸지 않는다.
- 백업 검사에서 이력 구조/연결 연구원을 검사하고 건수를 미리보기에 표시한다. 프로젝트 삭제 시 그 프로젝트의 변경 이력도 함께 제거하고 건수를 안내한다.

## 확인 범위

- 변경/추가 JavaScript 구문, Git 공백, 스크립트 순서와 DOM/이벤트 연결을 정적으로 확인한다.
- 이번 요청에는 테스트 지시가 없어 테스트를 추가하거나 실행하지 않는다. 실제 저장/취소/복귀, 반복 변경, 단계별 잠금, 다른 창 충돌, 복원/삭제, 초안 유지와 작은 화면의 실행 확인은 남아 있다.
- 원래 사용자 탭을 새로고침하거나 실습 프로젝트의 담당자·기록을 대신 바꾸지 않는다. 과거 WEB-061의 267개 자동검사는 이번 결과가 아니다.
