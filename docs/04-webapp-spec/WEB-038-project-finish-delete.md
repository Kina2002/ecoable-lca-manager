# WEB-038 프로젝트 완료와 생성 프로젝트 삭제 확인

작성일: 2026-10-18

## 삭제 버튼 위치 안내 보강 (2026-10-18)

사용자가 버튼을 찾지 못해 현재 화면을 읽어 확인했다. 열려 있던 라온소재는 기본 가상 샘플이라 삭제 버튼이 표시되지 않는 상태였다. 사용자 등록 프로젝트는 목록의 회사명·번호 아래에도 ‘프로젝트 삭제’를 추가하고 동일한 확인창으로 연결했다. 기본 샘플은 목록·상세에서 ‘기본 샘플 · 삭제 대상 아님’이라고 표시한다. 목록에서 삭제한 경우에도 명단·단계·자료를 다시 그리도록 연결했다. 삭제 대상·확인·저장 규칙은 유지한다. 구문·공백·정적 연결과 변경 전 샘플 화면 읽기만 확인했으며 새 버튼 클릭·확인·실제 삭제 실행 시험은 하지 않았다. 사용자 탭을 새로고침하거나 기록을 삭제하지 않았다.

## 사용자 합의

- 인증·등록 또는 고객의 최종 확인을 마친 프로젝트의 완료 처리, 완료일·근거·최종 보고서·확인 번호 보관과 계속 조회를 구현한다.
- 직접 생성한 프로젝트에 삭제 버튼을 추가한다. 사용자가 후속으로 요청한 ‘한 번 더 확인하는 문구창’을 제공하고 창에서 삭제를 다시 눌러야 실행한다.

## 프로젝트 완료

- 상세 → 인증·등록 → 프로젝트 완료 처리에 둔다. 9단계에서 진행 상태를 ‘승인·등록’으로 저장하고, 기존 최종 보고서·검토 경로·완료 근거가 최신일 때만 가능하다. 고객 제출도 최종 확인 번호·확인일을 같은 기존 상태로 기록한다. 제출 완료만으로 자동 완료하지 않는다.
- 최종 보고서 버전, 제출 유형·기관·요구명, 확인 번호·발급 또는 확인일을 기존 기록에서 불러와 보여준다. 보고서 보기로 보관 버전을 열 수 있다.
- 완료일은 오늘을 기본값으로 하고 오늘/달력을 제공한다. 담당자와 수정 가능한 완료 근거 문장을 불러온다. 사람이 최종 기록 확인에 체크하고 ‘프로젝트 완료 · 10단계로’를 눌러야 한다. 미래 날짜나 검토 완료일·발급/확인일보다 이른 완료일은 막는다.
- `certification.v1`의 기존 version 1 형식을 유지하고 끝에 `finished` 이벤트를 추가한다. actor/reason/at, finishedOn, confirmed, reportRevision, 당시 제출 details를 보관한다. 최종 보고서·내부/외부 검토 근거 사본은 같은 기록의 앞선 completed 이벤트에 계속 남는다.
- 기록 리비전과 최신 근거를 저장 직전에 재확인한다. 기존 공통 Web Lock을 사용하며 finished 이후 추가 이벤트·중복 완료·진행 정보 수정을 막는다. 예전 completed/started/updated 기록은 읽는다.
- currentStage에서 finished를 10단계 근거로 사용해 재실행·백업 복원 후에도 완료를 복원한다. 기존 scope의 단계 복원 합성 구조를 사용한다. 진행 중 홈 집계·할 일의 기존 stage < 10 조건에서 제외하며 단계 수·D-day를 갱신한다. 원래 자료·보고서 버전·검토·인증 이력은 읽기 전용 조회를 유지한다.
- 기본 10단계 가상 샘플에는 새 완료 기록을 만들어 넣지 않는다. 샘플 상태와 실제 저장한 완료 기록을 구분한다. 완료 취소, 단계 재개, 인증 만료·갱신은 이번 범위가 아니다.

## 직접 생성한 프로젝트 삭제

- `origin: user`인 목록의 회사명·번호 아래와 상세 제목 옆에 ‘프로젝트 삭제’를 표시한다. 실제 삭제 준비에서도 projects 저장 배열의 해당 ID가 있는지 확인해 기본 샘플 삭제를 막는다. 완료한 사용자 프로젝트도 삭제할 수 있다.
- native dialog 제목은 ‘이 프로젝트를 삭제할까요?’다. 회사명·프로젝트 번호·제품과 자료 요청(삭제 이력 포함)·보고서 버전·고객 의견·검증 지적 수, 함께 삭제할 범위·계산·해석·검토·인증·완료 기록을 표시한다.
- 취소/삭제 두 버튼을 두고 기본 초점은 취소다. 취소·Escape는 쓰지 않고 닫아 원래 버튼으로 초점을 돌린다. 처리 중에는 취소·Escape·중복 클릭을 막는다. 보관할 내용은 설정에서 먼저 백업하고 다른 앱 창은 닫도록 창에서 안내한다.
- 확인 전에 모든 기록을 격리된 기존 백업 검사로 확인한다. 확인창을 연 뒤 기록이 바뀌면 삭제하지 않고 창을 다시 열어 최신 대상·건수를 확인하게 한다.
- projects에서 해당 생성 기록과 수집 날짜, requests·comments의 해당 projectId 행, scope/modelling/interpretation/report/verification/review-route/certification의 해당 프로젝트 records만 제거한다. 보고서 v1 단일 기록과 v2 버전 배열을 모두 처리한다.
- 다른 프로젝트·담당 연구원 명단·샘플 기준일·번호 카운터를 보존한다. 새 프로젝트/자료/의견 번호를 재사용하지 않는다. 삭제 전후에 전체 형식·연결 검사를 거친다.
- 기존 전체 교체 저널·롤백·중단 복구·세대 검사를 재사용하므로 여러 키 중 일부만 삭제된 상태로 계속 작업하지 않는다. 성공한 현재 창은 새 명단으로 저장소를 다시 연결한 뒤 해당 세대만 재개해 목록으로 돌아간다. 두 자료 상태 필터와 기존 목록 필터를 제거하거나 초기화하지 않는다. 다른 창의 오래된 쓰기는 차단한다.
- 이 기능은 영구 삭제이며 앱 안 휴지통·개별 복원은 없다. 삭제 전 전체 백업 파일이 있다면 설정에서 전체 복원할 수 있지만 다른 기록도 그 백업 시점으로 교체된다. 임시 저널은 삭제 취소용 보관함이 아니다.
- Web Locks가 없는 환경과 업데이트 전 창의 동시 쓰기 한계는 WEB-037과 같다. 복원·삭제 전 다른 창을 닫도록 안내하며, 저장소 자체 손실까지 보장하지 않는다.

## 백업 호환과 구현

- 기존 11개 업무 저장 키를 유지한다. 새 도메인 저장 키는 추가하지 않는다. 백업 inspect를 삭제 준비에도 공유하고 새 finished 이벤트는 기존 인증 읽기 검사로 확인한다.
- 오래된 앱 코드는 finished 이벤트를 지원하지 않으므로 이 버전의 백업은 이 버전 이상에서 읽는다. 구형 인증 이력과 기존 WEB-037 백업을 새 코드에서 읽는 경로는 유지한다.
- `web/js/project-deletion.js`, `web/js/views/project-deletion.js`를 추가했다. certification 도메인/화면, project-detail, 공통 storage/app, HTML/CSS와 자산 버전을 연결했다.

## 확인 범위

- JavaScript 구문과 Git 공백, 코드·HTML 연결을 읽어 확인했다.
- 테스트 추가·실행은 하지 않았다. 실제 완료 저장·단계 복원·홈/할 일 제외, 삭제 확인창·취소·삭제·다른 프로젝트 보존·번호 유지·실패/중단 복구·다른 창·백업 복원·접근성·작은 화면의 실행 시험은 하지 않았다. 사용자 브라우저 기록을 실제로 완료하거나 삭제하지 않았다.
