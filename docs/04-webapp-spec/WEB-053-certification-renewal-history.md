# WEB-053 인증·등록 갱신 처리 이력

기준: 설계서 v02 F-12와 사용자의 기본 기능 순차 연속 구현 지시. WEB-050의 갱신 확인 할 일을 실제 처리 결과와 연결한다.

## 왜 만드는가

갱신 안내만 있으면 새 인증서를 받은 뒤에도 옛 만료일의 할 일이 계속 남는다. 준비·요청·완료를 기록하고, 공식 발급을 확인한 새 인증서의 날짜로 다음 관리 주기를 시작해야 한다.

## 화면과 동작

인증·등록 탭의 ‘인증·등록 갱신 기록’에서 처리 상태, 처리일, 확인 문서·기록 이름, 기록 담당자, 처리 내용과 근거를 적는다. 승인된 인증·등록에 한해 9·10단계에서 기록한다. 고객 제출에는 적용하지 않는다.

- **갱신 준비 / 갱신 요청:** 기존 인증 정보와 만료일을 유지하고 처리 이력만 추가한다. 안내 기간의 갱신 할 일에는 현재 처리 상태가 표시되며 계속 남는다. 실제 신청이나 이메일을 자동으로 보내지 않는다.
- **갱신 완료:** 기관의 완료 확인 체크, 이번 갱신의 제출일, 새 발급일·번호·공식 만료일이 추가로 필요하다. 새 발급일은 이전 발급일보다 늦고 처리일 이하여야 하며 만료일은 새 발급일보다 늦어야 한다. 처리일은 기존 발급일 이후부터 오늘까지다. 번호는 동일 번호를 다시 사용할 수 있다.
- 갱신 완료 시 현재 인증 정보와 만료일 기준만 새 문서로 바뀐다. 과거 보고서·인증서·프로젝트 완료 이력과 10단계는 보존한다. 옛 날짜의 갱신 할 일은 더 이상 계산하지 않고 새 만료일의 안내 기간이 오면 다시 보인다. 새 만료일도 이미 지났다면 안내는 계속 남는다.
- International EPD는 새 발급 건의 최신 버전·버전일 확인을 다시 요구한다. 옛 버전의 점검 기록은 이력에 남기고 새 발급 건의 점검 완료로 재사용하지 않는다.

이 기능은 공식 갱신 결과를 사후에 기록하는 기능이다. 같은 발급일의 단순 오기·편집 수정은 진행 정보 정정·버전 기준 기록으로 다루며, 새 발급일이 생긴 갱신과 구분한다. 기관의 등록 상태나 취소를 앱이 자동 조회하지 않는다.

## 저장·보호

기존 `certification.v1`에 `renewal-progress`, `renewed` 이벤트를 추가한다. 갱신 이벤트는 이전 인증 유형·제도·발급일·번호와 연결하고, 완료 이벤트 안에 새 인증 정보를 보관한다. 기존 기록을 수정하거나 지우지 않는다. 백업·복원과 프로젝트 삭제는 기존 인증 키를 사용한다. 쓰기 전에 수정 차수를 확인하고 오래된 화면·잘못된 날짜·기관 확인 누락은 저장하지 않는다.

## 검증

갱신 요청 중 할 일 유지, 완료 후 새 번호·만료일 전환과 이전 프로젝트 완료 기록 보존, 새 기간의 다음 갱신 안내, International EPD 점검 기준 재확인, 잘못된 날짜·번호·공식 확인 누락·고객 제출 제외를 검사했다. 전체 자동검사 **245개**, JavaScript 구문·Git 공백·정적 자산 HTTP 200을 통과했다. 실제 브라우저의 입력·클릭·좁은 화면 조작은 미확인이다.

면접 설명: “인증 갱신을 요청했다고 완료된 것은 아니기 때문에 그동안은 기존 만료일과 할 일을 유지합니다. 새 인증서가 발급된 것을 사람이 확인하고 기록해야 다음 유효기간으로 바뀝니다. 이전 인증서와 프로젝트 완료 이력은 그대로 남습니다.”
