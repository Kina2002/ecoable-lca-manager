# WEB-039 프로젝트 기본정보 수정과 변경 이력

작성일: 2026-10-18

## 사용자 합의

프로젝트를 잘못 입력했다고 삭제·재등록하지 않도록 기본정보 수정과 변경 이력을 제공한다. 계약·착수 단계에서는 회사명·제품명·업무 목적을 수정하고, 진행 중 목표일 변경도 지원한다. 기존 정보를 불러와 바꿀 부분만 고치며 보관한 보고서의 당시 내용은 유지한다.

## 화면과 조건

- 상세 화면 상단의 ‘기본정보 수정’에서 native dialog를 연다. 회사명·제품명·업무 목적·목표일을 최신 저장값으로 채운다. 사용자 생성 프로젝트와 기본 샘플 모두 같은 단계 조건을 따른다.
- 계약·착수(1)에서는 네 항목을 수정한다. 범위 정의~인증·등록(2~9)은 회사명·제품명·목적을 잠그고 목표일만 수정한다. 완료(10)는 버튼을 ‘기본정보·변경 이력’으로 표시하고 조회만 제공한다.
- 회사명·제품명은 각각 1~100자, 업무 목적은 기존 세 종류, 목표일은 유효한 날짜가 필수다. 숫자 8자리 날짜 입력과 오늘/달력을 제공한다. 수집 마감일·개별 요청 기한은 별도이며 함께 변경하지 않는다.
- 변경 사유는 선택 입력(최대 1,000자)이다. 변경 전후 내용·저장 시각·당시 단계는 자동 기록한다. 한국 시간으로 최신 순서의 접기·펼치기 이력을 표시한다. 바뀐 항목만 전→후로 보여준다. 변경이 없으면 저장하지 않는다.
- 닫기·Escape는 저장하지 않고 원래 버튼으로 복귀한다. 저장 중에는 중복 제출·입력 변경·취소를 막는다. 실패 시 입력을 유지한다. 저장 성공 후 상태 안내에 초점을 둔다.

## 저장 형식과 보호

- 새 저장 키 없이 기존 `projects.v1` version 1의 선택 `basicHistory`를 추가한다. 프로젝트 ID별 이벤트 배열이며 각 이벤트는 `before`, `after`(companyName/productName/purpose/targetDate), `at`, `stage`, `reason`을 보관한다. 기존 projects 배열의 최초 등록 정보는 덮어쓰지 않는다.
- 읽을 때 마지막 after를 현재 기본정보로 합치고 배열 길이를 basicRevision으로 사용한다. 예전 basicHistory 없는 저장본은 0차로 읽고 임의로 다시 쓰지 않는다. ID·프로젝트 코드·번호 카운터·등록 시각·담당자·평가 범위는 수정하지 않는다.
- 읽기 검사에서 알려진 프로젝트, 필드 형식·길이, 변경 존재, 시각/단계 순서, 전후 연결과 계약 이후 목표일 외 변경 금지를 검사한다. 첫 사용자 이벤트의 before는 최초 등록 정보와 일치해야 한다. 기본 샘플 목표일은 날짜에 따라 생성되므로 첫 before의 목표일은 당시 기록한 유효 날짜를 보존하고, 회사·제품·목적은 원래 정의와 비교한다. 후속 before는 직전 after와 일치해야 한다.
- 저장 직전에 최신 기본정보·이력 길이·단계를 다시 비교한다. 다른 창에서 수정·삭제·단계 이동하면 저장을 막고 창을 다시 열어 확인하도록 안내한다.
- 프로젝트 등록, 수집 마감일 저장, 기본정보 수정을 기존 검토 워크플로와 같은 Web Lock으로 묶는다. 등록/수집 날짜 저장의 두 화면 호출도 await와 저장 중 상태로 연결했다. 읽기 API는 동기를 유지하고 쓰기 API는 Promise를 반환한다. 잠금 미지원 브라우저·업데이트 전 창과 단계 저장 등 잠금을 쓰지 않는 기존 동작 사이의 완전한 창 간 트랜잭션을 보장하는 것은 아니다.
- 정상 저장 한 번에 이력과 현재값의 근거를 같은 JSON에 남긴다. 실패하면 기존 저장본을 유지한다. 브라우저 저장 세대 보호는 기존 어댑터를 사용한다.

## 관련 화면·백업·삭제

- 기존 프로젝트 객체의 기본정보만 갱신하고 상세의 제목·제품·목적·목표일과 읽기 전용 범위 요약을 부분 갱신한다. 폼·현재 상세 탭을 다시 만들지 않는다. 두 자료 필터, 목록 단계·검색·연구원·목적 조건을 초기화하지 않는다.
- 목록의 메타정보 읽기는 수집 날짜와 함께 최신 기본정보도 반영한다. 저장 후 목록/홈/할 일/연구원 프로젝트 명단을 갱신한다. 자료 요청 안내 문장도 현재 이름으로 바꾼다.
- 저장 보고서와 그 근거 사본은 수정하지 않는다. 아직 저장하지 않은 보고서의 기본 제목만, 사용자가 편집하지 않았고 기존 자동 제목 그대로일 때 새 제품명으로 갱신한다. 작성 중 제목은 덮어쓰지 않는다.
- 전체 JSON 백업은 projects 원문에 이력을 포함하며 복원 시 같은 프로젝트 읽기 검사를 거친다. 새 형식을 모르는 예전 앱에서 편집된 정보를 다루지 않도록 최신 코드로 새로고침한 상태에서 사용한다.
- 생성 프로젝트 영구 삭제 시 해당 basicHistory도 함께 지운다. 삭제 확인창의 이름·제품은 최초 등록 원문 대신 현재 수정된 값을 표시한다. 다른 프로젝트의 기본정보·이력·연구원 명단은 유지한다.
- 완료 취소, 회사·제품·목적의 2단계 이후 변경, 업종·유형·세부 동인·범위 항목 추가 수정, 이력 삭제·되돌리기는 이번 범위가 아니다.

## 확인 범위

- JavaScript 구문, Git 공백, 호출부와 HTML/자산 연결을 읽어 확인했다.
- 테스트 추가·실행은 하지 않았다. 실제 수정 저장·취소·새로고침 복원·기록 순서·단계별 잠금·다른 창 충돌·백업/삭제 호환·기존 등록/수집 날짜 저장·폼 보존·키보드·좁은 화면 실행 시험은 하지 않았다. 사용자 브라우저 기록은 변경하지 않았다.
