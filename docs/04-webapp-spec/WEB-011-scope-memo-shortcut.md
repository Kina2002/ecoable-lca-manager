# WEB-011 협의 메모와 범위 상태 바로 가기

## 목적과 사용자 요청

사용자는 범위가 어떻게 결정되고 있는지 메모로 남기고, 프로젝트 상세에서 수정 칸까지 스크롤을 많이 내려야 하는 불편을 줄이길 원했다. WEB-010에 협의 내용 기록과 바로 가기를 추가한다.

## 최종 배치 정정

사용자는 바로 가기를 **프로젝트 상세 창에서만** 원한다고 정정했다. 목록의 범위 상태는 일반 글자로 되돌리고 목록 바로 가기와 관련 초점 처리를 제거했다. 협의 메모와 상세의 바로 가기는 유지한다. 아래 동작·확인 절차도 이 최종 요구를 따른다.

## 동작

- 계약·범위 정의 단계의 범위 합의 기록에 **협의 메모**를 추가한다. 선택 입력이며 최대 2,000자다.
- 예: ‘고객은 요람~무덤을 요청했으며 사용 단계 자료 확보 가능 여부를 확인 중.’
- 기존 범위 저장 버튼으로 다른 범위 정보와 함께 저장한다. 저장 전의 입력만으로 저장됐다고 표시하지 않는다.
- 개요·범위의 읽기용 요약에도 메모를 표시하며 줄바꿈을 유지한다. HTML로 해석하지 않고 글자로 표시한다.
- 목록의 범위 상태는 일반 글자로 표시한다. 목록에서 범위 수정으로 바로 이동하는 버튼은 제공하지 않는다.
- 상세의 범위 상태도 버튼으로 표시한다. 누르면 범위 기록으로 이동하며 입력 중인 내용을 다시 만들거나 지우지 않는다.
- 키보드로 버튼을 실행할 수 있다. 수정 화면에서는 범위 상태 선택 칸에 초점, 읽기 전용에서는 기록 제목에 초점을 옮긴다.
- 목록으로 돌아가면 프로젝트 번호 버튼으로 초점을 복원한다. 프로젝트가 현재 단계 필터를 벗어났다면 기존 방식대로 단계 필터에 초점을 돌린다.
- 수집 이후에는 기존 읽기 전용 정책을 유지한다. 버튼을 ‘기록 보기’로 표시하고 기존 메모는 요약에서 확인한다. 수집 이후 메모 수정·범위 재협의·변경 이력은 구현하지 않는다.
- 메모는 현재 기록 한 건이다. 별도 날짜별 협의 이력이나 고객 동의의 증거가 아니다.

## ‘12개월이 아닌 기간을 사용하는 사유’의 의미

이번 평가에서 사용하는 자료 기간이 기본 12개월과 다른 이유를 설명한다. 예를 들어 신규 공장이 7월에 가동을 시작해 6개월치만 있다면 이유를 남겨 기간이 누락된 것인지 구분한다.

12개월은 이 시연 앱의 기본 설정이다. 모든 LCA에 무조건 같은 기간을 적용한다고 설명하지 않는다. 실제 기간·대표성은 적용 기준과 프로젝트 상황에 맞춰 확인한다. WEB-010의 기간 검사·확정 조건은 그대로 유지하고 입력칸 아래에 쉬운 설명을 추가한다.

## 기존 기록 보호

- 기존 `ecoable-lca-manager.scope.v1`의 범위 항목에 선택 필드 `scopeMemo`를 추가한다. 저장 키와 버전은 유지한다.
- 메모 필드가 없는 기존 저장본은 읽을 때만 빈 문자열로 취급한다. 읽었다는 이유로 저장을 다시 쓰지 않는다.
- 기존 기간·기준·합의 상태·단계와 자료 요청 저장소는 유지한다. 기존 기록을 초기화하지 않는다.
- 저장 실패 시 이전 메모·단계를 유지한다. 다른 화면에서 메모만 바뀌었더라도 오래된 화면에서 덮어쓰기·수집 시작을 막는다.
- 메모는 선택 항목이므로 확정·수집 시작의 필수 조건에 추가하지 않는다.

## 확인 방법

1. 새로고침 후 계약 또는 범위 정의 단계 프로젝트를 열고 상세의 범위 상태 버튼을 누른다.
2. 범위 기록으로 이동하고 상태 선택 칸에 초점이 오는지 확인한다.
3. 협의 메모를 적고 범위 저장한다. 요약에 메모가 나타나는지 확인한다.
4. 상세의 범위 상태를 누르고 기록이 유지되는지 확인한다.
5. 목록으로 돌아가 버튼 초점 복원과 새로고침 후 메모 유지를 확인한다.
6. 수집 이후 프로젝트는 ‘기록 보기’로 이동하고 읽기 전용을 유지하는지 확인한다.

## 검증

- `node --test web/tests/*.test.cjs`: **74개 통과**. 기존 70개와 메모 관련 4개다.
- 새 검사는 저장·새 저장소 복원·단계 이동 후 메모 유지, 메모 없는 기존 v1 읽기와 이후 수정, 2,000자 제한·잘못된 형식·저장 실패, 다른 화면의 메모 변경 감지를 포함한다.
- 변경 JavaScript 구문·HTML 연결·HTTP 응답·공백 오류를 확인했다. 상세 전용 배치 정정 후에는 구문·목록 바로 가기 제거와 상세 연결 유지·HTTP 200·공백 오류를 확인했다. 저장 로직은 변경하지 않아 기존 자동 검사를 반복하지 않았다.
- 기존 브라우저 보안 정책의 접근 차단을 우회하지 않았다. **실제 클릭·스크롤·키보드 초점·작은 화면은 미확인**이며 사용자의 화면 확인이 필요하다.

## 변경 파일

`scope.js`는 메모 보관·기존 기록 호환을, `views/scope.js`는 입력과 바로 가기 초점을 담당한다. `project-list.js`는 상태를 글자로, `project-detail.js`는 범위 상태 버튼·메모를 표시한다. `app.js`는 상세 버튼에서 범위 기록으로 이어지는 동작을 연결한다. 배치 정정 후 목록·앱 자산 버전은 WEB-011.1이다.

면접 설명 예: ‘범위 상태만으로는 협의 중인 이유를 알기 어려워 메모를 추가했습니다. 수정하려면 스크롤을 많이 내려야 해서 상세의 상태 표시를 버튼으로 바꿨고, 누르면 입력칸으로 이동하도록 했습니다. 이전 저장본에는 메모가 없으므로 읽을 때 빈 값으로 처리해 기존 데이터를 유지했습니다.’
