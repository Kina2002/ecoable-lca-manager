# WEB-037 전체 기록 백업·복원과 저장 위치 선택

작성일: 2026-10-18

## 사용자 합의

현재 브라우저의 업무 기록을 파일로 내려받고, 다른 컴퓨터에서 파일을 읽어 복원한다. 사용자가 저장할 폴더도 고를 수 있기를 요청했다. 설정 탭을 추가하되 용어사전은 주 메뉴 맨 아래를 유지한다.

## 화면과 사용 순서

1. 설정 → 백업 내려받기. 저장 위치 선택 / 브라우저 기본 다운로드를 고른다.
2. 위치 선택은 `showSaveFilePicker`의 다른 이름으로 저장 창에서 폴더와 파일명을 고른다. 선택을 취소하면 다운로드를 강행하지 않는다. 지원하지 않는 환경은 기본 다운로드로 표시하고 브라우저 설정의 저장 위치 확인을 안내한다. 지원되더라도 브라우저가 차단하면 기본 다운로드로 바꾸도록 안내한다.
3. 백업 파일 선택으로 파일을 읽는다. 이 시점에는 기존 기록을 쓰지 않는다. 백업 시각(한국 시간), 프로젝트 목록·수, 연구원·요청(삭제 포함)·보고서 버전·고객 의견·지적 수를 표시한다.
4. 현재 기록을 이번 화면에서 먼저 백업해야 복원할 수 있다. 일반 다운로드는 저장 완료를 앱이 알 수 없으므로 다운로드 요청과 실제 저장을 구분해 알린다.
5. 사용자가 파일 보관, 미저장 입력 별도 보관, 다른 앱 창 닫기와 전체 교체를 체크하고 ‘현재 기록을 백업 파일로 교체’를 누른다.
6. 복원 직전 현재 기록이 안전 백업과 같은지 비교한다. 바뀌면 다시 백업하도록 막는다. 성공 후 명시적 새로고침으로 저장소·화면·단계를 함께 다시 초기화한다. 자동으로 새로고침하지 않는다.

## 파일 구성과 검사

- JSON 루트: `format: lca-project-manager-backup`, `version: 1`, `createdAt`, `sampleDate`, `records`.
- `records`는 기존 11개 저장 키 전부를 포함한다. 각 값은 원래 JSON 문자열 또는 미저장 상태의 `null`이다. 보고서 v1/v2, 삭제 이력과 과거 근거 사본을 변경하거나 다시 생성하지 않는다.
- 프로젝트, 연구원, 범위, 요청, 계산, 해석, 보고서, 고객 의견, 외부 검증, 내부 검토 경로, 인증·등록을 포함한다.
- 가상 샘플은 앱의 정의와 파일의 생성 기준 날짜로 복원한다. 복원된 기준 날짜를 `ecoable-lca-manager.sample-date.v1`에 보관해 다시 열어도 샘플 일정이 임의로 이동하지 않게 한다. 새 사용자 프로젝트 생성일과 현재 날짜 표시는 오늘 기준을 유지한다.
- 20MB 상한, JSON 구문, 파일 식별자·버전·날짜, 정확한 키 구성, 각 기존 저장소의 읽기 검사와 번호·자료·근거 사본 검사를 재사용한다. 격리된 읽기 전용 저장소에 주입하므로 미리보기 검사는 실제 저장소에 쓰지 않는다.
- 담당 연구원 ID, 고객 의견과 보고서 버전, 검증 차수·답변의 보고서, 내부 검토·인증에 보관한 보고서 사본, 보고서 변경 이력의 고객 의견 연결도 확인한다. 최신 자료와 달라진 과거 계산·해석·보고서는 그 사본과 기존 변경 경고를 유지한다.
- 잘못된 현재 기록이나 앱이 모르는 저장 키가 있으면 정상 백업으로 포장하지 않고 멈춘다. 암호화·서명·위변조 증명 파일은 아니다.
- 첨부파일 원본, 저장 전 입력, 검색·필터와 화면 위치는 포함하지 않는다. 이 파일에 실제로 보관된 문서 이름과 기록만 포함한다. 서버 업로드·자동 백업·기록 합치기·전체 초기화는 이번 범위가 아니다.

## 교체·실패·다른 창 보호

- 기존 11개 저장 키와 도메인 형식은 유지한다. 공통 저장 어댑터의 읽기·쓰기에서 복원 세대와 진행 중 저널을 확인한다. 복원 후 오래된 앱 상태로 쓰려는 창은 재열기 안내로 멈춘다.
- 복원은 기존 검토 워크플로와 같은 Web Lock을 사용한다. Web Locks가 없는 환경에서는 동기 쓰기와 세대 검사를 사용하므로 모든 환경의 창 간 완전한 동시성 보장을 주장하지 않는다. 사용자는 복원 전에 다른 앱 창을 닫도록 명시적으로 안내받는다. 업데이트 전 코드를 연 창은 새 어댑터를 사용하지 않으므로 반드시 닫아야 한다.
- 브라우저 여러 키 쓰기는 단일 DB 트랜잭션이 아니다. 교체 전에 `ecoable-lca-manager.restore-journal.v1`에 기존 값을 먼저 보관한다. 공간 부족으로 저널을 못 쓰면 기존 값은 건드리지 않는다.
- 교체 후 각 값을 다시 비교한다. 실패하면 기존 값으로 되돌리고, 되돌리기에도 실패하면 저널을 남긴 채 앱 쓰기를 막는다. 다음 시작 때 같은 잠금 안에서 복원 전 값을 재적용한다. 저널이 남아 있으면 성공으로 간주하지 않는다.
- `ecoable-lca-manager.restore-epoch.v1`은 복원 세대다. 복원 후 다른 창의 저장을 막고, 복원 창도 새로고침 후에 사용하도록 한다. 이 두 제어 키는 업무 백업에 넣지 않는다.
- 임시 저널 공간이 추가로 필요하다. 브라우저 저장소 자체 삭제·기기 고장까지 저널이 보장하지 않으므로 내려받은 백업 파일을 별도로 보관해야 한다.

## 확인 범위

- JavaScript 구문과 Git 공백을 확인했다. 코드·HTML 연결을 읽어 검토했다.
- 사용자 요청에 따른 별도 테스트 추가·실행은 없다. 브라우저 화면, 실제 폴더 선택·다운로드·파일 읽기·복원·새로고침, 구형 보고서·다른 컴퓨터·다른 탭, 용량 부족·중단·복구·키보드·좁은 화면의 실행 시험은 하지 않았다. 기존 미확인 기능을 검증 완료로 바꾸지 않는다.
