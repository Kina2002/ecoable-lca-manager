# WEB-062 고객사 내부 취합 부서·필요한 증빙 안내

구현일: 2026-10-19

## 사용자와 정한 업무 흐름

고객사 담당자가 내부 부서의 자료를 모아서 연구원에게 전달한다. 자료별 부서는 고객사 담당자가 취합할 때 참고하는 정보이며, 부서를 고른다고 연락 대상이 바뀌지 않는다. 요청문 수신 대상은 기존 프로젝트의 고객사 담당자다.

## 화면과 사용법

1. 자료 요청을 등록한 뒤 해당 행의 **취합 부서·증빙 안내**를 펼친다.
2. **고객사 내부 취합 부서**와 **필요한 증빙 종류**를 선택하거나 직접 입력한다. 모두 선택 사항이며 각 100자 이내다.
3. **구분별 예시 채우기**는 예시만 채운다. 에너지는 시설관리/고지서, 생산량·할당 근거는 생산/생산실적 등이며 실제 고객사 조직을 확인하고 바꿔 저장한다. 기존 기록에 자동 적용하지 않는다.
4. **취합 정보 저장** 후 요청문을 만들면 해당 자료에 저장된 부서와 증빙 종류, 담당자가 취합해 전달해 달라는 문장을 포함한다. 미정 값은 문장에 임의로 채우지 않는다.
5. **받은 자료 기록** 창에서 현재 요청의 안내와 실제 받은 증빙 파일 이름을 비교한다. 필요한 증빙의 종류와 실제 파일 이름은 별개다.

입력 비우기는 폼만 비우고 저장 버튼을 눌러야 반영된다. 미정 항목은 접힌 제목에서도 알린다. 미정 때문에 단계 이동·승인·자료 제출을 막지 않는다. 삭제한 요청과 9단계 이후에는 현재 저장 안내만 조회한다. 파일 원본 업로드나 고객사 부서별 실제 발송은 추가하지 않았다.

## 저장과 보호

- 기존 `requests.v1` 각 요청의 선택 `collectionContext`에 department/evidenceType/revision/updatedAt을 보관한다. 새 키나 백업 버전은 추가하지 않는다. 예전 요청은 필드 없이 읽고 값을 만들어 다시 쓰지 않는다.
- 새 기록의 문자열·길이·제어문자·revision/시각을 읽기와 저장 양쪽에서 검사한다. 저장 전 최신 요청/단계와 편집을 시작한 취합 정보를 비교한다. 다른 창에서 바뀌면 기존 입력을 남기고 중단한다.
- 공통 쓰기 잠금이 있는 환경에서는 잠금 안에서 최신 읽기와 저장을 수행한다. 저장 실패·복원 세대 보호는 기존 storage 경로를 사용한다. 모든 구형 쓰기 경로 사이의 완전한 서버 트랜잭션을 제공하는 것은 아니다.
- 필터/목록 재그리기 시 같은 프로젝트의 취합 폼 초안과 편집 시작 값을 메모리에 보관한다. 저장 성공 때만 초안을 제거한다. 새로고침/다른 프로젝트의 미저장 초안 영구 보관은 제공하지 않는다.
- 기존 요청 삭제/복원과 JSON 백업/복원은 요청 원문을 유지하므로 취합 정보도 함께 보관한다. 복원 검사는 requests 저장소 검사를 재사용한다. 실제 백업 파일 왕복은 이번에 실행하지 않았다.
- 취합 정보만 수정하면 자료 상태·받은 수치·증빙 파일 이름·검토 결과·계산 근거 서명은 그대로 유지한다. 계산 근거 사본·CSV·보고서에는 이번 업무 안내 필드를 추가하지 않는다. 기존 보관 사본도 변경하지 않는다.
- 요청문 생성 근거에는 취합 정보를 포함하여, 생성 이후 부서/증빙 정보가 바뀌면 이전 문구를 복사하거나 발송 기록으로 저장하기 전에 재생성을 안내한다. 과거 발송 사본은 그대로 남긴다.

## 확인과 제한

- 최신 원격 main의 WEB-061을 fast-forward로 받은 뒤 WEB-062를 구현했다. 기존 사용자 브라우저/저장 기록은 조작하지 않았다.
- 변경 JavaScript 6개 구문 검사와 diff 공백, 스크립트 연결을 확인했다. 자동 테스트는 추가·실행하지 않았다. 267개 통과는 WEB-061 당시 기록이다.
- 실제 선택/예시/저장/필터 왕복·입력 유지·동시 편집 충돌·요청문/받은 자료 표시·백업 왕복·모바일 배치의 실행 확인은 남아 있다.

## 쉽게 말하면

고객사 담당자에게 보내는 준비 목록에 “이 항목은 시설관리 쪽에 확인하고 고지서를 함께 모아 주세요”라는 참고 내용을 붙이는 기능이다. 담당자가 내부 자료를 취합해 전달하는 흐름을 유지한다.
