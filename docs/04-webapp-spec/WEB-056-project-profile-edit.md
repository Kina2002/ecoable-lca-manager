# WEB-056 프로젝트 추가정보 편집

사용자가 승인한 세 번째 기능. 기존 기본정보 수정 창에서 업종·유형·세부 동인·결과 활용처를 입력·수정하고 변경 이력을 보관한다.

## 왜 만드는가

가상 샘플에만 적혀 있던 정보를 신규 프로젝트나 실제 협의 내용에 맞게 바꿀 수 있어야 한다. 업종은 고객사의 분야, 프로젝트 유형은 수행할 업무, 세부 동인은 의뢰한 구체적 계기, 활용처는 결과를 제출·활용할 곳이다. 활용처에 인증 제도를 고르는 것은 인증을 획득했다는 기록과 구별한다.

## 화면·규칙

- 상세 상단 ‘기본정보 수정’ 창에 추가정보를 넣는다. 업종·유형은 단일 선택, 세부 동인·활용처는 여러 개 선택한다. 다중 선택은 접어서 표시하고 선택 건수를 보여 준다. 미정이나 빈 선택을 명시적으로 저장할 수 있다.
- 추가정보는 1~8단계에서 편집한다. 인증·등록 준비(9) 이후는 제출 근거를 보호하기 위해 읽기 전용이다. 회사·제품·업무 목적은 기존대로 계약(1)에서만 수정하고 목표일은 1~9단계에서 수정한다. 완료(10)는 조회만 한다.
- 기본정보와 추가정보를 한 번의 저장으로 반영한다. 변경 전후, 당시 단계·한국 표시 시각·선택 사유를 같은 창의 이력에서 확인한다. 한쪽만 바뀌면 그 이력만 늘린다.
- 상세 요약의 업종·유형, 업무 목적 카드의 동인·활용처, 목록 검색·할 일·정보 확인 안내문에 최신 값을 연결한다. 자료 상태 필터 두 개와 기존 작성 폼을 유지한다.

## 보고서 연결

기존 보고서 보관본은 수정하지 않는다. 추가정보를 편집한 프로젝트는 새 보고서의 프로젝트 사본에 업종·유형·동인·활용처를 담고 본문에도 표시한다. 최신 프로젝트 정보와 보관본이 다르면 기존 보고서의 기준 변경 안내와 새 버전 저장 절차를 사용한다. 계산 활동량이나 외부 계산 결과를 자동 변경하지 않는다. 최초 추가정보 편집 전의 옛 보고서는 업그레이드만으로 새 필드를 임의 삽입하지 않는다.

## 저장·호환·보호

기존 `projects.v1`에 선택적인 `profileHistory`를 추가한다. 기존 `basicHistory`·등록 원문·번호·수집 마감일을 보존한다. 샘플의 기존 ‘국내 환경성적표지’ 표현도 유지해 읽고, 신규 선택 목록은 설계서 상수를 사용한다. 다른 창의 기본/추가정보 수정 차수와 현재 단계를 확인한다. 잘못된 선택·중복 값·손상 이력·저장 실패 시 기존 값을 바꾸지 않는다. 백업은 기존 프로젝트 키를 포함하며 프로젝트 삭제 때 해당 추가정보 이력만 함께 제거한다.

## 검증

샘플 무수정 읽기, 추가정보 저장·재읽기·이력, 다른 창과 9단계 쓰기 차단, 잘못된 선택·손상 저장본 보호, 기본/추가정보 동시 저장 실패의 원자성, 옛 보고서 보존·새 기준 변경, 백업 검증과 프로젝트별 삭제 격리를 검사했다. 전체 자동검사 **257개**, 변경 JavaScript 구문·Git 공백·정적 자산 HTTP 200이 통과했다. 실제 브라우저의 창·체크박스·편집·저장·작은 화면 배치는 미확인이다.
