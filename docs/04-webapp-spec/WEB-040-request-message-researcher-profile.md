# WEB-040 자료 요청문과 연구원 소속 정보

작성일: 2026-10-18

## 사용자 합의

자료 요청문을 만들고 의도한 동작을 테스트한다. 추가 요청으로 메일 첫 인사말에 연구원의 회사·부서·이름을 넣고, 담당 연구원 탭에 가상 소속과 정보 수정 버튼을 제공한다. 실제 메일 발송과 AI 연결은 포함하지 않는다.

## 요청문 사용 흐름

1. 프로젝트 상세 → 자료 요청 → **요청문 만들기**를 펼친다.
2. 처음 요청 / 미제출 재요청 / 보완 요청을 선택한다.
3. 넣을 자료를 고르고 **선택한 자료로 요청문 만들기**를 누른다.
4. 제목·본문을 확인하고 직접 고친 뒤 제목 / 본문 / 둘 다 복사한다.

- 처음 요청과 미제출 재요청은 현재 프로젝트의 미삭제 `요청` 상태 중 받은 자료가 없는 항목만 대상으로 한다. 보완 요청은 `보완 요청` 상태만 대상으로 한다. 제출됨·검토 중·승인 자료를 미제출로 재촉하지 않는다.
- 회사·제품·고객 담당자·자료 기준기간·요청 번호/내용·제출 기한·연구원 소개/서명을 저장 기록으로 채운다. 기한이 같으면 한 번, 다르면 항목별로 표시한다.
- 보완 요청은 저장한 보완 사유와 **기존 제출 기한**을 넣고, 보완 기한은 별도 협의라고 표시한다. 새 기한을 임의로 확정하지 않는다.
- 없는 값은 `[입력 필요: …]`와 안내로 남긴다. 연구원은 프로젝트의 researcherId로만 연결하며 동명이인·이름만 있는 기록의 소속을 추측하지 않는다.
- 원자료·자료 상태·프로젝트 단계는 생성·편집·복사로 바뀌지 않는다. 9단계 이후는 새 요청문을 만들 수 없다. 기존 두 자료 상태 필터·개별/일괄 등록 폼은 유지한다.
- 직접 수정한 글은 선택/종류/원자료가 바뀌어도 유지한다. 다시 생성하려면 교체 확인을 체크한다. 선택이나 종류가 바뀌면 다시 생성 전 복사를 막는다.
- 복사 직전 프로젝트·선택 자료·연구원 정보를 다시 읽고 생성 당시와 비교한다. 상태·보완 사유·소속 등이 바뀌면 기존 글을 보존하며 다시 만들도록 안내한다. 클립보드 비동기 처리 뒤에도 다시 확인한다.
- 클립보드 쓰기가 완료된 뒤에만 성공을 표시한다. 거부/미지원이면 수동 복사할 내용을 선택해 제공한다. 작성 초안과 발송 기록은 별도 저장하지 않는다.

## 담당 연구원

| 기본 가상 연구원 | 회사 | 부서 |
| --- | --- | --- |
| 김하늘 | 새움환경컨설팅 | 제품환경팀 |
| 박서연 | 새움환경컨설팅 | 탄소평가팀 |
| 이도윤 | 새움환경컨설팅 | LCA분석팀 |

- 등록 시 이름(필수)·회사/부서(선택)를 받는다. 각 항목은 최대 100자다.
- 카드의 **연구원 정보 수정**에서 최신 이름·회사·부서를 불러와 수정·저장한다. 취소/Escape는 저장하지 않는다. 빈 회사·부서는 미정으로 표시한다.
- 기존 `researchers.v1` version 1에 선택 회사/부서 필드와 `profiles` 맵을 추가한다. 샘플·사용자 연구원 모두 ID별 현재 프로필과 revision을 저장한다. 구형 이름만 있는 사용자 기록은 빈 소속으로 읽고 읽는 것만으로 다시 쓰지 않는다.
- 저장 전 현재 프로필과 편집 시작 값/리비전을 비교해 오래된 편집을 차단한다. 저장 실패 시 기존 기록과 입력을 유지한다. 기존 동기 저장 방식이며 여러 창의 완전한 트랜잭션/서버 감사 이력은 제공하지 않는다.
- 연구원 ID·번호·담당 프로젝트 연결·번호 카운터를 유지한다. 프로젝트에 당시 기록한 이름과 보관 보고서 사본을 덮어쓰지 않는다. 새 요청문은 ID로 연결된 최신 프로필을 사용한다. 이름이 다르면 연구원 카드의 프로젝트 목록에 기록된 이름도 표시한다.
- 기존 전체 JSON 백업은 researchers 원문에 추가 필드도 함께 보관한다. 최신 앱에서 읽어야 한다.

## 검증 결과

사용자가 테스트를 명시적으로 요청해 자동검사를 추가·실행했다.

- `node --test web/tests/*.test.cjs`: **217개 통과, 실패 0개**. PowerShell에서는 파일 목록을 인수 배열로 전달했다.
- 요청문 세 종류, 상태별 제외, 선택 항목/공통·개별 기한, 보완 사유, 누락 값·잘못된 날짜·중복 번호, HTML 문자와 긴 글의 원문 처리, 원본 불변, 변경 감지, 클립보드 완료/거부/미지원, 실제 자료 저장소의 추가 쓰기 없음 등을 검사했다.
- 연구원 기본 소속·신규 등록·기존 형식 읽기·샘플/사용자 수정·연결/번호 보존·오래된 편집·잘못된 값·저장 공간 오류를 검사했다.
- WEB-039에서 프로젝트 쓰기 API가 Promise로 바뀐 뒤 기존 검사 일부가 완료를 기다리지 않아 실패했다. 해당 검사 호출을 await로 고쳤다. 이를 이번 기능의 실제 앱 오류로 설명하지 않는다.
- 별도 `127.0.0.1:5188` 저장 공간의 실제 UI에서 세 자료 일괄 등록, 빈 대상의 생성 차단, 최초 요청문, 회사/부서 소개, 직접 편집·교체 확인, 미제출 재요청, 받은 자료 제외, 보완 사유 반영·기존 기한 구분을 확인했다.
- 실제 UI에서 연구원 소속 수정/저장·취소·새로고침 복원·소속 포함 신규 등록을 확인했다. 다른 창에서 소속을 바꾼 뒤 기존 요청문 복사를 차단하고 다시 만들면 최신 소속을 반영하는 것도 확인했다.
- 실제 복사 버튼의 성공 안내를 확인했다. 브라우저 검사 도구의 가상 클립보드는 앱의 시스템 클립보드와 연동되지 않아, 외부 편집기에 붙여 넣은 최종 문자열까지는 확인하지 못했다. 정확한 전달 문자열과 실패 경로는 자동검사로 확인했다. 모바일/모든 브라우저/실제 권한 거부 UI는 미확인이다.
- 화면 검사는 별도 테스트 origin만 사용했다. 사용자의 5180 탭·저장 기록을 초기화하거나 테스트 자료를 넣지 않았다. 실제 메일을 보내지 않았다.

## 후속 범위

메일 계정 연결·발송/수신 이력·AI 문장 생성, 회사/부서의 조직 관리, 요청문 초안/템플릿 저장은 별도로 합의한다. 실제 내부 LCA 계산과 AI는 기존 사용자 결정대로 기본 기능 완성 뒤 검토한다.
