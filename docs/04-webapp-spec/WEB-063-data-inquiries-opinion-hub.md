# WEB-063 자료 질의와 질문·의견 통합 조회

구현일: 2026-10-19

## 사용자 합의

자료에 관해 고객에게 확인할 질문·고객 답변·해결 여부를 해당 자료에 연결한다. 기존 보고서 고객 의견과 외부 검증 지적도 한곳에서 확인하고 원래 기록으로 이동한다.

## 화면

- 프로젝트 상세의 **질문·의견** 탭에서 자료 질의/고객 의견/검증 지적을 종류와 처리 상태로 고른다. 최근 변경 순으로 보여주며 기존 고객 검토·검토/검증 탭을 유지한다.
- **자료 질의 등록하기**를 펼쳐 요청 번호·질문·기록 담당자를 선택/입력한다. 담당자는 기존 연구원 기본값과 선택 보조를 사용한다. 자료 요청이 없으면 등록을 막고 먼저 요청을 등록하도록 안내한다.
- 자료 요청 행의 **질문 등록**은 같은 프로젝트의 질문 입력 영역으로 이동하고 해당 자료를 선택한다. 다른 자료에 작성 중인 질문이 있으면 내용을 유지하고 안내한다.
- 질의 목록은 접기/펼치기다. 질문 당시 요청 내용과 원 질문을 보관하며 답변·종결 근거·재개 사유와 기록자/한국 시각을 이력으로 남긴다.
- 고객 의견·검증 지적은 같은 화면에서 원문·상태·보고서/차수·저장 답변을 조회하고 **원래 기록에서 답변·처리**로 이동한다. 원래 단계·보고서·차수 조건을 재사용한다. 기존 의견을 복제 저장하지 않는다.

## 자료 질의 처리

1. **열림**으로 등록한다. 요청이 아직 미제출이어도 질문할 수 있다.
2. 고객에게 받은 답변을 적고 처리 방법을 확인 중/설명으로 해결/수정 자료에 반영 중에서 선택해 **답변 저장**한다.
3. 설명으로 해결하거나 수정 자료 반영을 확인한 뒤 종결 근거를 적고 저장된 답변 확인에 체크해 **질의 종결**한다. 확인 중 상태는 종결하지 못한다.
4. 종결 후에는 사유와 담당자를 남겨 **다시 열기**를 할 수 있다. 새 답변을 받아야 다시 종결할 수 있다.

수정 자료 반영을 선택하려면 질문 등록 당시와 다른 받은 자료 updatedAt이 필요하다. 실제 수정 자료는 기존 자료 요청의 받은 자료 창에서 먼저 기록한다. 답변에 연결한 받은 자료가 종결 전에 또 바뀌면 최신 답변 확인을 요구한다. 설명 답변은 자료를 자동 수정/승인하지 않는다. 질의 자체가 기존 단계 이동 조건을 추가로 막지는 않는다.

질의는 1~8단계의 미삭제·해당되는 자료에서 기록한다. 삭제/해당 없음인 자료와 9단계 이후는 이력 조회다. 과거 질문은 사라지지 않으며 현재 업무 조건이 다시 허용되면 기록할 수 있다. 메일 발송·고객 직접 입력 포털은 추가하지 않았다.

## 보관과 데이터 보호

- 기존 requests.v1의 선택 inquiries에 전역 INQ 번호·프로젝트/요청 ID·질문 당시 요청 설명/구분/받은 자료 시각·불변 원 질문·추가 이벤트를 저장한다. 새 저장 키/전체 백업 형식 변경은 없다.
- 읽기 시 요청/프로젝트 연결·번호·원 질문/이벤트 길이와 날짜·허용 상태 전이를 검사한다. 기존 기록은 inquiries 없이 읽으며 읽기만으로 새 필드를 저장하지 않는다.
- 변경은 공통 Web Lock 안에서 최신 단계/자료/이벤트 개수를 확인하고 한 번의 requests 쓰기로 저장한다. 이전 이벤트를 덮어쓰지 않는다. 다른 창의 변경은 현재 폼을 유지하며 저장을 거부한다.
- 질의 카드와 신규 질문 폼은 목록 갱신/탭 왕복 때 유지한다. 충돌 시 직접 **최신 기록 불러오기**를 눌러 입력을 교체한다. 프로젝트를 바꾸거나 새로고침하면 미저장 초안을 영구 보관하지 않는다.
- 기존 JSON 백업은 요청 원문과 함께 질의도 보관·검사하고 미리보기에 건수를 표시한다. 직접 생성한 프로젝트 삭제는 해당 프로젝트의 질의만 함께 제거하고 재확인 창에 건수를 표시한다. 다른 프로젝트/번호 카운터/기본 문장/발송 사본을 보존한다.
- 자료 질의는 자료 수치·승인 상태·계산 근거·보고서 사본을 바꾸지 않는다. 과거 고객 의견/검증 지적의 저장 구조와 종결 조건도 동일하다.

## 할 일·홈

미종결 질의를 자료 질의 유형으로 표시한다. 제목을 누르면 질문·의견의 해당 질의를 펼친다. 활성 자료의 1~8단계만 대상이며 완료/읽기 전용 이력은 자동 할 일에서 제외한다. 홈의 기존 연구원 필터와 확인 필요 집계에 같은 할 일을 사용한다. 마감일을 임의로 만들지 않는다.

## 함께 고친 기존 초기화 오류

실제 초기 화면 확인 중 WEB-061 프로젝트 보충 정보의 날짜 입력을 부모 노드에 붙이기 전에 inputAssist.date를 호출해 app 초기화가 중단되고 탭 클릭이 동작하지 않는 오류를 발견했다. 입력/레이블을 먼저 붙인 뒤 보조 기능을 연결하도록 순서를 고쳤고 해당 스크립트 캐시 버전을 갱신했다.

## 확인 범위와 제한

- 변경/추가 JavaScript 14개 구문과 diff 공백, 스크립트 연결을 확인했다. 자동 테스트 추가·실행은 하지 않았다. 267개 통과는 WEB-061 당시 기록이다.
- 종료된 미리보기 서버를 5180에서 다시 실행했다. 임시 탭의 실제 앱 시작→상세→질문·의견 탭 전환과 빈 목록/분류/상태/등록 접기를 확인했다. 원래 사용자 탭을 새로고침하거나 업무 기록을 생성/삭제/복원하지 않았다.
- 실제 질의 등록/답변/종결/재개·새 받은 자료 연결·충돌·할 일 이동·백업/프로젝트 삭제·모바일의 전체 흐름 확인은 남아 있다. 원래 기록이 없는 상태에서 조회한 초기 화면을 전체 실행 검증으로 설명하지 않는다.
