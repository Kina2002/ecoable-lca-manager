# WEB-002 · 단계별 프로젝트 건수와 단계 선택 필터

- 기준: 웹앱 설계서 v02 3장·7장, 사용자가 제공한 단계별 프로젝트 화면
- 작성일: 2026-10-16
- 관계: F-09의 단계별 프로젝트 현황, F-01의 단계 필터 부분
- 상태: 구현·아래 검증 완료. 사용자와 화면·설명을 확인한 뒤 다음 기능을 정한다. F-01·F-09 전체 완료를 뜻하지 않는다.

## 1. 왜 만드는가

여러 프로젝트를 관리하는 연구원은 '자료를 모으는 중인 업무만', '검증 중인 업무만' 빠르게 찾고 싶다.
전체 명단을 일일이 읽지 않아도 되도록 단계별로 세고, 원하는 단계의 명단만 보여준다.

쉽게 말해 위쪽 숫자는 분류해 세어 둔 명단의 개수이고, 단계 버튼은 그 분류의 명단을 펼치는 손잡이다.
버튼은 조회 조건만 바꾼다. 실제 프로젝트의 단계를 옮기는 버튼이 아니다.

## 2. 사용 흐름

1. 페이지를 열면 10단계의 건수와 전체 프로젝트 7개가 보인다.
2. '데이터 검토 1개' 버튼을 누른다.
3. 선택한 단계가 진한 초록으로 표시되고 다온케미칼만 보인다.
4. 다른 단계를 누르면 해당 단계의 명단으로 바뀐다.
5. 같은 단계를 다시 누르거나 '전체 보기 7'을 누르면 전체로 돌아온다.
6. 0개인 단계를 누르면 해당 단계의 프로젝트가 없다는 안내가 나온다.

## 3. 규칙

- 단계 이름과 순서는 설계서 v02의 10단계를 사용한다. 참고 이미지의 5단계로 줄이지 않는다.
- 위쪽 건수는 항상 전체 원본 명단으로 계산한다. 아래 목록을 걸렀다고 다른 단계가 0으로 바뀌지 않는다.
- 완료·사후관리 프로젝트도 해당 단계에 포함한다. 숫자는 '그 단계에 현재 속한 프로젝트 수'다.
- 선택은 한 번에 하나다. 선택한 단계와 전체 보기의 `aria-pressed`로 현재 상태를 표시한다.
- 필터로 새 배열을 만들며 원본 명단과 프로젝트의 단계 값은 바꾸지 않는다.
- 선택 후에도 버튼을 다시 만들지 않아 키보드 초점이 유지된다. Enter·Space로도 누를 수 있다.
- 필터 선택은 저장하지 않는다. 새로고침하면 전체 보기에서 시작한다.
- PC에서는 순서를 보여주는 화살표 모양, 좁은 화면에서는 다섯 칸씩 두 줄로 표시한다.
- 휴대폰에서는 짧은 단계 이름을 쓴다. 버튼의 접근성 이름에는 전체 단계 이름과 건수를 제공하고, 목록 제목에도 선택한 전체 이름을 보여준다.
- 결과 안내는 `role="status"`로 전달한다. 0건 안내는 선택한 단계 이름을 포함한다.

## 4. 초기 샘플의 기대 건수

| 단계 | 개수 | 프로젝트 |
|---|---:|---|
| 계약·착수 | 1 | 이음모빌리티 |
| 범위 정의 | 1 | 해든솔라 |
| 데이터 수집 | 1 | 라온소재 |
| 데이터 검토 | 1 | 다온케미칼 |
| 계산(모델링) | 0 | 없음 |
| 결과 해석 | 1 | 새봄리사이클 |
| 보고서 | 0 | 없음 |
| 제3자 검증 | 1 | 솔뫼철강 |
| 인증·등록 | 0 | 없음 |
| 완료·사후관리 | 1 | 단단내화 |

합계는 7개다. 이 숫자를 HTML에 고정해서 쓰지 않고 명단에서 계산한다.

## 5. 코드가 움직이는 순서

1. 기존 `data.js`에서 전체 샘플 명단을 만든다.
2. `rules.js`의 `stageCounts(projects)`로 10단계의 건수를 센다.
3. `stage-filter.js`가 건수를 단계 버튼으로 보여준다.
4. 사용자가 누른 단계 번호를 `app.js`의 `selectedStage`에 기억한다. `null`은 전체 보기다.
5. `projectsForStage(projects, selectedStage)`가 조건에 맞는 명단만 골라 새 배열로 반환한다.
6. 기존 목록 화면은 골라진 명단을 보여주고 제목·건수·빈 목록 안내를 갱신한다.

전체 명단은 보관한 원본, 선택한 명단은 잠시 골라 본 결과다.
이 둘을 구분해야 전체 보기로 돌아갈 수 있고, 다른 단계의 숫자도 유지할 수 있다.

## 7. 면접 설명

**왜 만들었나요?**

연구원이 프로젝트 전체를 읽지 않아도 특정 업무 단계의 프로젝트를 바로 찾도록 만들었습니다.

**필터가 프로젝트 단계를 바꾸나요?**

아닙니다. 선택한 단계와 같은 프로젝트만 새 명단으로 골라 보여줍니다. 실제 단계 값과 원본 명단은 유지합니다.

**하나를 골랐는데 다른 단계의 개수가 그대로인 이유는 무엇인가요?**

단계별 건수는 전체 명단으로 세고, 아래 목록만 선택 조건으로 거릅니다. 그래야 다른 단계에 남아 있는 업무도 계속 볼 수 있습니다.

**왜 모든 숫자를 1·0으로 직접 써두지 않았나요?**

명단에서 계산해야 나중에 프로젝트가 늘거나 단계가 바뀌었을 때에도 같은 규칙으로 정확히 셀 수 있기 때문입니다.

## 8. 이번 기능의 경계

프로젝트 실제 단계 변경, 검색·목적·담당자 필터, 프로젝트 상세·등록·수정, 필터 저장은 구현 범위에 포함하지 않는다.
다음 기능은 사용자가 이 화면을 확인한 뒤 함께 정한다.
