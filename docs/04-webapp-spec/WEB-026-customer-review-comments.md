# WEB-026 고객 검토 의견과 보고서 버전 연결

- 작성일: 2026-10-18
- 승인: 보고서 버전에 고객 의견·담당자 답변·처리 상태·수정 버전을 연결하자는 제안에 사용자가 “응 만들어보자”로 승인했다.
- 설계 대응: F-08 검토 의견의 **고객 검토 부분**. 전체 F-08 완료는 아니다.

## 1. 목적과 사용 순서

예를 들어 고객이 보고서 v1을 읽고 “운송 거리 근거를 적어 주세요”라고 말했을 때, 원문과 답변, 어느 보고서에 반영했는지 남긴다.

1. 프로젝트 상세의 **고객 검토** 탭에서 의견 대상 보고서 버전을 선택한다.
2. 고객 의견, 선택 고객 이름, 기록 담당자를 저장한다. 의견 번호 CMT-0001 등과 **열림** 상태로 보관한다.
3. 담당자 답변·이름·처리 방법을 저장한다. **답변됨** 상태가 된다.
4. 보고서를 수정한 경우 보고서 탭에서 새 버전을 저장하고, 고객 검토 탭에서 그 버전을 반영 보고서로 선택해 답변을 저장한다.
5. 처리 방법과 답변을 확인하고 종결 확인을 체크한 뒤 **의견 종결**을 누른다.
6. 추가 의견이 필요하면 담당자와 사유를 적고 **의견 다시 열기**를 누른다. 이전 답변·종결은 처리 이력에 남으며 새 답변을 저장한 뒤 다시 종결한다.

설명으로 해결한 경우에는 보고서를 새로 만들지 않고 처리 방법을 **설명으로 해결**로 저장하고 종결할 수 있다. 답변은 담당자가 적어 둔 기록이다. 고객에게 전송되거나 고객이 수락했다는 자동 증명은 아니다.

## 2. 상태·버전 규칙

| 동작 | 조건 | 결과 |
| --- | --- | --- |
| 의견 등록 | 실제 보관한 같은 프로젝트 보고서 선택, 의견·기록자 필수 | 열림 |
| 답변 저장 | 종결 전, 답변·담당자 필수 | 답변됨 |
| 보고서 수정으로 기록 | 의견 대상보다 나중에 보관한 같은 프로젝트 버전 선택 | 반영 보고서 번호 보관 |
| 종결 | 저장된 답변, 처리 방법 확정, 확인 체크 | 종결 |
| 다시 열기 | 종결 상태, 담당자·재개 사유 필수 | 열림, 현재 처리 방법 미정 |

- 처리 방법은 미정 / 보고서 수정 / 설명으로 해결이다. 미정으로 답변은 저장할 수 있으나 종결할 수 없다.
- 같은 버전이나 더 오래된 버전을 수정 반영으로 지정할 수 없다.
- 최초 고객 의견·대상 버전·제목·등록자는 수정하거나 삭제하는 기능이 없다. 잘못된 기록의 사정은 답변과 재개 이력에 적을 수 있다.
- 쓰기는 보고서 단계(7)에 한정한다. 후속 단계에서는 읽기만 제공한다. 7→8 자동·수동 이동은 이번에 추가하지 않았다.
- 현재 원자료·계산이 달라졌어도 유효하게 보관한 보고서에 대한 의견은 기록할 수 있다. 보고서 새 버전 저장의 기존 최신 근거 검사와 내보내기 보호는 유지한다.
- 이름은 직접 확인해 기록한 문자열이다. 로그인 신원이나 서버 감사 기록이 아니다.

## 3. 화면과 연결

- 상세에 **고객 검토** 탭을 추가한다. 전체·열림·답변됨·종결 건수를 표시한다.
- 처리 상태·의견 대상 보고서 필터를 조합한다. 등록 후에는 전체 조건으로 바꾸고 새 의견에 초점을 옮긴다.
- 의견 카드에서 원래 보고서와 현재 반영 보고서로 이동한다. 보고서 탭에서는 보관 버전을 선택해 연결된 의견으로 이동한다.
- 보고서 새 버전의 변경 기록에서 관련 의견을 최대 50건 선택한다. 기존 자유 메모는 보존한다.
- 선택한 의견의 번호·대상 버전·원문을 **그 보고서 저장 시점의 사본**으로 남긴다. 이 내용은 본문·Markdown·PDF·Word의 공통 보고서 섹션에 포함된다.
- 이후 의견을 답변·종결해도 이미 보관한 보고서 사본은 수정하지 않는다. 보고서 이력에는 현재 의견 상태를 별도 영역으로 표시한다.
- 보고서에 의견을 연결해 저장하는 일과, 그 보고서에 수정을 반영했다고 답변을 기록하는 일은 별개다. 보고서 저장만으로 답변·종결을 자동 처리하지 않는다.
- 기존 회사별 자료 상태 필터·수집 단계 하위 필터·보고서 작성 초안은 유지한다. 의견 입력·답변 초안은 같은 상세 내 탭 전환·필터·갱신에서 보존한다. 상세를 닫거나 새로고침하면 미저장 입력은 복원하지 않는다.

## 4. 저장 구조와 실패 보호

새 키 `ecoable-lca-manager.comments.v1`:

```text
{ version: 1, nextNumber, items: [
  { id, projectId, reportRevision, reportTitle, content, reviewer,
    events: [ { type, actor, at, ...처리별 기록 } ] }
] }
```

- created / replied / closed / reopened 이벤트를 순서대로 추가한다. 현재 상태·답변·반영 버전은 이력에서 구한다. 답변 수정도 이전 답변을 남긴다.
- 고객 의견 3,000자, 담당자·고객 이름 100자, 재개 사유 1,000자 제한. 고객 이름만 선택 사항이다.
- 저장할 때 최신 단계·보관 보고서·의견 리비전을 다시 읽는다. 예상 리비전과 다르면 저장을 중단하고 입력은 유지한다. 최신 답변 불러오기는 사용자가 눌러 미저장 입력을 초기화한다.
- Web Locks 지원 환경에서 같은 의견 저장 키의 쓰기를 직렬화한다. 미지원 환경은 예상 리비전 검사만 적용하므로 여러 탭의 완전한 원자성을 보장하지 않는다.
- JSON 형식·프로젝트·ID 중복·이벤트 순서·필수 입력·버전 관계 등을 읽을 때 검사한다. 손상된 기록을 빈 목록으로 덮어쓰지 않는다. 연결 보고서가 없거나 프로젝트 단계를 읽지 못하면 조회 가능한 의견은 유지하고 쓰기를 막는다.
- 저장 공간 부족·저장 시작 실패는 오류로 표시하고 기존 자료와 입력을 유지한다. 중복 클릭과 저장 중 다른 의견의 변경을 막는다.
- 기존 일곱 저장 키는 그대로 두고 의견 동작은 새 키만 쓴다. 보고서의 기존 내부 version:2 형식을 유지하며 change에 선택 필드 `commentIds`, `commentLinks`를 추가한다. 두 필드 없는 기존 보고서도 읽는다.
- 브라우저·주소별 저장이므로 다른 기기로 자동 이동하지 않는다. 전체 백업/복원·서버 저장은 별도 기능이다.

## 5. 확인 범위

- 변경한 JavaScript 구문 확인과 `git diff --check` 공백 확인을 수행했다.
- 별도 localhost의 기존 가상 프로젝트·v1 보관 보고서로 고객 검토 탭, 버전 선택·의견 등록 입력·건수·필터의 초기 화면 표시를 확인했다. 사용자 127.0.0.1의 입력 기록은 변경하지 않았다.
- 이번 작업에서 테스트는 추가하거나 실행하지 않았다. 의견 등록·답변·수정 버전 연결·종결·재개·새로고침 복원·오류·동시 쓰기의 실제 실행 확인은 남아 있다. 기존 WEB-020의 166개 결과를 이번 통과 수로 주장하지 않는다.
- PDF·Word의 새 의견 섹션은 기존 공통 섹션 생성 경로에 연결했으며 파일 생성·시각적 렌더를 이번에 재실행하지 않았다. 기존 문서 확인과 Word 렌더 제한은 WEB-023을 참고한다.

## 6. 이번 범위 밖

자료 질의·제3자 검증 지적 유형, 검토 라운드 자동 증가, 검증기관·차수별 보완, 고객 직접 입력 포털, 첨부 파일, 메일, 알림, 7→8 이후 이동은 후속으로 정한다. 내부 LCA 계산·AI는 기존 합의대로 기본 기능 구현 뒤에 검토한다.

## 7. 쉬운 설명

“v1 보고서에 받은 질문을 공책에 적고, 내가 뭐라고 답했는지와 v2 어디에 고쳤는지 함께 남기는 기능입니다. 고치지 않고 설명으로 해결할 수도 있습니다. 해결했다고 표시해도 예전 질문과 답변은 지워지지 않습니다.”
