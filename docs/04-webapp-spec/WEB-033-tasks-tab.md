# WEB-033 할 일 탭

작성일: 2026-10-18

## 1. 합의와 목적

사용자가 다음 기능 설명을 듣고 할 일 탭 구현을 승인했다. 프로젝트·자료·고객 의견·검증 기록에서 확인할 업무를 계산하며 별도 할 일을 입력하거나 저장하지 않는다. 앱의 주 메뉴에 할 일을 추가한다. 홈 대시보드 보강·백업은 이번에 진행하지 않는다.

## 2. 할 일 규칙

완료·사후관리 단계(10)는 제외하며, 날짜 기준은 기존 앱의 `LCA.rules.today()`를 따른다. 요청 하나는 아래 규칙 중 하나로만 표시한다. 삭제·승인 자료는 제외하고 9단계 이후 읽기 전용 원자료는 다시 할 일로 만들지 않는다.

| 유형 | 표시 기준 | 연결 |
| --- | --- | --- |
| 기한 초과 | 요청 상태이고 제출 기한이 오늘보다 전 | 자료 요청의 해당 카드 |
| 마감 임박 | 요청 상태이고 기한이 오늘~3일 후 | 자료 요청의 해당 카드 |
| 보완 요청 | 보완 요청 상태, 기한과 보완 사유 함께 표시 | 해당 자료 카드 |
| 자료 검토 | 제출됨 또는 검토 중 | 해당 자료 카드 |
| 고객 의견 | 열림 또는 답변됨. 답변됨은 종결 확인 안내 | 해당 고객 의견 |
| 검증 지적 | 종결되지 않은 차수별 지적, 기한과 보고서 버전 표시 | 해당 차수·지적 |
| 정보 확인 | 담당자·목표일 누락, 범위 단계 이후 필수 범위 누락/미확정, 수집 단계 이후 요청 0건 | 개요·범위 또는 자료 요청 |

- 제출됨·검토 중은 기한이 지나도 고객 미제출로 판정하지 않는다. 자료 검토로만 표시한다.
- 범위 정의 전에는 기준기간·기준량 등을 필수 누락으로 요구하지 않는다. 요청 0건은 범위 단계가 아닌 수집(3)부터 확인한다.
- 고객 담당자는 실제 저장 필드 `customerContactName`으로 확인한다. 예전 미연결 규칙의 `contactId`로 가상 누락을 만들지 않는다. 범위 검사는 현재 `scope.missing` 규칙을 사용한다.
- 고객 의견과 검증 지적은 원래 이벤트에서 현재 상태를 계산한다. 답변 저장만으로 사라지지 않으며 종결 기록이 있어야 제외한다.
- 고객 의견은 7단계 외, 검증 지적은 8단계 외이면 현재 읽기 전용임을 표시한다. 할 일에서 단계 제한을 해제하거나 자동 처리하지 않는다.
- 기본 순서는 기한 초과 → 보완 요청 → 마감 임박 → 자료 검토 → 검증 지적 → 고객 의견 → 정보 확인이다. 기한이 지난 검증 지적도 맨 앞 우선순위로 올린다. 같은 우선순위에서는 기한·프로젝트 번호·고정 ID로 정렬한다.
- 인증 만료·갱신, 수동 할 일, 메일 발송·알림·자동 완료는 이번 범위가 아니다. 0건은 전체 프로젝트 완료 판정이 아니다.

## 3. 화면과 이동

- 전체 및 일곱 유형별 건수·필터, 담당 연구원 선택, 회사·제품·번호·업무 검색, 조건 초기화, 최신 기록 확인 버튼을 제공한다. 건수는 전체 업무 기준이고 목록은 필터 조합 결과다.
- 목록에 회사 가상 표시·프로젝트 번호·제품·담당자·단계·기록 상태·관련 날짜를 표시한다. 긴 원문은 카드에서 일부만 표시하고 원래 화면에서 확인한다.
- 제목을 누르기 직전에 다시 읽어 이미 처리됐거나 계산에서 제외된 업무면 최신 목록을 안내한다.
- 업무를 열면 해당 상세 탭과 자료/의견/지적으로 이동한다. 요청이 기존 상세 상태 필터로 숨겨졌다면 해당 상세 필터만 전체로 바꿔 보여주며, 상단 수집 단계 필터는 바꾸지 않는다.
- 상세의 할 일로 버튼은 원래 검색·필터·스크롤을 유지한 목록으로 돌아간다. 사라진 업무는 제목에 초점을 둔다. 프로젝트 메뉴는 기존 목록·상세 동선을 유지한다.
- 기존 프로젝트에서 할 일 메뉴를 보고 프로젝트 메뉴로 돌아올 때 폼을 다시 만들지 않는다. 같은 프로젝트의 업무로 이동할 때도 기존 상세를 재사용한다. 다른 프로젝트를 새로 열면 기존의 상세 종료 정책을 따른다.
- 할 일이 보일 때만 60초 간격·화면 복귀·다른 탭 저장 변경으로 재계산한다. 내용이 같으면 목록을 다시 만들지 않는다. 필터와 검색 입력을 유지한다.

## 4. 저장과 실패 처리

- 새 저장 키·자료 변경·상태 변경은 없다. `tasks.build`는 조회 결과로 목록을 계산한다.
- 고객 의견 저장소에 읽기 전용 `snapshot()`을 추가해 현재 의견 목록만 반환한다. 검증은 기존 순수 `snapshot(id)`를 사용한다. 보고서/범위 조회의 순환 연결을 추가하지 않는다.
- 프로젝트/단계를 읽지 못하거나 다른 탭의 프로젝트 명단과 현재 명단이 다르면 계산을 중단하고 안내한다. 가상 기본값으로 누락 업무를 생성하지 않는다.
- 요청 또는 고객 의견 기록을 읽지 못하면 그 출처의 업무를 제외하고 경고한다. 부분 목록을 전체 정상 0건으로 설명하지 않는다. 검증 기록은 단계 확인에도 연결돼 있어 오류에 따라 전체 계산이 멈출 수 있다.
- 원래 기록에서 승인·종결하거나 정보를 채우면 다음 재계산에 반영한다. 할 일 목록만 따로 삭제/완료 처리하지 않는다.

## 5. 구현 위치

- `web/js/tasks.js`: 실제 저장 형식에 맞춘 조회 규칙·정렬.
- `web/js/views/tasks.js`: 목록·필터·검색·건수·경고·초점.
- `web/js/app.js`: 메뉴·상세 연결·복귀·날짜/저장 이벤트 갱신.
- `web/js/customer-review.js`: 읽기 전용 현재 의견 snapshot.
- `web/js/views/requests.js`, `web/js/views/verification.js`: 특정 기록으로 이동.
- `web/index.html`, `web/css/app.css`: 메뉴·화면·스타일.
- 기존 `rules.todayTasks`는 예전 미연결 데이터 구조용 함수로 남기며 이 화면에서 호출하지 않는다.

## 6. 확인과 제한

- JavaScript 구문·Git 공백 검사를 확인했다.
- 별도 localhost 탭에서 할 일 메뉴와 초기 화면, 실제 가상 저장 기록에서 계산된 정보 확인 4건, 유형별 건수·담당자 선택의 표시를 확인했다. 사용자 탭·브라우저 저장 기록은 변경하지 않았다.
- 테스트 추가·실행은 하지 않았다. 미제출/보완/검토·의견·지적의 모든 조합, 날짜 경계·정렬·검색·필터·상세 이동·복귀·입력 유지·읽기 실패·다른 탭 변경·작은 화면/키보드의 실제 실행 시험은 하지 않았다.
- 이전 저장·단계 전환 기능의 미확인 사항을 이번 작업으로 완료 처리하지 않는다.
