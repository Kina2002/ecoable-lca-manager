# WEB-046 받은 자료의 출처 기록

기준: 설계서 v02 F-04의 활동량 출처·계수 출처·획득 방법·2차 계수 데이터셋. 2026-10-19 사용자 요청으로 WEB-045 다음 **자료 출처 기록** 한 기능을 구현했다.

## 왜 만드는가

같은 `12,000 kWh`도 고객사 전력 고지서에서 읽은 값인지, 외부 통계의 평균값인지에 따라 설명이 달라진다. 또 이 활동량을 환경영향으로 바꿀 때 참고하는 **계수**의 출처도 따로 남겨야 나중에 계산 근거를 찾을 수 있다. 이 앱은 두 출처와 값을 얻은 방법을 기록한다. 계수 자체를 찾아 주거나 환경영향을 계산하지 않는다.

쉽게 말해 **활동량**은 “얼마나 썼나?”, **계수**는 “그 사용량의 환경영향을 계산할 때 어떤 기준값을 썼나?”다. **1차**는 해당 회사·제품에서 직접 측정·기록한 자료, **2차**는 외부 데이터베이스·문헌·통계 등에서 가져온 자료로 이 시연 앱에서 분류한다. 실제 분류는 적용 기준과 자료의 생성 경위를 확인해 담당자가 판단한다.

## 화면과 사용 흐름

1. 프로젝트 → 자료 요청 → 한 건의 **받은 자료 기록** 또는 **받은 자료 보기·수정**을 연다.
2. **자료 출처·획득 방법 기록**을 펼친다. 긴 입력창을 기본적으로 접어 화면 길이를 줄였다. 기존에 출처가 있는 기록을 다시 열면 펼쳐진 상태로 보인다.
3. 활동량 출처(1차/2차), 획득 방법(측정/계산/추정/가정), 필요하면 활동량 자료 이름·제공처를 적는다. 2차 활동량은 자료 이름·제공처가 필수다.
4. 수치 자료라면 계수 출처(1차/2차)를 별도로 고른다. 2차 계수일 때 DB 이름·데이터셋 이름·버전·기준연도(4자리)·제공처/출처를 적는다. 문서·설명 자료에는 계수 칸을 보이지 않는다.
5. 저장하면 받은 자료 요약에서 출처를 확인할 수 있다. 출처를 아직 모르면 비워 둔 채 자료를 기록하고 나중에 수정할 수 있다. 2차를 선택하고 필수 근거를 빠뜨린 경우에는 저장을 막는다.

값 `0`은 여전히 유효한 수치일 수 있으며 WEB-045의 ‘해당 없음’과 다르다. 출처를 입력하는 것만으로 자료가 자동 승인되지 않는다. 승인된 자료를 다시 저장해 출처를 바꾸면 이전 검토 체크·승인을 초기화하고 새 자료에 대해 다시 검토한다.

## 저장 형식과 이전 자료 보호

기존 `ecoable-lca-manager.requests.v1`의 받은 자료(`receipt`)에 선택적인 `provenance` 객체를 더한다. 출처를 전혀 기록하지 않은 기존 저장본에는 이 객체를 추가하지 않고 그대로 읽는다. 기존 백업 키와 파일 형식도 늘리지 않는다.

```json
{
  "provenance": {
    "activitySource": "1차",
    "activitySourceDetail": "가상 전력 고지서",
    "factorSource": "2차",
    "acquisitionMethod": "측정",
    "datasetDatabase": "가상 LCI DB",
    "datasetName": "전력 생산",
    "datasetVersion": "v1.0",
    "datasetYear": "2022",
    "datasetSource": "가상 발행기관"
  }
}
```

각 텍스트는 최대 200자이며 앞뒤 공백을 제거한다. 2차 계수일 때만 데이터셋 칸을 저장한다. 출처·방법의 알 수 없는 선택값이나 손상된 데이터셋은 저장본 읽기 실패로 처리하고 원문을 덮지 않는다. 이전 출처 없는 기록은 ‘미기록’으로 보여 주며 자동으로 1차/2차를 추정하지 않는다.

## 이후 단계에서 쓰는 방법

- 승인 자료 CSV에는 활동량·계수 출처, 획득 방법, 해당 데이터셋 정보를 **기존 열 뒤에 추가**한다. 출처 없는 과거 자료는 새 열이 빈칸이다.
- 계산 근거 사본에는 받은 자료의 출처도 함께 저장하므로 출처를 나중에 수정하면 현재 계산 근거가 바뀐 것으로 표시된다.
- 새 보고서의 승인 원자료 부분에는 기록된 출처를 표시한다. 출처 필드가 없던 옛 보고서의 출력 내용은 그대로 둔다.
- 데이터셋 이름을 직접 적는 기능이다. DB 실재 여부, 이용 조건, 숫자 계수값을 자동 확인하거나 가져오지 않는다. 계수 참고값 관리와 설정의 **자료 출처** 통합 화면은 별도 후속 기능이다.

## 확인

- 전체 자동검사 **228개 통과**. 기존 출처 없는 자료 읽기, 1차/2차 선택, 2차 활동량·계수 근거 누락 차단, 문서 자료와 1차 계수의 불필요한 데이터셋 제거, 재저장 후 재검토, 손상 기록 보호, CSV 열, 계산 결과 재읽기, 보고서 출처 표시를 확인했다.
- 변경 JavaScript 구문과 Git 공백을 검사했다.
- 실제 브라우저에서 입력창 펼치기·필드 표시·저장·수정·좁은 화면 배치를 직접 조작해 확인하는 일은 남아 있다. 이 작업 환경의 브라우저 제어는 이전 보안 정책 차단을 우회하지 않았다.

면접 설명 예시: “전력 고지서의 사용량과 그 사용량에 적용할 환경영향 계수는 출처가 다를 수 있어 별도로 기록했습니다. 2차 계수는 어느 DB의 어느 버전인지 적어야 하므로, 나중에 계산 근거와 보고서를 다시 확인할 수 있습니다. 기존 자료에는 출처를 임의로 채우지 않았고, 출처를 고쳐 저장하면 자료를 다시 검토하게 했습니다.”
