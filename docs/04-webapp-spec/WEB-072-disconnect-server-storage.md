# WEB-072 서버 저장 연결 해제

## 요청과 범위

2026-10-27 사용자는 데이터아카데미에서 배운 Supabase를 뜻했다고 정정했고, 로그인 구현이 복잡했던 경험을 설명한 뒤 ‘우선 지금 연결한 서버는 빼줘’라고 요청했다.

이번 변경은 WEB-071의 로그인·계정별 서버 저장을 해제하고 이전 브라우저 저장 방식으로 돌아가는 것이다. Supabase나 다른 인증/DB는 새로 연결하지 않는다. 롤플레이는 계속 보류한다.

## 변경 내용

- 로그인·계정 이름·서버 저장 상태·서버 백업 상단 영역과 `cloud.js` 연결을 제거한다.
- `storage.js`는 기존 `window.localStorage`를 직접 사용하는 방식으로 복귀한다.
- 앱 시작의 서버 조회·대기와 초기 `inert`를 제거한다. 업무 저장, 전체 복원 저널, 다른 창 보호 등 서버 도입 전 규칙을 유지한다.
- 서버에서 추가했던 TypeScript API·로그인 틀·D1 설정과 생성용 서버 폴더를 현재 Git 소스에서 제거한다. 구현은 Git 이력과 저장소 밖 보관 폴더에서 복구할 수 있다.
- 공개 Site는 같은 ID·주소·public 범위를 유지하며 `static.directory=dist`, `d1=null`, `r2=null`의 정적 배포로 전환한다. Worker와 업무 API를 배포물에 포함하지 않는다.
- README는 다시 브라우저 저장·백업 이동 안내로 맞춘다. WEB-071 SPEC은 과거 구현 기록으로 남기고 이 문서에서 해제 상태를 안내한다.

## 기록 보호

- 연결 해제 전 현재 계정 화면의 ‘이 기기 기록 내려받기’로 백업 파일을 내려받고 저장소 밖 보관 폴더에 복사했다. 실제 업무 JSON은 Git과 공개 배포에 추가하지 않는다.
- 원래 `ecoable-lca-manager.*` 실습 기록과 `lca-cloud-cache.v1.*` 임시 기록을 지우거나 서로 덮어쓰지 않는다. 브라우저 버전은 기존 실습 저장 키만 사용한다.
- 데이터베이스의 데이터를 영구 삭제하는 작업은 하지 않는다. 실행 중인 서버 저장 연결을 끊는 작업과 데이터 삭제를 구분한다.
- 기존 `handoff/latest-backup.json`, 실습 일지와 R08 메모는 수정하지 않는다. 사용자 업무 상태를 대신 진행시키지 않는다.

## 확인

- 복귀한 앱 파일은 WEB-071 전 버전과 대조한다.
- 활성 화면/스크립트의 서버 로그인·API 호출·서버 상태 영역 참조가 없는지 확인한다.
- 정적 배포물에 Worker 엔트리와 `cloud.js`가 없는지 확인한다.
- 배포 후 같은 주소에서 로그인 영역 제거·기존 프로젝트/담당 연구원 표시를 확인한다. 이미 열어 둔 옛 화면은 새로고침해야 한다.
- 전체 자동 테스트 묶음은 사용자 요청 원칙에 따라 실행하지 않는다. 실제 저장/복원을 대신 수행하지 않는다.
