# WEB-064 인증 상태와 확인 이력

기준: F-12, WEB-051 공식 만료일, WEB-053 갱신 이력. 제출 당시의 진행 상태와 현재 문서 기준 유효 상태를 구분한다.

## 사용할 곳

프로젝트 상세 → 인증·등록 상단의 **현재 인증 상태**. 확인 입력은 **상태 확인·취소·회복 기록**을 펼쳐 사용한다. 과거 확인 내용은 아래 **완료·제출 변경 이력**에서 펼친다. 입력·기록은 기존 공통 크기와 접기 방식을 사용한다.

## 표시 규칙

| 표시 | 기준 |
| --- | --- |
| 준비 | 제출 시작 전 또는 제출 준비 |
| 심사 중 | 제출 완료 / 보완 요청. 원래 진행 상태도 함께 표시 |
| 유효 | 승인된 인증·등록이며 기록한 공식 만료일 안이고 갱신 안내 시작 전 |
| 만료 임박 | 공식 만료일 기준 기존 갱신 안내 시작일부터 만료일까지. 6개월 전, UL EPD는 60일 전 |
| 만료 | 공식 만료일 다음 날부터. 만료 당일은 오늘까지로 표시 |
| 취소 | 대상 인증서에 문서·기관 근거로 취소를 직접 확인한 이력이 있음 |
| 확인 필요 | 공식 만료일 없음, 추가 확인 필요 기록, 미래 발급일, 반려 등 |
| 대상 아님 | 고객 제출. 인증 유효 상태를 적용하지 않음 |

유효·만료 표시는 **기록한 문서 기준**이며 기관에 실시간 조회한 결과가 아니다. 예상 만료일만 있을 때는 유효·만료로 단정하지 않는다. 기존 갱신 할 일의 예상일 안내는 유지한다. 반려와 만료를 취소로 바꾸지 않는다.

## 확인 이력 입력

- 승인된 인증·등록의 9·10단계에서 유효 / 취소 / 확인 필요 중 선택한다.
- 확인일, 확인 문서·기관 기록 이름(200자), 담당자(100자), 확인 내용·사유(1,000자), 직접 확인 체크를 요구한다. 원본 파일 업로드는 없다.
- 확인일은 발급일 및 같은 인증서의 직전 확인일 이후부터 오늘까지다. 같은 날 재확인도 사유와 새 이력으로 남길 수 있다.
- 유효 확인은 공식 만료일을 먼저 기록하고, 그 만료일 이내에 확인한 내용만 저장한다. 과거 유효 확인이 있어도 현재 날짜가 만료일을 지났다면 만료로 보인다.
- 취소는 별도의 확인 문구를 제공한다. 이후 확인 필요를 남기거나 만료일을 정정해도 취소는 유지한다. 문서로 유효 회복을 확인하거나 새 공식 인증서의 갱신 완료를 기록해야 해제된다.
- 새 갱신 인증서는 새 번호·발급일 기준으로 상태를 계산한다. 이전 인증서의 취소/확인 이력은 보존하며 새 인증서에 적용하지 않는다.

## 할 일과 단계

- 승인된 인증·등록의 상태가 확인 필요라면 홈과 할 일의 **인증 상태 확인**에서 바로 인증·등록으로 이동한다. 완료 프로젝트도 포함하고 연구원 필터를 따른다. 기한은 임의로 만들지 않는다.
- 취소된 인증서의 갱신 준비/요청·연간 점검 안내와 신규 점검 기록을 중단한다. 새 인증서가 공식 발급된 갱신 완료 또는 유효 회복 기록은 가능하다.
- 취소 상태로 새 프로젝트 완료 처리는 막는다. 이미 완료한 프로젝트는 10단계와 기존 완료 기록을 유지한다.
- 제출 진행의 승인·등록 이력, 과거 보고서·제출 사본·갱신/점검 이력을 덮어쓰거나 이전 단계로 되돌리지 않는다.

## 저장과 보호

기존 certification.v1의 events에 status-check를 추가한다. 당시 유형·기관·제도·번호·발급일·공식 만료일과 확인 내용/확인일/문서 이름/담당자/사유/저장 시각을 보관한다. 기존 상태 확인이 없는 저장본도 그대로 읽고, 조회만으로 저장하지 않는다.

기존 공통 Web Lock·최신 revision·복원 세대 보호를 재사용한다. 충돌 시 저장을 거부하고 작성 중 입력을 유지한다. 직접 최신 인증 기준 확인을 눌러 대상 번호·발급일을 다시 확인한 후 체크해야 저장한다. 탭 왕복/목록 갱신은 폼을 재생성하지 않는다. 프로젝트 변경·새로고침 전 미저장 글은 별도 보관해야 한다.

전체 JSON 백업은 기존 인증 키의 원문을 포함하고 validRecord로 새 확인 이벤트를 검사한다. 프로젝트 삭제는 해당 인증 기록 전체와 함께 제거한다. 새 저장 키/백업 형식은 만들지 않았다. 새 이벤트를 포함한 백업은 WEB-064 이상 코드로 읽는다.

## 확인 범위

- 변경 JavaScript 구문, diff 공백, 스크립트 연결을 확인했다. 자동 테스트는 추가·실행하지 않았다. 전체 자동검사 267개 통과는 WEB-061 당시 결과다.
- 별도 임시 탭에서 앱 시작과 인증·등록 탭의 초기 준비 상태/접힌 입력 배치를 확인했다. 해당 탭 오류 로그는 없었다. 사용자 원래 탭을 새로고침하거나 업무 기록을 생성/삭제/복원하지 않았다.
- 실제 확인 저장/취소/회복/갱신, 날짜 경계, 충돌·백업/삭제, 완료 프로젝트 할 일과 좁은 화면의 실행 확인은 남아 있다. 초기 준비 화면 확인을 전체 기능 시험으로 설명하지 않는다.
