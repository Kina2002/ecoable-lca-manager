# WEB-001 · 7개 가상 프로젝트 목록 조회

- 기준 설계: `docs/02-design/lca-webapp-design.md` v02, 3장·7-1장·9-3장
- 작성일: 2026-10-16
- 구현 범위: F-01 중 목록 조회. F-01 전체 완료를 뜻하지 않는다.
- 상태: 구현·아래 동작 확인 완료. 사용자와 화면을 함께 확인한 뒤 다음 기능을 정한다.

## 1. 왜 만드는가

연구원이 여러 고객사의 LCA 업무를 맡으면 '어느 회사의 어떤 제품이 지금 어디까지 왔는지' 한곳에서 볼 필요가 있다.
첫 화면에 프로젝트 명단을 모아 놓으면 각 업무의 목적과 진행 단계를 찾아볼 수 있다.

프로젝트는 '고객사가 맡긴 하나의 업무'다. 고객사는 같은 회사라도 제품이나 계약이 다르면 여러 프로젝트를 가질 수 있다.
이번 시연은 가상 고객사 7곳의 프로젝트 7개로 시작한다.

## 2. 사용 흐름

1. 웹앱 주소를 연다.
2. 상단의 기준 날짜와 전체 프로젝트 수 7을 확인한다.
3. 회사명, 제품·평가 범위, 업무 목적, 현재 단계, 목표 완료일을 읽는다.
4. 휴대폰에서는 같은 명단을 세로로 쌓인 카드 형태로 읽는다.

## 3. 화면과 데이터

| 표시 항목 | 데이터 | 의미 |
|---|---|---|
| 회사명·가상 표시 | `companyName`, `isFictional` | 시연을 위해 만든 회사임을 표시 |
| 프로젝트 번호 | `code` | 업무를 구분하는 번호. 번호의 2026은 샘플 식별자의 일부 |
| 제품·평가 범위 | `productName`, `functionalUnit`, `boundary`, `modules` | 어떤 제품을 얼마만큼, 어디까지 살펴보는지 |
| 업무 목적 | `purpose` | 고객사 요구 대응, 규제 대응, 제품 환경성 진단 |
| 현재 단계 | `stage` → `LCA.constants.STAGES` | 설계서의 10단계 중 현재 위치 |
| 목표 완료일 | `targetDate` | 시연용 목표 날짜 |

### 설계서 9-3장과의 대응

| 번호 | 회사(모두 가상) | 제품 | 현재 단계 | 기준일 대비 목표일 |
|---|---|---|---|---|
| LCA-2026-001 | 라온소재 | 양극재 전구체 | 데이터 수집 | +45일 |
| LCA-2026-002 | 솔뫼철강 | 코일 철근 | 제3자 검증 | +24일 |
| LCA-2026-003 | 다온케미칼 | 카본블랙 | 데이터 검토 | +35일 |
| LCA-2026-004 | 새봄리사이클 | rPET 재생 칩 | 결과 해석 | +14일 |
| LCA-2026-005 | 해든솔라 | 태양광 패널 | 범위 정의 | +75일 |
| LCA-2026-006 | 단단내화 | 내화물 | 완료·사후관리 | −14일 |
| LCA-2026-007 | 이음모빌리티 | 자동차 부품 | 계약·착수 | +100일 |

목적·동인·활용처·기능단위·시스템 경계는 설계서 9-3장의 내용을 따른다.
목표일의 간격은 이 기능에서 정한 시연용 값이며 실제 계약·인증 마감일이 아니다.
완료 프로젝트의 목표일은 과거지만, 이 화면은 지연 여부를 판단하거나 경고하지 않는다.

## 4. 동작 규칙

- 처음에는 7개 모두 표시하며 프로젝트 번호 순서로 보여준다.
- 회사마다 '가상' 표시를 붙인다. 회사 이름 자체도 가상이다.
- 앱을 여는 브라우저의 날짜를 기준일로 사용한다. 기준일은 상단에 표시한다.
- 페이지를 열 때 샘플을 새로 만든다. 목표일은 `LCA.rules.addDays()`로 계산한다.
- 단계는 번호를 기준으로 공통 목록에서 이름을 찾는다. 3/10 단계는 '일을 30% 끝냈다'는 뜻이 아니다.
- 이름이나 제품 등 데이터는 `textContent`로 넣는다. 문장이 HTML 명령으로 실행되지 않게 한다.
- 프로젝트가 0개면 빈 목록 안내를 표시하고 숫자도 0으로 바뀐다.
- 단계 번호를 찾을 수 없으면 '단계 확인 필요', 목표일이 없으면 '미정'으로 표시한다.
- 입력·변경 기능이 없는 조회 화면이므로 이번 기능은 localStorage에 저장하지 않는다.

## 5. 파일별 역할

| 파일 | 역할 | 쉬운 비유 |
|---|---|---|
| `web/index.html` | 화면의 제목·표·영역 배치, 스크립트 순서 | 빈 게시판 |
| `web/css/app.css` | 색·글자·간격, PC/휴대폰 배치 | 게시판의 모양 |
| `web/js/constants.js` | 공통 진행 단계 10개 등 | 단계 이름표 모음 |
| `web/js/rules.js` | 기존 날짜 계산을 재사용 | 달력 계산기 |
| `web/js/data.js` | 7개 샘플 프로젝트 생성 | 명단 |
| `web/js/views/project-list.js` | 받은 명단으로 표의 행 생성 | 명단을 게시판에 붙이는 사람 |
| `web/js/app.js` | 기준 날짜를 정하고 데이터와 화면 연결 | 시작 순서를 정하는 사람 |

기존 `constants.js`, `rules.js`의 인증·데이터 요청 관련 v02 변경은 해당 기능에서 별도로 반영한다.

## 6. 이번 기능의 경계

프로젝트 상세·등록·수정, 검색·필터, 브라우저 저장, 요청 항목, 메일, 검토 의견, 인증·사후관리, 실제 공개 데이터 연동은 다음에 각각 합의한다.
시연 포인트를 설명하는 나머지 데이터와 동작을 이 단계에서 완성했다고 표시하지 않는다.
동작하지 않는 상세 버튼·등록 버튼도 미리 표시하지 않는다.
현재는 밝은 화면만 구현했다. 어두운 화면은 향후 범위를 정한다.
배포는 제출 준비 단계에서 진행하며, 이번에는 로컬 미리보기와 GitHub 업로드로 확인한다.

## 7. 확인 결과

확인일: 2026-10-16. 실제 기기별 하드웨어 시험이 아니라 브라우저 뷰포트 크기를 바꿔 확인했다.

| 항목 | 방법 | 결과 |
|---|---|---|
| 로컬 실행 | Python 정적 서버로 `/` 응답 확인 | HTTP 200 |
| JavaScript 문법 | 새 JS 파일 3개에 `node --check` 실행 | 오류 없음 |
| 7개 샘플·가상 표시·단계 | 실제 브라우저의 행 수·가상 표시 수·접근성 트리와 설계서 9-3장 비교 | 각각 7개, 회사·제품·단계 일치 |
| 연말·윤년 날짜 | Node에서 실제 `rules.js`·`data.js`를 불러 2026-12-31·2028-02-20 기준으로 계산 | 월·연도 경계와 윤년 통과 |
| 샘플을 새로 만드는 동작 | 한 명단의 회사명·동인 배열을 바꾼 뒤 새 명단 생성 | 새 명단은 원래 내용 유지 |
| PC·태블릿·휴대폰 | 너비 1440·820·390·320px 설정, 화면·문서 너비와 표시 내용 확인 | 가로 넘침 없음, PC 표·휴대폰 카드 표시 |
| 키보드 본문 이동 | '본문으로 건너뛰기' 링크를 Enter로 실행 | `main-content`로 초점 이동 |
| 브라우저 오류 | 페이지 로드·크기 변경·메뉴 이동 후 콘솔 확인 | 오류·경고 없음 |
| 빈 목록·미정·알 수 없는 단계 | 관련 표시 분기 코드 검토 | 분기 구현 확인. 브라우저에서 해당 입력을 주입한 시험은 하지 않음 |

날짜·샘플 생성 확인은 7개 assertion(예상한 값과 같은지 비교하는 검사)으로 수행했다.
화면에 입력 기능이 없는 첫 조회 기능이므로 별도의 테스트 프레임워크나 설치 패키지는 추가하지 않았다.

## 8. 면접에서 설명하기

**Q. 왜 이 화면부터 만들었나요?**

A. 연구원이 관리하는 업무를 먼저 한눈에 보여주고, 이후 자료 요청·검토·메일 기능이 어떤 프로젝트에 연결되는지 이해하기 쉽게 만들었습니다.

**Q. 실제 고객사 데이터인가요?**

A. 회사와 프로젝트는 가상입니다. 제품 종류와 업무 목적은 조사 자료와 설계서에 맞췄고, 화면에도 가상임을 표시했습니다.

**Q. 왜 화면과 데이터를 파일로 나눴나요?**

A. 명단의 내용이 바뀌어도 표를 다시 만들지 않도록 했습니다. 나중에 공개 데이터를 활용할 때도 화면이 읽을 형식에 맞춰 데이터를 정리할 수 있습니다.

**Q. 3/10 단계는 진행률 30%인가요?**

A. 아닙니다. 10개 업무 단계 중 세 번째에 있다는 뜻입니다. 각 단계의 작업량이 다르므로 비율로 부르지 않았습니다.

**Q. 왜 목록에 저장 기능이 없나요?**

A. 이번 기능은 준비된 명단을 보여주기만 합니다. 입력과 수정 기능을 만들 때 브라우저 저장도 별도의 범위로 구현합니다.

## 9. 직접 확인할 것

라온소재의 제품·목적·현재 단계를 찾아 말해본다. 단단내화가 목록에 계속 표시되는 이유(완료 후 사후관리)를 생각해본다.
`data.js`에서 명단을 만들고 `project-list.js`에서 화면에 보여준다는 두 역할을 구분해본다.
