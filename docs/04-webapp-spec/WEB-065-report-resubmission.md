# WEB-065 제출 후 보고서 보완·재제출

## 합의한 흐름

제출한 프로젝트에서 보완 요청의 날짜·요청자·문서 이름·사유를 남기고 **보완 시작**한다. 같은 프로젝트의 보고서(7) 작업을 열어 자료/외부 계산 결과/해석을 필요한 만큼 수정하고 새 보고서 버전을 저장한다. 새 보고서의 내부 검토 또는 외부 검증을 거쳐 완료 근거를 다시 보관한 뒤 제출일·받는 기관·제출 문서 이름·실제 제출 확인으로 **재제출 기록**을 남긴다. 실제 메일 발송은 하지 않는다.

## 보존과 제한

- 제출 횟수, 보고서 버전, 검증 차수는 별개다. 제출 목록에서 어떤 보고서가 언제 어디로 제출됐는지 연결한다.
- 이전 제출/보고서/인증/프로젝트 완료 이벤트는 보존한다. 완료 프로젝트를 보완 시작하면 진행 중으로 다시 집계하되 이전 완료 사실을 이력에 남긴다.
- 9·10단계의 실제 제출 기록이 있는 프로젝트만 보완을 시작한다. 기본 완료 샘플처럼 제출 근거가 없으면 시작하지 않는다. 동시에 한 건의 보완만 연다.
- 임의 단계 선택은 제공하지 않는다. 보완 시작 이벤트가 보고서 작업을 여는 근거이며 새 보고서에 대한 검토를 저장하면 8단계로, 재제출을 저장하면 9단계로 이동한다.
- 새 보고서는 보완 시작 시점의 최신 버전보다 커야 한다. 외부 경로는 새 보고서를 연결한 새 검증 차수와 종결을 요구한다. 기존 검토 근거 재사용으로 재제출하지 않는다.
- 평가 범위·기본정보는 원래 제출 단계의 편집 제한을 유지한다. 보완 중 자료/계산/해석을 바꾸면 기존 보고서 근거 일치 검사를 그대로 거친다.
- 최신 인증 revision·보고서·검토 기준을 저장 전에 다시 확인하며 충돌 시 초안을 유지한다. 재제출하면 기존 9단계 읽기 전용 조건을 복구한다.
- 기존 certification.v1 이벤트와 11개 업무 저장 키를 유지한다. 백업은 제출 보고서 사본 연결과 이벤트를 검사하며 프로젝트 삭제는 해당 인증 이력과 함께 제거한다.
- 기존 발급 인증의 문서 기준 상태·갱신/점검 안내는 보완·재제출 진행과 구분해 조회한다. 보고서 보완만으로 이전 인증을 취소하지 않는다. 같은 인증 번호·발급일이면 기존 취소 확인도 유지한다. 보완 중 기존 인증 기록은 조회하며, 현재 제출의 승인 정보를 기록한 뒤 해당 인증의 후속 확인을 저장한다.

## 저장과 단계 복원

certification.v1에 amendment-started(이전 제출/진행/보고서 사본·이전 단계·보완 시작 당시 최신 보고서 번호·요청 근거)와 resubmitted(번호·제출일·기관·문서·검토한 보고서 사본) 이벤트를 추가한다. 기존 completed 이벤트는 이번 보완 구간의 새 완료 근거로 누적한다. 이전 finished 이벤트는 지우지 않고 현재 구간의 완료 여부만 따로 판정한다.

범위 저장소의 단계 값을 낮춰 덮어쓰지 않는다. 현재 구간이 열렸을 때만 명시적 단계 우선값을 적용한다. 보완 시작 시 7, 시작 당시 최신 보고서보다 큰 새 버전의 검토 근거가 생기면 8, resubmitted를 기록하면 9다. 앱 시작/다른 창/백업 검사에서 같은 조합 규칙을 사용한다. 새 외부 차수를 시작하기 전에는 과거 차수의 지적을 수정하지 못한다.

폼과 확인 체크, 기록 사유, 최신 revision/보고서 사본 비교 및 기존 공통 잠금을 사용한다. 다른 창의 기록 변경 시 입력을 유지하고 명시적으로 최신 기준을 다시 읽는다. 과거 보고서 보기 버튼은 기존 보관 버전/비교 기능을 연다. 제출 목록은 회차별로 접고 펼치며 같은 화면의 갱신 때 펼침을 유지한다. 미저장 입력은 프로젝트 변경·브라우저 새로고침 후 영구 복구되는 저장본이 아니다.

이전 앱의 제출 완료/보완 후 같은 보고서 재제출도 당시 완료 근거 보고서에 연결해 제출 횟수에 포함한다. 과거 기록에 없던 제출 파일 이름은 만들어 넣지 않고 이전 진행 기록 참조로 표시한다. 새 이벤트를 포함한 백업은 WEB-065 이상 코드로 읽는다.

## 확인 범위

- 변경/추가 JavaScript 13개 구문과 diff 공백·스크립트 연결을 확인했다. 자동 테스트는 추가·실행하지 않았다. WEB-061의 267개 통과는 이번 작업의 결과가 아니다.
- 별도 임시 탭에서 앱 시작→완료 샘플 상세→인증·등록의 보완/제출 목록 초기 안내와 접힘 배치를 확인했다. 해당 탭 오류 로그는 없었다. 실제 제출 기록이 없는 샘플을 조회했으며 보완을 시작하거나 사용자 원래 탭/업무 기록을 바꾸지 않았다.
- 실제 제출된 프로젝트의 보완 시작→자료 수정/재승인→계산/해석/새 보고서→내부·외부 재검토→완료 근거→재제출→재승인/재완료 및 반복 회차·다른 창·백업/삭제·모바일의 전체 실행 확인은 남아 있다. 초기 안내 화면 확인을 전체 동작 시험으로 설명하지 않는다.
