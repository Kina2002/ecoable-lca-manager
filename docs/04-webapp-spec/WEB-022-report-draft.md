# WEB-022 보고서 작성 시작과 초안 보관

## 1. 범위

2026-10-17 사용자는 결과 해석 구현을 확인하고 다음 기능 구현을 요청했다. 결과 해석 뒤의 보고서 단계 연결과 기존 기록을 모은 초안을 구현한다. 승인 원자료·외부 계산 결과·담당자 해석을 그대로 정리하며 자동 LCA 계산이나 AI 문장 생성은 하지 않는다.

이 기능은 보고서의 첫 초안 관리다. 고객 검토 의견·종결 조건, 제3자 검증, 인증, 7→8 이동, Word/PDF 양식, 증빙 파일 업로드는 포함하지 않는다. 적용 기준별 완전한 공식 보고서 템플릿이나 적합성 검사를 구현했다고 설명하지 않는다.

## 2. 별도 보고서 작성 시작 (6→7)

- 상세에 다섯 번째 **보고서** 탭을 추가한다.
- 결과 해석 단계(6)에서 현재 요청이 최소 한 건·전부 승인, 외부 계산 결과의 원자료·범위 일치, 저장된 해석 존재·계산 결과 일치가 필요하다.
- 조건이 맞으면 **보고서 작성 시작** 버튼을 활성화한다. 클릭 시 최신 범위·자료·계산·해석을 다시 읽어 6→7만 저장한다. 조건 충족과 해석 저장만으로 자동 이동하지 않는다.
- scope.v1에서 7단계를 읽고 복원한다. 기존 단계 1~6 기록과 원래 결과 해석 샘플을 유지한다. 단계 되돌리기나 건너뛰기는 추가하지 않는다.

## 3. 초안 저장과 본문

보고서 단계(7)에서 제목(필수 1~200자), 작성 메모(선택 최대 3,000자), 현재 자료·계산 결과·해석을 읽었다는 확인을 저장한다. 제목은 제품명에 ‘LCA 보고서 초안’을 붙인 기본값이다. 현재 승인·계산·해석 조건을 저장할 때 다시 검사한다.

저장된 초안 본문에는 다음을 담는다.

1. 프로젝트 번호, 가상 회사·제품, 업무 목적·유형, 고객 담당자·연구원 이름
2. 평가 기준량·경계·모듈·기준기간·적용 기준
3. 계산에 연결한 승인 요청의 번호·구분·내용, 원자료 값/단위/밀도 또는 문서 설명, 기간·증빙 이름·검토 메모
4. 외부 계산 도구·DB·평가 방법·할당 근거·계산일·파일 이름·메모·결과 지표와 계산 결과 버전
5. 담당자가 작성한 네 가지 해석과 해석 버전
6. 보고서 작성 메모

본문은 **가상 데이터 · 검토 전 초안**으로 표시한다. 현재 화면에서 펼쳐 읽거나 저장된 초안을 **글 파일(.md)**로 내려받는다. 파일명에 프로젝트 번호와 초안 버전을 포함한다. 숫자의 자릿수·지수 표기는 그대로 보존한다. 텍스트를 DOM에 넣을 때 textContent를 쓰며 내보낸 Markdown의 사용자 입력은 문법 문자를 이스케이프한다. 증빙·결과 파일은 이름만 포함하고 파일 내용은 첨부하지 않는다. 이 파일은 전체 브라우저 데이터의 복원용 백업이 아니다.

## 4. 근거 변경과 수정

- 초안에 프로젝트 정보와 당시 해석 전체 사본을 저장한다. 해석 사본에는 계산 결과와 그 계산에 연결한 승인 자료·평가 범위가 포함된다.
- 현재 자료·계산·해석 또는 보고서에 담은 프로젝트 정보가 달라지면 **자료 또는 해석 변경 · 보고서 초안 재확인 필요**를 표시한다. 단계·목표일 자체는 초안의 근거 변경으로 보지 않는다.
- 기존 본문과 작성 중인 제목·메모를 자동 덮어쓰지 않는다. 오래된 초안의 내려받기와 오래된 입력 기준으로 저장하는 것을 막는다.
- 최신 계산 결과에 맞게 해석을 저장한 뒤 **초안 기준 다시 확인**을 누른다. 제목·메모는 유지하고 확인 체크를 해제한다. 다시 읽고 확인하여 저장하면 새 초안 버전이 된다.
- 이 흐름을 위해 WEB-021의 해석 입력을 결과 해석(6)뿐 아니라 보고서(7)에서도 허용한다. 원자료 변경 시 외부 계산 결과 갱신→해석 갱신→초안 갱신 순서로 진행하며 프로젝트를 되돌리지 않는다. 8단계 이후의 해석·초안 편집은 지원하지 않는다.

## 5. 저장과 보호

새 키 `ecoable-lca-manager.report.v1`에 `{version:1, records:{프로젝트ID:초안}}` 형식으로 저장한다. 제목·메모·확인, 프로젝트 ID, 초안 버전, 근거 사본·비교 키, 생성/수정 시각을 포함한다. 프로젝트별 현재 초안 한 건이며 과거 버전 목록을 제공하지 않는다. 다른 화면의 초안 저장은 예상 버전 비교로, 자료·해석 변경은 근거 비교로 덮어쓰기를 막는다.

기존 여섯 저장 키와 기록을 보존한다. 단계 이동은 scope.v1만, 초안 저장은 report.v1만 쓴다. 저장본 형식·해석·계산·범위 기록 오류와 쓰기 실패는 기존 기록을 보존하고 작업을 막는다. 브라우저 입력이나 내려받은 보고서의 내용은 GitHub에 자동 올라가지 않는다.

## 6. 확인 범위와 남은 검증

- 변경 JavaScript 7개 파일의 구문 검사와 Git 공백 검사를 수행했다.
- 실제 사용자 미리보기에서 새 보고서 탭, 안내·제목·메모·저장/내려받기 영역이 표시되는 것을 확인했다. 자료가 없는 원래 결과 해석 샘플은 시작 버튼과 저장이 비활성으로 표시됐다. 사용자 저장 자료는 변경하지 않았다.
- 별도 localhost의 기존 가상 기록(계산 결과 버전 3·해석 버전 2)에서는 보고서 준비 완료와 시작 버튼 활성 표시를 확인했다. 단계 이동 버튼이나 저장·내려받기는 실행하지 않았다.
- 이번 요청에서 테스트는 추가·실행하지 않았다. 기존 166개는 WEB-020 당시의 통과 기록이며 이번 변경을 검증한 수치가 아니다.
- 실제 6→7 저장·새로고침 복원, 초안 저장·파일 내려받기, 근거 변경 후 차단·갱신, 다른 탭 충돌·저장 실패와 모바일 전용 크기는 아직 동작 검증하지 않았다. 해당 조건은 구현과 코드 검토 범위이며 실행 검증 완료로 주장하지 않는다.

## 7. 쉬운 설명

“앞에서 모은 자료·계산 결과·사람이 적은 해석을 한 문서에 모으는 기능입니다. 준비가 끝나면 버튼으로 보고서 단계에 들어가 초안을 저장합니다. 원자료나 해석을 바꾸면 보고서도 다시 확인하도록 알려줍니다. 현재는 초안이며 고객 의견 반영과 검증 절차는 다음 기능에서 연결합니다.”
