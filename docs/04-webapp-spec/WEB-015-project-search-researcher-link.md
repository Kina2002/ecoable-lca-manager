# WEB-015 프로젝트 담당자 표시·연구원 바로 가기·검색과 필터

## 1. 사용자 요청과 목적

사용자는 프로젝트 목록에서도 담당 연구원을 보고, 상세의 담당 연구원을 눌러 연구원 탭으로 이동하고, 첨부 이미지의 프로젝트 표 제목 옆 빈 공간에 검색·필터를 원했다.

프로젝트를 열기 전에 담당자를 알 수 있게 하고, 회사·제품·담당자·단계를 조합해 찾는 시간을 줄인다. F-09 프로젝트 현황표의 검색·필터 일부와 사용자 추가 동선이다. 다른 기한·메일·인증 기능을 이번에 추가하지 않는다.

## 2. 프로젝트 목록의 담당 연구원

- 기존 고객사·프로젝트 칸의 번호 아래 **담당 연구원: 이름 · RSR 번호**를 표시한다. 별도 열을 늘려 제품·목적 칸을 좁히지 않는다.
- ID 없는 예전 이름은 ‘기존 이름 기록’, 이름도 없으면 ‘미정’으로 표시한다.
- 목록의 범위 상태는 기존 사용자 정정대로 글자로 유지한다. 범위 바로 가기는 상세 안에서만 제공한다.

## 3. 상세에서 연구원 탭으로 이동

- 개요·범위의 담당 연구원 이름을 버튼으로 표시한다. 이름이 없으면 미정 글자로 남긴다.
- ID로 연결된 연구원은 해당 연구원 카드에 초점·스크롤을 옮기고 테두리로 강조한다. 다른 연구원 카드도 함께 남겨 전체 명단을 볼 수 있다.
- 이름만 있거나 현재 명단에서 ID를 확인할 수 없으면 **연구원 연결 확인** 카드로 이동한다. 같은 이름의 사람을 임의로 찾지 않는다.
- 저장소 읽기 실패나 연결이 바뀐 경우 오류 또는 연결 확인 안내를 보여주며 잘못된 카드로 이동하지 않는다.
- 프로젝트 메뉴로 돌아갈 때 상세의 입력·탭·스크롤은 기존 방식으로 유지한다. 목록으로 돌아갈 때 검색·조건과 단계 선택도 유지한다.

## 4. 검색·필터 배치와 규칙

요청 이미지의 빨간 영역인 **프로젝트 표 제목과 표시 건수 사이**에 다음을 배치한다. 좁은 화면에서는 같은 제목 영역 안에서 줄바꿈한다.

| 조작 | 규칙 |
|---|---|
| 프로젝트 검색 | 회사명·제품명·프로젝트 번호·담당 연구원 이름/번호에서 찾음 |
| 담당 연구원 | 프로젝트에 배정된 ID별 선택, 미정, 기존 이름 기록 |
| 업무 목적 | 전체 / 고객사 요구 대응 / 규제 대응 / 제품 환경성 진단 |
| 조건 초기화 | 위 세 조건만 초기화. 위쪽 단계 선택은 유지 |

- 검색은 입력 즉시 적용한다. 대소문자·전각/반각·공백과 번호의 하이픈 차이를 정리한다.
- 공백으로 나눈 검색어는 **모두** 맞아야 한다. 회사명과 제품명 등 서로 다른 칸에 나뉘어 있어도 된다. 예: ‘김하늘 전구체’.
- 단계·검색·연구원·목적은 **AND 조건**이다. 예: 데이터 수집 + 김하늘 + 고객사 요구 대응.
- 연구원은 ID로 구분한다. 동명이인이어도 번호가 다른 선택지다. 기존 이름 기록은 특정 연구원 선택에 자동 합산하지 않는다.
- 연구원 선택지는 전체 프로젝트의 배정 기록에서 구성한다. 명단에만 등록하고 아직 아무 프로젝트도 맡지 않은 사람은 선택지에 나오지 않는다.
- 선택 후 담당이 바뀌어 더 이상 배정 프로젝트가 없어져도 그 조건을 임의로 해제하지 않는다. 0건을 보여주고 조건을 바꾸거나 초기화할 수 있다.
- 결과가 없으면 조건에 맞는 프로젝트가 없다고 안내한다. 기호를 정규식으로 실행하지 않는다.
- 표시 건수는 현재 표의 결과 건수다. **위쪽 단계별 건수는 전체 명단 기준**으로 유지한다.
- 검색은 프로젝트 표에만 적용한다. 기존 수집 단계의 자료 상태 하위 필터와 회사별 자료 필터는 독립적으로 유지한다.
- 단계 버튼이나 전체 보기로 단계를 바꿔도 검색·연구원·목적은 유지한다. 조건 초기화는 단계를 유지한다.
- 새 프로젝트 등록 성공 때는 기존 등록 동작처럼 새 업무가 보이도록 검색·조건을 초기화하고 계약 단계로 이동한다.
- 조회 조건은 현재 화면 메모리에만 둔다. 새로고침하면 전체·빈 검색으로 시작한다. 프로젝트·범위·자료 저장본은 변경하지 않는다.

## 5. 사용자 확인 예시

1. 새로고침 후 각 프로젝트의 회사명 아래 담당 연구원이 표시되는지 확인한다.
2. 제목 옆 검색에 ‘전구체’를 입력해 라온소재만 표시되는지 확인한다.
3. 조건 초기화 후 위쪽 데이터 수집을 누르고 연구원 김하늘을 선택한다. 해당 조건의 프로젝트만 표에 남고 상단 단계별 숫자는 그대로인지 확인한다.
4. 다른 목적을 선택해 0건을 만들고 안내·조건 초기화를 확인한다. 초기화해도 데이터 수집 단계가 유지돼야 한다.
5. 프로젝트 상세에서 담당 연구원을 누른다. 해당 연구원 카드로 이동·강조되고 맡은 프로젝트가 보이는지 확인한다.
6. 프로젝트 메뉴로 돌아와 기존 상세 입력과 위치가 유지되는지 확인한다. 기존 이름 기록은 연결 확인으로 이동하는지 확인한다.

## 6. 검증과 한계

- `node --test web/tests/*.test.cjs`: **119개 통과**, 기존 110개와 새 검색·필터 검사 9개다.
- 빈/공백 조회, 기존 단계 조회와 일치, 여러 검색 필드·번호 표기 정규화, 복수 검색어, 네 조건 조합, 동명이인·기존 이름·미정 구분, 선택지 중복 제거, 빈 결과·기호 처리, 원본·전체 단계 건수 보존, 초기화 활성 조건을 확인했다.
- 변경 JavaScript 구문·HTML 정적 ID/레이블/ARIA/스크립트 경로·HTTP 200·공백 오류를 확인한다.
- 이전 브라우저 접근 차단을 우회하지 않았다. **실제 클릭·제목 영역 배치·모바일 줄바꿈·카드 이동/강조·초점·왕복 시 입력과 스크롤 유지는 미확인**이다. 사용자 화면 확인이 필요하다.

## 7. 파일과 면접 설명

- `project-filter.js`: 데이터만 받아 검색·ID·목적·단계를 조합한다. 저장하거나 원본을 바꾸지 않는다.
- `views/project-filter.js`: 입력·조건 초기화·배정 선택지를 관리한다.
- `project-list.js`: 담당 연구원과 결과 건수·빈 결과 안내를 표시한다.
- `project-detail.js`, `views/researchers.js`: 이름 버튼과 ID 기준 카드 이동을 연결한다.
- `app.js`: 단계 필터와 표 검색을 합치고 기존 화면 왕복을 연결한다.

면접 설명 예: ‘프로젝트 목록에서 담당자를 바로 보도록 했고, 단계·검색·담당자·목적을 모두 만족하는 업무만 찾게 했습니다. 단계별 전체 건수는 그대로 유지해 검색 결과 수와 전체 현황을 구분했습니다. 상세에서 연구원을 누르면 이름 문자열 대신 ID로 해당 담당자의 프로젝트를 찾아 보여줍니다.’
