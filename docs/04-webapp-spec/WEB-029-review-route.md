# WEB-029 미정·내부 검토·외부 검토 경로

- 작성일: 2026-10-18
- 승인: 사용자가 내부/외부 검토 분기를 “그럼 그렇게 해보자”로 승인하고, 이어 미정도 포함하도록 요청했다.
- 기존 WEB-027 외부 검증과 WEB-028 후속 제출 사이에 검토 방식을 연결하는 확장이다. 적용 기준·고객 요구에 따른 필요성을 자동 판정하지 않는다.

## 1. 선택과 화면

프로젝트 상세의 기존 **제3자 검증** 탭과 8단계 이름을 **검토·검증**으로 바꿨다.

| 저장한 방식 | 화면·경로 |
| --- | --- |
| 미정 | 기본값. 방식 결정·근거 기록만 제공하며 내부 완료·외부 시작·후속 제출을 막는다. |
| 내부 검토 | 내부 검토자·날짜·내용·확인 항목을 보관해 보고서를 확정한다. 외부 기관·검증자·차수·지적 화면은 숨긴다. |
| 외부 검토(제3자 검증) | 내부 확인 기록 후 기존 검증기관·검증자·차수·지적 화면으로 이어진다. |

- 방식과 기록 담당자·선택 근거/변경 사유를 저장한다. 미정의 근거만 선택 사항이다. 방식 저장만으로 단계가 바뀌지 않는다.
- 선택은 보고서(7)·검토·검증(8)에서 가능하다. 9단계 이후는 이전 근거를 유지하기 위해 읽기 전용이다.
- 화면에서 선택을 바꿔도 저장 전에는 기존 경로를 유지한다. 목적·제도 이름만으로 앱이 임의로 선택하지 않는다.
- 외부 검증을 아직 시작하지 않았다면 방식을 바꿀 수 있다. 기존 내부 기록과 당시 방식은 이력에 남는다.
- 외부 검증 차수가 실제로 생겼다면 내부나 미정으로 바꾸지 못한다. 미종결 지적을 건너뛰거나 기존 검증 기록을 숨겨 버리는 변경을 막는다. 진행 중 외부 검증을 철회하고 다른 경로로 재개하는 정책은 후속이다.

## 2. 공통 내부 검토와 보고서 확정

- 최신 유효 보고서가 필요하고 고객 의견이 모두 종결되어야 한다. 아직 미정이면 완료 저장을 막는다.
- 내부 검토자·검토일·검토 내용·기록 담당자를 적는다. 범위/자료 근거, 계산/해석, 보고서 내용/표기 세 항목과 최종 확인에 모두 체크한다.
- 검토자의 역할·독립성은 적용 기준과 고객 요구에 맞춰 사람이 확인한다. 이름이 같거나 다르다는 이유로 앱이 자격·독립성을 자동 판정하지 않는다.
- 내부 검토자·기록자는 각 100자, 검토 내용 3,000자, 방식 근거 1,000자 제한이다. 날짜는 연월일 8자리 또는 YYYY-MM-DD로 입력한다.
- 완료 시 당시 보고서 전체 사본과 검토 내용을 보관한다. 처음 7단계에서 완료 저장하면 같은 저장으로 8단계 진입 근거가 생긴다. 외부 방식을 택했다면 내부 확인 완료 후 8단계에서 외부 1차를 시작한다.
- 내부 경로는 외부 검증 기록을 생성하지 않고 보고서를 확정할 수 있다. 외부 경로는 새 프로젝트 기준으로 현재 보고서의 내부 확인을 마쳐야 차수를 시작할 수 있다.
- 보고서·자료·계산·해석이 달라지면 현재 근거에 맞는 새 보고서를 먼저 보관하고 내부 검토를 다시 기록한다. 이전 보고서·확인 기록은 덮어쓰지 않는다.
- 검토 완료는 특정 보고서 버전에 대한 확인이다. 8단계에서는 보완 보고서를 새 버전으로 만들 수 있고, 그 버전은 다시 검토해야 한다.

## 3. 후속 제출과 연결

- WEB-028 인증·등록 탭은 이제 **검토·검증 완료**를 보관한다. 내부 경로는 내부 완료 기록을, 외부 경로는 내부 확인과 외부 지적 종결·검증 완료를 근거로 사용한다.
- 내부 경로의 완료 사본에는 외부 검증 대신 `reviewMethod: internal`과 내부 검토/방식 이력 사본을 넣는다. 외부 경로는 `external`과 기존 검증 사본도 함께 넣는다.
- 현재 방식·보고서·내부 검토/외부 기록이 달라지면 후속 제출 시작을 막고 완료 근거를 새로 남기게 한다.
- 9단계 시작은 기존대로 별도 버튼이며, 시작 후에는 이전 단계 쓰기를 막는다. 제출 유형은 인증/등록/고객 제출을 사람이 정한다. 내부 검토만으로 어떤 제도의 외부 검증 요구를 충족한다고 판정하지 않는다.
- 내부 경로에서 인증이나 제출이 필요하지 않은 경우에는 보고서를 확정한 상태로 남길 수 있다. 자동 9→10이나 별도 납품 완료 경로는 이번에 추가하지 않았다.

## 4. 저장과 기존 기록 호환

새 키 `ecoable-lca-manager.review-route.v1`:

```text
{ version: 1, records: { projectId: { revision, events: [
  selected: { method, actor, reason, at },
  reviewed: { method, reviewer, reviewedOn, note, checks, confirmed, report, actor, at }
] } } }
```

- 방식 선택과 내부 완료를 이벤트로 추가한다. 전체 리비전은 이벤트 수다. JSON·프로젝트·방법·날짜·시간 순서·필수 입력·보고서 사본·확인 항목을 검증한다.
- 첫 reviewed 이벤트의 단일 setItem이 내부 경로의 8단계 진입 근거다. 저장 실패 시 단계만 먼저 바뀌지 않는다. scope.load/currentStage는 내부/외부/후속 제출의 저장된 유효 단계 중 가장 높은 단계를 복원한다.
- WEB-028까지의 기존 열 저장 키는 유지한다. verification에 읽기 전용 snapshot API를 추가해 방식 조회와 단계 복원에서 순환 조회가 생기지 않게 한다.
- 기존 외부 차수가 있고 새 방식 기록이 없는 프로젝트는 **외부 검토로 연결 표시**한다. 읽기만으로 기존 데이터를 쓰거나 내부 검토 기록을 만들어내지 않는다. 이 프로젝트의 기존 외부 경로·완료 사본은 그대로 읽는다.
- 기존 외부 기록 프로젝트에서 내부 확인을 새로 저장하면, 같은 저장에 기존 외부 기록을 근거로 한 방식 연결과 실제 입력한 내부 검토를 함께 남긴다. 이후에는 새 내부 검토의 최신성 검사를 적용한다.
- 기존 certification.v1의 외부 완료 사본도 읽는다. 새 완료에는 선택 필드 `reviewMethod`, `reviewRoute`를 더하고 내부 경로에서 `verification: null`을 허용한다. 과거 외부 완료의 기관·차수 사본은 보존한다.
- 보고서/고객 의견/검증/후속 제출과 같은 Web Lock을 사용한다. 저장 시 현재 단계·방식·리비전·최신 보고서를 다시 확인한다. Web Locks 미지원의 완전한 동시 쓰기 원자성은 보장하지 않는다.
- 예상 리비전·보고서가 달라지면 입력을 유지하고 저장을 막는다. **검토 기준 다시 확인**은 입력을 유지하며 기준을 바꾸고 확인 체크를 해제한다.
- 저장 공간 오류·손상 기록·중복 클릭을 처리한다. 탭 전환에서 작성 입력을 유지하며, 새로고침/상세 닫기 후의 미저장 초안 복원은 지원하지 않는다.
- 기존 자료 필터 두 위치, 보고서 버전·계산·해석·고객 의견·외부 지적 기록과 브라우저 입력은 유지한다.

## 5. 확인 범위

- 변경한 JavaScript 구문과 Git 공백을 확인했다.
- 별도 localhost의 기존 보고서가 있는 가상 프로젝트에서 **검토·검증** 탭·8단계 이름, 미정 기본값, 미정/내부/외부 세 선택지, 미정일 때 내부·외부 기록 영역을 숨기는 초기 화면을 확인했다. 사용자 127.0.0.1의 입력 기록은 변경하지 않았다.
- 이번에는 테스트를 추가하거나 실행하지 않았다. 실제 방식 저장·내부 검토 저장·8단계 복원·외부 시작·보고서 변경 후 재확인·내부 경로의 후속 제출·기존 사본 호환·동시 쓰기 실행 확인은 남아 있다. 기존 테스트 결과를 이번 통과 수로 주장하지 않는다.
- PDF·Word 생성과 기존 흐름의 회귀 실행은 이번에 하지 않았다.

## 6. 후속 범위

진행 중 외부 검증 철회/경로 재개, 이전 차수 지적 추가, 내부 지적 항목별 보완 관리, 표준·제도별 의무 판정, 검토자 자격·권한, 검토/검증 생략 후 납품 완료, 9→10·사후관리·AI·내부 계산은 별도 합의한다.
