# WEB-020 승인 자료 내보내기와 외부 계산 결과 등록

## 1. 사용자 합의

2026-10-17 사용자는 앱 내부 LCA 계산을 AI 연결처럼 기획한 기본 기능 구현 이후에 검토하기로 했다. 이번에는 계산 단계의 승인 자료 정리·CSV 내보내기와 외부 도구에서 계산한 결과·산정 근거 기록을 구현한다. 내부 환경영향 계산 엔진과 5→6 단계 이동은 이번 범위에 포함하지 않는다.

## 2. 계산 자료·결과 탭

프로젝트 상세의 개요·범위, 자료 요청 다음에 **계산 자료·결과** 탭을 추가했다. 세 탭은 방향키·Home·End로 이동하며 기존 자료 상태 필터와 입력 초안을 유지한다.

### 승인 원자료 CSV

- 현재 프로젝트의 삭제하지 않은 승인 요청만 포함한다. 다른 프로젝트와 미승인 자료는 제외하며 승인/전체·제외 건수를 표시한다.
- 승인 자료가 한 건 이상이면 단계와 관계없이 내보낼 수 있다. 승인 0건·저장소 오류는 버튼을 막고 클릭 시 최신 기록을 다시 읽는다.
- 요청 번호·구분·내용·제출 기한, 받은 값·단위·밀도 또는 문서 설명, 자료 기간·증빙 파일 이름, 승인 메모·시각과 내보내기 시각을 포함한다.
- 가상 데이터임을 명시하고 프로젝트·제품·평가 기준량·경계·모듈·기준기간·적용 기준을 함께 적는다.
- UTF-8 BOM, CRLF, 따옴표/쉼표/줄바꿈 이스케이프와 수식으로 해석될 수 있는 텍스트 방어를 적용한다. 파일명은 `가상_승인자료_프로젝트번호.csv`다.
- 원래 기록한 활동량을 보존한다. 연간 전력량 등을 제품 기준량당 값으로 자동 환산하지 않는다. 특정 LCA 도구의 바로 가져오기 형식이 아니며 담당자가 도구의 입력 항목과 기준에 맞춰 사용한다.

### 외부 계산 결과 입력

- 계산 도구·버전, 배경 DB·버전, 평가 방법·버전, 외부 계산일, 할당 방법·적용 근거, 결과 파일 이름이 필수다. 계산 메모는 선택이다.
- 지표 이름·결과값·단위를 1~20개 기록한다. 중복 지표 이름은 거절한다. 값은 음수·0·소수·지수 표기를 허용하고 유효한 유한수인지 확인한다. 원래 문자열을 보관해 `1.2300`, `-1.2e-3` 같은 표기를 유지한다.
- 프로젝트의 평가 기준량·범위와 같은 기준으로 계산했다는 확인이 필요하다. 단위/방법의 과학적 적합성을 자동 판정하지 않는다.
- 단계 5 이상이며 현재 요청이 최소 한 건이고 모두 승인돼야 저장한다. 버튼을 누를 때 최신 단계·자료·범위를 다시 확인한다.
- 파일은 이름만 기록한다. 파일 내용 업로드, DB/API 연결, 실제 외부 도구 실행은 하지 않는다.

## 3. 저장 근거와 변경 안내

결과와 함께 당시 제품·평가 기준량·경계·기간·적용 기준과 승인 요청·받은 자료·검토 기록의 사본을 저장한다. 저장 화면에서 결과 표, 계산일, 저장 버전·시각, 당시 범위와 승인 자료를 다시 볼 수 있다.

현재 자료와 저장 당시 근거가 달라지면 **근거 자료 변경 · 재계산 결과 확인 필요**를 표시한다. 받은 자료 재기록·재승인, 요청 추가/삭제, 범위 변화가 대상이며 단계·일정만 바뀐 것은 계산 근거 변경으로 보지 않는다. 기존 결과를 자동 삭제하거나 최신 자료를 기준으로 자동 재계산하지 않는다.

입력 중 근거가 바뀌면 초안을 유지하고 이전 기준으로 저장하는 것을 막는다. 담당자가 외부 계산을 다시 확인한 뒤 **입력 기준 다시 확인**을 누르면 최신 근거로 바뀌며 기준 확인 체크를 해제한다. 입력값은 유지하되 같은 기준인지 다시 확인해야 저장할 수 있다. 외부 계산의 정확성은 이 체크만으로 검증되지 않는다.

## 4. 저장과 호환

- 새 키 `ecoable-lca-manager.modelling.v1`에 프로젝트별 현재 결과 한 건을 보관한다. 다른 네 저장 키를 변경하지 않는다.
- 수정 시 버전 번호를 증가시키고 최초 생성 시각은 유지한다. 이전 결과 이력을 여러 버전으로 조회하는 기능은 아니다.
- 다른 탭이 결과를 먼저 바꾸면 버전 충돌로 덮어쓰기를 막는다. 자료/범위 변경도 서명 비교로 거절한다.
- 손상된 결과·근거·요청·범위와 브라우저 쓰기 실패를 성공으로 처리하지 않는다. 기존 기록을 지우거나 새 저장본으로 자동 덮어쓰지 않는다.
- 결과 저장은 프로젝트 단계, 승인 상태, 일정, 기존 필터를 바꾸지 않는다. 브라우저 입력 결과는 GitHub나 다른 컴퓨터로 자동 이동하지 않는다.

## 5. 확인 결과

- 자동 검사 **166개 통과**(기존 156개 + 계산 자료/결과 10개). CSV 포함/제외·원자료 보존·문자 이스케이프, 수치 표기·필수 입력·중복·개수 제한, 단계/승인 조건, 저장/복원·프로젝트 분리·다른 저장 키 보존, 버전 충돌, 근거 변경, 쓰기 실패·손상 검사를 포함한다.
- JavaScript 구문과 Git 공백 오류를 확인했다.
- 실제 사용자 미리보기에서 승인 0건의 CSV 비활성화와 검토 단계의 결과 입력 비활성화를 확인했다.
- 별도 `localhost:5180` 저장 공간에서 가상 승인 자료 1건을 CSV로 내려받아 헤더와 값·단위·기간·증빙 이름을 확인했다.
- 실제 화면에서 두 지표(`1.2300`, `-1.2e-3`)와 산정 근거 저장→새로고침 복원→받은 전력량 변경→승인 초기화/내보내기·저장 차단/기존 결과 변경 경고→재승인→입력 기준 갱신→수정 결과 `1.3300` 저장 버전 2→새로고침 복원을 확인했다.
- 계산 당시 승인 자료 펼치기와 현재 근거 일치 안내를 확인했고 브라우저 오류는 없었다. 사용자 미리보기의 원래 입력 기록은 변경하지 않았다. 실제 고객 자료·배경 DB·외부 계산 도구는 사용하지 않았다. 모든 작은 화면·키보드·달력 조합을 확인한 것은 아니다.

## 6. 설명 예시

“검토를 통과한 원자료를 CSV로 정리해 계산 담당자에게 넘기고, 외부 LCA 도구에서 나온 지표와 계산 도구·DB·평가 방법·할당 근거를 기록합니다. 결과가 어떤 승인 자료와 평가 범위를 기준으로 했는지 함께 보관해 자료가 바뀌면 재계산 확인이 필요하다고 알려줍니다. 내부 계산 엔진은 기본 기능을 완성한 뒤 별도로 확장할 예정입니다.”
