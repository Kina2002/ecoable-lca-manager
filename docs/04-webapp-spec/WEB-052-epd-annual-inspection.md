# WEB-052 International EPD 연간 점검

기준: 설계서 v02 F-06·F-12. 사용자는 기획한 기능의 순차 연속 구현을 승인했다.

## 왜 만드는가

프로젝트가 완료돼도 EPD에 적힌 정보가 계속 맞는지 확인해야 한다. 발급일과 최신 버전일이 다를 수 있으므로, 문서의 버전·버전일을 별도로 기록하고 연간 점검을 관리한다.

## 동작

승인된 International EPD 등록의 인증·등록 탭에서 다음 두 가지를 입력한다. 완료·사후관리 10단계에서도 기록할 수 있다.

1. 최신 EPD 버전, 버전일, 확인 문서 이름, 기록자, 확인 근거. 이를 기록하지 않았다면 홈·할 일에 ‘점검 기준일 확인’을 표시한다.
2. 점검 대상일별 점검일, 점검 중/점검 완료, 확인 문서 이름, 담당자, 확인 결과와 필요한 조치. 점검 완료는 별도 확인 체크를 요구한다.

버전일의 매년 기념일을 점검 예정일로 계산한다. 2월 29일은 평년에는 2월 말일로 맞춘다. 문서의 공식 만료일(없으면 예상 만료일) 이전의 점검만 만든다. 예정일 30일 전부터 홈·할 일에 보이며, 점검 중에는 계속 남는다. 완료 기록을 남기면 다음 미완료 연도로 이동한다. 빠뜨린 과거 점검을 자동 완료하거나 건너뛰지 않는다. 다른 연도를 먼저 기록하더라도 가장 이른 미완료 연도는 유지한다.

점검일은 대상일 30일 전부터 오늘까지 허용한다. 기존 완료 기록도 대상일을 골라 정정할 수 있으며 이전 결과는 이력에 남는다. 새 버전·버전일을 기록하면 그 버전의 점검 주기를 사용하고 이전 버전의 기록은 이력으로 보존한다. 점검 기준 변경은 공식 EPD 갱신·기관 재승인 처리와 같지 않다.

## 근거

[EPD International의 연간 내부 사후점검 안내](https://www.environdec.com/news/epd-internal-follow-up)는 최신 버전일을 기준으로 적어도 매년 점검하고 필요한 변경을 기록하도록 설명한다. 30일 전 안내는 설계서의 내부 업무 관리 시점이다. 점검 결과에 따라 업데이트·재검증이 필요할 수 있으므로 결과와 조치를 사람이 적고 확인한다. 앱이 10% 변화나 공식 승인 여부를 자동 판정하지 않는다.

## 저장·보호

`certification.v1`에 `inspection-plan`, `inspection` 이벤트를 추가한다. 기존 백업 키와 기록 형식을 유지한다. 이력은 인증 유형·제도·발급일·번호에 연결하고 점검은 EPD 버전·버전일에 추가로 연결한다. 다른 화면에서 저장된 수정 차수를 재검사한다. 계획·점검의 작성 중 입력을 각각 보호하며 최신 기준 확인 시 완료 체크를 해제한다. 손상 기록은 자동 복구하거나 덮어쓰지 않는다.

## 검증·범위

30일 경계·윤년·만료일 경계, 과거 미완료 연도 보존, 점검 중/완료 후 다음 연도 이동, 완료 프로젝트의 홈·할 일 포함, 기준일 누락 안내, 다른 버전·미래 점검·존재하지 않는 차례 거절을 검사했다. 전체 자동검사 **243개**, JavaScript 구문, Git 공백, 미리보기 정적 파일 HTTP 200을 확인했다. 실제 브라우저 클릭·입력·좁은 화면 조작은 미확인이다. 수정 EPD의 기관 제출·재검증·자동 파일 분석은 포함하지 않는다.

면접 설명: “EPD는 받은 뒤에도 정보가 맞는지 매년 확인해야 합니다. 문서의 최신 버전일을 기준으로 점검 일정을 만들고, 30일 전부터 할 일에 보여 줍니다. 담당자가 점검 결과를 완료로 기록해야 다음 연도 점검으로 넘어가므로 놓친 점검이 저절로 사라지지 않습니다.”
