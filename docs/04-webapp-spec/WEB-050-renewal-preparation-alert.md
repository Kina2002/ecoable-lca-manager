# WEB-050 인증 갱신 준비 안내

기준: 사용자가 WEB-049 예상 만료일 계산을 확인한 뒤 다음 기능으로 제안한 갱신 준비 알림 구현을 승인했다. 설계서 v02 F-06·F-12의 6개월 전 안내와 UL EPD 60일 전 안내를 시연용 관리 규칙으로 적용한다.

## 왜 만드는가

예상 만료일을 인증 화면 안에서만 보면 완료된 프로젝트를 다시 열지 않는 한 놓치기 쉽다. 날짜가 가까워지면 ‘할 일’과 홈의 우선 할 일에 보여 담당자가 발급 문서의 **실제 유효일**과 갱신 필요 여부를 확인하게 한다. 이 화면의 ‘갱신 준비’는 내부 관리 안내이지 인증기관의 공식 갱신 기한이나 법적 만료 판정이 아니다.

## 언제 보이나

- `WEB-049`에서 예상일을 계산할 수 있는 **승인·등록** 건만 대상이다. 환경성적표지·저탄소제품·International EPD·EPD Norway는 예상 만료일 **달력상 6개월 전**, UL EPD는 **60일 전**부터 보인다.
- 월말은 해당 달에 같은 일이 없으면 마지막 날로 맞춘다. 예: 예상 만료일 2029-08-31의 6개월 전은 2029-02-28이다.
- 시작일 전에는 인증 화면에 안내 시작 예정일을 표시하고 할 일은 만들지 않는다. 시작일부터는 ‘갱신 준비’, UL은 ‘갱신 요청 확인’을 보인다. 예상일을 지나도 자동으로 ‘실제 만료’로 단정하지 않고 ‘예상 만료일 경과·실제 유효기간 확인’을 남긴다.
- 고객 제출, 준비·제출·보완·반려 상태, 알 수 없는 제도, 유형과 제도가 맞지 않는 기록은 제외한다. 완료·사후관리(10단계) 프로젝트도 갱신 확인 대상이다.

## 어디서 보이나

인증·등록 탭의 예상 만료일 안내, ‘할 일’의 **갱신 확인** 필터, 홈의 ‘먼저 처리할 일’과 ‘확인 필요 프로젝트’에 연결한다. 할 일 제목을 누르면 해당 프로젝트의 인증·등록 탭으로 간다. 완료 프로젝트의 과거 인증 기록은 읽기 전용이다. 홈의 진행 프로젝트 수·자료 비율은 완료 프로젝트를 계속 제외하며, 갱신 확인 건수에는 완료 프로젝트를 포함한다고 설명한다.

## 데이터·한계

기존 `certification.v1`을 읽고 현재 날짜에 맞춰 할 일을 다시 계산한다. 새 저장 키, 인증 이력 변경, 프로젝트 단계 변경은 없다. 인증 기록을 읽지 못하면 갱신 확인을 0건 성공으로 속이지 않고 경고를 표시한다. 현재는 **실제 만료일 입력, 갱신 완료 처리, 알림 해제, 매년 점검, 메일·시스템 푸시 알림**을 구현하지 않는다. 따라서 예상 만료일을 지난 안내는 기록이 정정되거나 후속 갱신 처리 기능이 만들어질 때까지 남는다.

## 근거와 검증

6개월은 설계서 v02의 시연용 내부 관리 시점이다. UL의 60일은 [2018년 UL EPD 서비스 약관](https://japan.ul.com/wp-content/uploads/sites/27/2018/12/0_Terms_EPD_12_06_2018.pdf)의 사전 서면 통지 조항에서 확인했으나, 실제 업무에는 현행 계약과 기관 안내를 다시 확인해야 한다. [EPD International](https://api.environdec.com/api/v1/epdlibrary/files/8168b86f-ab27-4bd3-16f7-08dbca69748b/data)의 공개 EPD에서도 게시일 단순 계산과 표시된 유효일이 다를 수 있으므로 이 앱은 **예상일 기준**이라고 표시한다.

자동검사는 6개월·60일 경계, 월말, 예상일 경과, 완료 프로젝트의 할 일·홈 포함, 고객 제출 제외와 읽기 실패 경고를 확인했다. 전체 236개 검사, 변경 JavaScript 구문, 정적 자산 HTTP 200, Git 공백 검사도 통과했다. 실제 사용자 브라우저의 클릭·좁은 화면 조작은 별도 확인이 필요하다.

면접 설명: “프로젝트가 완료돼도 인증 유효기간 관리가 끝나는 것은 아닙니다. 예상 만료일을 기준으로 갱신 확인 시점이 오면 할 일에 다시 보이게 했습니다. 단, 발급 문서의 실제 만료일과 현재 갱신 조건을 담당자가 확인해야 하므로 앱은 ‘갱신 완료’나 ‘공식 만료’라고 자동 판정하지 않습니다.”
