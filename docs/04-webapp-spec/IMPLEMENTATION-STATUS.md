WEB-038은 최종 확인 후 프로젝트 완료(9→10)와 생성 프로젝트 영구 삭제·재확인 창이다. F-01의 단계 연결과 삭제를 늘렸으며 일반 정보 수정·추가 범위항목 등은 남아 부분 상태와 거친 점수는 유지한다. F-12 만료·갱신은 구현하지 않았다. 구문·공백·정적 연결만 확인했고 실제 완료/삭제/복구/화면 시험과 테스트 추가·실행은 하지 않았다.

WEB-033으로 할 일 탭을 추가했다. 실제 자료·의견·지적·범위 기록으로 업무를 계산하며 F-06을 미구현에서 부분으로 바꿨다. 만료·갱신 알림은 남아 있다. 별도 localhost의 초기 4건 표시와 구문·공백만 확인했고 테스트 추가·실행과 전체 분류/이동/실패 시험은 하지 않았다.

WEB-032는 일괄·개별 요청 입력의 접기·펼치기 배치 개선이다. 기능군 점수는 변하지 않는다. 두 영역은 기본 접힘이며 입력을 지우지 않는다. 구문·공백·초기 배치만 확인했고 입력 유지·저장 시험은 하지 않았다.

WEB-031로 자료 요청 일괄 생성의 화면·저장을 연결했다. F-03의 복수 구분 선택·기본 문장 수정·공통 기한·근거·기존 구분 건너뛰기를 구현했고 단계는 사용자 합의대로 별도 버튼을 유지한다. 아래 기능군 점수는 코드와 화면 연결 기준으로 갱신했으며 실제 일괄 등록 실행을 확인한 비율은 아니다. 테스트 추가·실행은 하지 않았다.

WEB-030 입력 편의 개선을 추가했다. 보고서·고객 검토·검토·검증·인증·등록의 기록 담당자 접기와 연구원 선택, 실제 날짜의 오늘·달력, 다음 검증 차수의 기존 기관·담당자 불러오기를 연결했다. 기존 큰 기능군의 부분 상태와 아래 거친 수치는 유지한다. 구문·공백·초기 화면 배치만 확인했으며 테스트 추가·실행과 실제 저장·차수 시작 확인은 하지 않았다.

설계서 v02 F-01~F-18, WEB-001~024 명세와 실제 HTML·JavaScript 연결을 하위 에이전트가 읽기 전용으로 대조했다. 이후 WEB-026 고객 검토, WEB-027 제3자 검증, WEB-028 인증·등록과 8→9, WEB-029 미정/내부/외부 검토 분기를 반영했다. WEB-025는 배치 교정이라 별도 큰 기능으로 세지 않는다. 이 현황은 테스트·런타임 검증률이 아니다.

## 요약

프로젝트 등록→담당자→범위 확정→자료 요청·제출→검토·승인→외부 계산 결과→해석→보고서→내부/외부 검토→완료 근거→인증·등록/고객 제출의 기본 길을 연결했다. 승인 원자료 CSV, 근거 변경 감지, PDF·Word 내보내기, 보고서 버전·고객 의견·검증 차수·지적 처리·완료 사본·제출 상태 이력을 구현했다. 검토 방식 미정과 내부 확인 기록도 추가했다. 기능마다 실제 실행 확인 범위는 각 SPEC을 따른다.

원래 18개 큰 요구사항 묶음을 모두 같은 비중으로 놓고, 합의한 기능 연결 1점·부분 구현 0.5점·미구현 0점으로 잡으면 **전체 약 33%, 최초 1차 범위 약 50%**다. 기능 연결 점수와 실제 실행 검증은 구분한다.

- 전체: (기능 연결 1개 + 부분 10개 × 0.5) / 18개 = 33.3%
- 1차: (기능 연결 1개 + 부분 9개 × 0.5) / 11개 = 50.0%
- WEB-033에서 F-06의 실제 기록 기반 할 일 화면을 연결했다. 만료 알림과 전체 실행 확인은 남아 있다. WEB-032까지는 전체 30.6%·1차 45.5%였다.
- WEB-031에서 F-03의 복수 선택과 일괄 저장을 추가했다. 실제 저장·중복·실패 등 실행 확인은 남아 있다. WEB-030까지는 전체 27.8%·1차 40.9%였다.
- WEB-028의 인증·등록 번호·날짜·상태 이력으로 F-12를 미구현에서 부분으로 바꿨다. 만료·점검·갱신은 남아 있다.
- WEB-026 전 최초 점검은 전체 22.2%·1차 31.8%였다. F-08을 미구현에서 부분으로 바꾼 결과이며 개발 시간의 진척을 뜻하지 않는다.
- WEB-027을 추가해도 F-01·F-08 전체 충족은 아직 아니므로 이 계산에서는 부분 상태와 수치가 유지된다. 작은 작업의 실제 증가가 이 거친 점수에 매번 반영되지는 않는다.
- 이 수치는 보수적인 체크리스트 추정이며 개발 시간·난이도·완성도 검증률이 아니다. 부분 구현의 깊이가 모두 같지도 않다.
- 큰 묶음 단위 점수이므로 보고서 내보내기·버전 보관 등 완성된 작은 기능 수를 직접 보여주지 않는다.
- PDF·Word·보고서 이력 등 추가 구현은 최초 기능군에 정확히 대응하지 않아 이 수치에 충분히 반영되지 않는다. 현재 확장한 앱 전체의 정밀한 공식 공정률로 사용하지 않는다.
- 10단계 중 1→9 연결이 전체 기능 90%라는 뜻도 아니다. 사후관리와 단계 내 세부 작업, 다른 큰 영역이 남아 있다.

## 이후 후보

2. 제출 이후 보고서 재작성용 단계 재개·새 제출 차수

할 일의 만료 알림·규칙 기반 메일도 최초 1차 범위에 남아 있다. 전체 JSON 백업/복원은 WEB-037에서 연결했으며 실제 실행 확인이 남아 있다. 규칙 기반 메일은 이후로 미룬 AI 메일 보조와 구분한다. AI·파일 추출·내부 LCA 계산은 별도 후속 확장이며 위 18개 분모에 추가하지 않았다. 내부 LCA 계산 엔진은 원 설계에서도 제외했다.

새 기능을 임의로 진행하지 않고 사용자와 순서를 정한다. 이후 구현이 늘면 이 날짜의 수치와 상태를 최신으로 갱신해야 한다.
