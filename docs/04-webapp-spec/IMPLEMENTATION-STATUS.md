# 구현 현황 점검 — 2026-10-18

설계서 v02 F-01~F-18, WEB-001~024 명세와 실제 HTML·JavaScript 연결을 하위 에이전트가 읽기 전용으로 대조했다. 이후 부모가 WEB-026 고객 검토와 WEB-027 제3자 검증 차수·지적 및 7→8을 반영했다. WEB-025는 배치 교정이라 별도 큰 기능으로 세지 않는다. 이번 조사는 테스트·런타임 검증이 아니다.

## 요약

프로젝트 등록→담당자→범위 확정→자료 요청·제출→검토·승인→외부 계산 결과→해석→보고서→제3자 검증의 기본 길은 연결했다. 승인 원자료 CSV, 계산·해석·보고서 근거 변경 감지, PDF·Word 내보내기, 보고서 버전 보관·변경 이력, 고객 의견과 검증 지적·답변·종결·수정 버전 연결, 검증 차수도 구현했다. 기능마다 실제 실행 확인 범위는 각 SPEC을 따른다.

원래 18개 큰 요구사항 묶음을 모두 같은 비중으로 놓고, 묶음 전체 충족 1점·부분 구현 0.5점·미구현 0점으로 잡으면 **전체 약 25%, 최초 1차 범위 약 35~40%**다.

- 전체: 부분 9개 × 0.5 / 18개 = 25.0%
- 1차: 부분 8개 × 0.5 / 11개 = 36.4%
- WEB-026 전 최초 점검은 전체 22.2%·1차 31.8%였다. F-08을 미구현에서 부분으로 바꾼 결과이며 개발 시간의 진척을 뜻하지 않는다.
- WEB-027을 추가해도 F-01·F-08 전체 충족은 아직 아니므로 이 계산에서는 부분 상태와 수치가 유지된다. 작은 작업의 실제 증가가 이 거친 점수에 매번 반영되지는 않는다.
- 이 수치는 보수적인 체크리스트 추정이며 개발 시간·난이도·완성도 검증률이 아니다. 부분 구현의 깊이가 모두 같지도 않다.
- 큰 묶음을 완전히 충족한 것만 완료로 세므로 ‘전체 충족 0개’는 완성된 작은 기능이 없다는 뜻이 아니다.
- PDF·Word·보고서 이력 등 추가 구현은 최초 기능군에 정확히 대응하지 않아 이 수치에 충분히 반영되지 않는다. 현재 확장한 앱 전체의 정밀한 공식 공정률로 사용하지 않는다.
- 10단계 중 1→8 연결이 전체 기능 80%라는 뜻도 아니다. 인증·등록 등의 단계 내 작업과 다른 큰 영역이 남아 있다.

## 근거와 제한

- 기준: `docs/02-design/lca-webapp-design.md` 4장
- 연결 UI: `web/index.html`, `web/js/app.js`, `web/js/views/`와 기능 도메인 모듈
- 일부 함수만 있는 미연결 규칙: `web/js/rules.js`의 missingInfo·recommendMail·todayTasks·projectStats
- 보고서 새 버전 저장·복원·비교·동시 쓰기는 WEB-024의 실행 검증이 남아 있다. PDF 확인과 Word 렌더 제한은 WEB-023을 따른다.

- WEB-027도 구문·공백·초기 화면만 확인했다. 실제 7→8 저장·복원·답변·종결·2차 시작·동시 쓰기 및 8단계 보고서 보완 실행 확인은 남아 있고 테스트 추가·실행은 하지 않았다.
