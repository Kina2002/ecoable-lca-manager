# 구현 현황 점검 — 2026-10-18

설계서 v02 F-01~F-18, WEB-001~024 명세와 실제 HTML·JavaScript 연결을 하위 에이전트가 읽기 전용으로 대조했다. WEB-025는 배치 교정이라 별도 큰 기능으로 세지 않는다. 이번 조사는 테스트·런타임 검증이 아니다.

## 요약

프로젝트 등록→담당자→범위 확정→자료 요청·제출→검토·승인→외부 계산 결과→해석→보고서의 기본 길은 연결했다. 추가 요청으로 승인 원자료 CSV, 계산·해석·보고서 근거 변경 감지, PDF·Word 내보내기, 보고서 버전 보관·변경 이력도 구현했다. 기능마다 실제 실행 확인 범위는 각 SPEC을 따른다.

원래 18개 큰 요구사항 묶음을 모두 같은 비중으로 놓고, 묶음 전체 충족 1점·부분 구현 0.5점·미구현 0점으로 잡으면 **전체 약 20~25%, 최초 1차 범위 약 30~35%**다.

- 전체: 부분 8개 × 0.5 / 18개 = 22.2%
- 1차: 부분 7개 × 0.5 / 11개 = 31.8%
- 이 수치는 보수적인 체크리스트 추정이며 개발 시간·난이도·완성도 검증률이 아니다. 부분 구현의 깊이가 모두 같지도 않다.
- 큰 묶음을 완전히 충족한 것만 완료로 세므로 ‘전체 충족 0개’는 완성된 작은 기능이 없다는 뜻이 아니다.
- PDF·Word·보고서 이력 등 추가 구현은 최초 기능군에 정확히 대응하지 않아 이 수치에 충분히 반영되지 않는다. 현재 확장한 앱 전체의 정밀한 공식 공정률로 사용하지 않는다.
- 10단계 중 1→7 연결이 전체 기능 70%라는 뜻도 아니다. 아직 고객 검토 등의 단계 내 작업과 다른 큰 영역이 남아 있다.

## 이후 후보

1. 고객 검토 의견을 보고서 버전과 연결하고 답변·종결·다음 버전 반영 기록
2. 제3자 검증 지적·보완 차수와 후속 단계 조건
3. 인증·등록·사후관리와 점검·갱신

오늘 할 일·규칙 기반 메일·전체 JSON 백업/복원도 최초 1차 범위에 남아 있다. 규칙 기반 메일은 이후로 미룬 AI 메일 보조와 구분한다. AI·파일 추출·내부 LCA 계산은 별도 후속 확장이며 위 18개 분모에 추가하지 않았다. 내부 LCA 계산 엔진은 원 설계에서도 제외했다.

새 기능을 임의로 진행하지 않고 사용자와 순서를 정한다. 이후 구현이 늘면 이 날짜의 수치와 상태를 최신으로 갱신해야 한다.
