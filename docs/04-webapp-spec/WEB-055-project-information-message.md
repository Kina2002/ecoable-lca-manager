# WEB-055 정보 확인 안내문

사용자 승인 순서의 두 번째 기능. 자료 요청과 구분해 고객에게 확인할 누락 정보·협의안을 선택하고 안내문을 만든다.

## 목적과 사용법

프로젝트 상세 → 자료 요청 → 요청문 만들기에서 ‘정보 확인’을 고른다. 고객 담당자, 희망 완료일, 평가 제품, 결과 활용처, 기준량·단위, 평가 범위, 자료 기준기간, 요구받은 기준 중 빈 정보나 협의할 범위만 목록에 보인다. 선택한 항목으로 문장을 만들고 기존처럼 수정·복사한다. 실제로 보냈다면 WEB-054 발송 사본을 기록한다. 자료 요청이 0건이어도 사용할 수 있다.

고객에게 평가 방법을 혼자 정하라고 요구하지 않는다. 거래처·인증기관의 요구 문서나 고객의 희망 사항을 공유받고 범위·기준은 함께 협의한다고 설명한다. 우리 측 연구원 배정·회사·부서는 고객에게 확인할 항목으로 만들지 않는다. 발신자 정보가 비었다면 초안에서 입력 필요로 안내한다. 고객 담당자 자체를 묻는 문장에는 고객사 담당자라는 일반 인사를 사용한다.

## 연결과 규칙

- 1~8단계 및 기존 읽기 가능 조건을 유지한다. 안내문을 만들거나 복사해도 값·범위·상태·단계는 바뀌지 않는다.
- 값이 채워지면 확인 대상에서 제외한다. 협의 중인 경계는 1~2단계에서 범위안 확인 항목으로 보여 주며 확정 후 제외한다.
- 선택한 정보나 발신자·프로젝트 정보가 바뀌면 옛 기준의 복사를 막는다. 직접 수정한 문구의 교체 확인도 유지한다.
- ‘정보 확인’ 할 일에 고객에게 물을 대상이 있을 때 요청문 바로가기를 제공한다. 자료 요청 미등록 등 내부 업무만 있는 할 일에는 고객 안내 바로가기를 억지로 만들지 않는다.
- 새 저장 키나 자동 입력은 없다. 실제 발송 사본은 WEB-054의 기존 발송 로그를 사용한다.

## 검증

자료 0건의 생성, 내부 연구원 질문 제외, 정보 입력 후 대상 제거·옛 초안 변경 감지, 완비한 프로젝트의 0건, 단계·읽기 전용 조건, 정보 확인 발송 사본 저장과 자료 미생성을 검사했다. 전체 자동검사 **253개**, 변경 JavaScript 구문·Git 공백·정적 자산 HTTP 200을 통과했다. 실제 브라우저에서의 선택·편집·이동·입력 유지 조작은 미확인이다.

면접 설명: “전력 사용량 같은 수치를 요청하기 전에 고객 담당자나 요구 범위를 먼저 확인해야 할 때가 있습니다. 그래서 빈 프로젝트 정보를 고객 질문으로 바꾸되, 연구원 배정처럼 우리 내부에서 정할 것은 제외했습니다. 답변을 받아 입력하면 같은 항목이 계속 질문 목록에 남지 않습니다.”
