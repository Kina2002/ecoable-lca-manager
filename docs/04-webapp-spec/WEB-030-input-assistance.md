# WEB-030 반복 입력 줄이기

작성일: 2026-10-18

## 1. 사용자 합의와 범위

사용자가 반복 입력이 많다는 불편을 말했고, 구현 계획을 확인한 뒤 승인했다. 보고서·고객 검토·검토·검증·인증·등록의 기록 담당자, 날짜 선택, 다음 검증 차수의 기존 정보 활용을 개선한다. 자료 요청 일괄 생성·오늘 할 일·전체 백업은 다음 별도 기능이다.

## 2. 기록 담당자와 실제 검토자

- 기존 프로젝트 담당 연구원 기본값을 유지하고, 작성자·기록자 입력을 공통 접기·펼치기 영역으로 모은다.
- 접힌 상태에서도 이름을 보여준다. 펼치면 직접 수정하거나 등록 연구원 목록에서 선택할 수 있다. 선택 목록은 연구원 번호를 함께 표시하되 기존 저장 형식처럼 이름만 보관한다. 연구원 ID를 기존 기록에 새로 연결하지 않는다.
- 프로젝트 담당자 이름과 같은 경우 기본값의 출처를 표시한다. 입력·기존 기록의 이름이 다르면 실제 기록한 사람인지 확인하도록 안내한다. 로그인한 사람이나 인증된 사용자로 표현하지 않는다.
- 기본 이름이 없으면 입력 영역을 처음부터 펼친다. 빈 담당자로 제출하면 해당 영역을 펼쳐 이름 칸에 초점을 둔다. 기존 필수 검사도 유지한다.
- 실제 내부 검토자는 별도로 직접 입력하거나 등록 연구원에서 선택한다. 기록 담당자로 자동 지정하지 않는다.
- 고객 의견을 준 사람과 외부 검증 담당자를 내부 연구원으로 임의 지정하지 않는다.
- 연구원 저장 기록을 읽지 못하면 목록을 숨기고 수동 이름 입력을 안내한다. 이 보조 기능은 저장소에 쓰지 않는다.

## 3. 실제 업무 날짜 선택

- 내부 검토일, 검증 지적 보완 기한, 검토·검증 완료일, 제출일, 발급·확인일에 공통 오늘 버튼과 기본 HTML 달력 입력을 제공한다.
- 오늘은 클릭 시점의 Asia/Seoul 날짜다. 날짜를 자동 확정하거나 빈 날짜를 화면 진입 때 채우지 않는다.
- 기존 숫자 8자리/날짜 직접 입력을 유지하고 달력과 동기화한다. 달력이나 오늘으로 입력해도 기존 input/change 이벤트를 전달해 미저장 변경·기준 충돌 검사를 적용한다.
- 실제 업무 날짜와 자동 저장 시각을 구분해 안내한다. 기존 날짜 유효성·전후 순서 검사는 도메인에 그대로 둔다.
- 읽기 전용·저장 중·오류 상태에서 날짜 버튼과 달력도 함께 비활성화한다. 동적으로 바뀌는 내부/외부 완료일 이름도 접근성 이름에 반영한다.

## 4. 다음 검증 차수와 대상 표시

- 다음 차수 입력을 처음 준비할 때 가장 최근 검증 차수의 기관·검증 담당자를 불러온다. 어느 차수에서 가져왔는지 표시하고 수정할 수 있다.
- 첫 차수에는 과거 기관·담당자를 만들지 않는다. 차수 메모·지적·답변·확인 체크를 이전 차수에서 복사하지 않는다.
- 사용자가 차수 입력을 시작했다면 일반 새로 읽기·기준 재확인·저장 실패 때 입력을 자동으로 덮어쓰지 않는다. 성공 후 다음 차수 준비 때 새로 저장된 차수를 기준으로 채운다.
- 보고서에는 저장할 다음 버전 번호를 표시한다. 기존 고객 의견 대상 버전 선택, 검증 차수 자동 증가·지적의 현재 차수 연결, 완료 근거 보고서 연결을 유지한다.
- 과거 기록·이력·저장 키·형식·업무 단계 조건·양쪽 자료 필터는 변경하지 않는다. 별도 자동 저장이나 로그인을 추가하지 않는다.

## 5. 구현 위치

- 공통 UI: `web/js/views/input-assist.js`
- 연결: `report-history.js`, `report.js`, `customer-review.js`, `review-route.js`, `verification.js`, `verification-issue.js`, `certification.js` (모두 `web/js/views/`)
- 로딩 순서와 캐시 버전: `web/index.html`
- 접힌 이름·날짜·인증 입력 스타일: `web/css/app.css`

## 6. 확인과 제한

- JavaScript 구문과 Git 공백 검사를 확인했다.
- 별도 localhost 탭에서 기존 가상 프로젝트를 열어 검토 방식의 접힌 기록자, 인증 화면의 오늘·달력과 비활성 상태 배치를 확인했다. 사용자 127.0.0.1 탭을 새로고침하거나 저장 기록을 수정하지 않았다.
- 테스트 추가·실행은 하지 않았다. 실제 이름 변경 저장·달력/오늘 입력 저장·다음 차수 불러오기·실패/동시 변경·작은 화면/키보드의 전체 동작은 실행 확인하지 않았다.
- 이전 WEB-024~029에 남은 저장·단계 이동·호환 확인을 이번 작업으로 완료 처리하지 않는다.
- 기존 브라우저 저장 범위이며 기기 공유·인증된 사용자 식별·서버 감사 기록·실제 파일 첨부를 구현한 것이 아니다.
