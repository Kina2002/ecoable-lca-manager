# WEB-044 할 일에서 상황에 맞는 요청문 만들기

구현일: 2026-10-19

## 사용자 합의

할 일에서 ‘요청문 만들기’를 누르면 해당 프로젝트·자료·기한·연구원 정보를 채우고, 상황에 맞는 종류를 골라 초안을 만든다. 기존 요청문을 재사용하고 마감 임박 전용 안내문을 추가한다.

## 사용 흐름

1. 할 일의 기한 초과/마감 임박/보완 요청 항목에서 **요청문 만들기**를 누른다.
2. 최신 기록을 읽고 해당 프로젝트의 자료 요청 탭과 요청문 영역을 연다.
3. 해당 자료 **한 건만 선택**하고 다음 종류로 제목·본문을 만든다.

| 최신 할 일 종류 | 요청문 종류 |
| --- | --- |
| 기한 초과 | 미제출 재요청 |
| 마감 임박(오늘~3일 뒤) | 마감 임박 안내 |
| 보완 요청 | 보완 요청 |

4. 회사·제품·고객 담당자·기준기간·자료 번호/내용·기한·연구원 소개/서명을 확인하고 글을 고친 뒤 기존 복사 기능을 사용한다.
5. **← 할 일로**를 누르면 기존 유형/연구원/검색/스크롤 위치로 돌아간다. 가능한 경우 해당 요청문 버튼에 초점을 맞추고, 버튼이 없어졌으면 업무 제목이나 제목 영역을 사용한다.

## 대상과 최신 기록

- 자료 검토·고객 의견·검증 지적·정보 확인에는 자료 재요청 버튼을 붙이지 않는다. 프로젝트 9단계 이후/읽기 전용도 제외한다.
- 이동 전 최신 할 일과 자료를 다시 확인한다. 이미 처리됐거나 제출/삭제/승인되면 원래 할 일 화면에서 안내한다. 여전히 같은 자료가 다른 종류의 할 일에 해당하면 최신 종류를 사용한다.
- 자료 번호는 행 순서가 아닌 프로젝트 ID/요청 ID로 연결한다. 대상 이외의 요청을 자동으로 함께 선택하지 않는다. 요청문 화면에서 사용자가 다른 적합한 자료를 추가 선택하는 기존 기능은 유지한다.
- 자료 요청 상태 필터 두 개를 초기화하지 않는다. 요청문 영역으로 바로 이동하며 자료 목록의 초점 이동을 호출하지 않는다.
- 마감 임박 안내는 미삭제·`요청` 상태·받은 자료 없음·유효한 기한이 오늘부터 3일 이내인 자료만 대상으로 한다. 기한 초과/4일 이후/날짜 불명/제출됨/검토 중/보완 요청/승인은 제외한다. 요청문 화면에서도 직접 선택할 수 있다.
- 최초/미제출 재요청의 기존 수동 대상 규칙은 유지한다. 보완 요청은 기존 제출 기한과 저장 보완 사유를 쓰고 새 보완 날짜를 임의로 확정하지 않는다.

## 작성 글과 복사 보호

- 새 초안은 자동으로 만들되, **같은 프로젝트에서 직접 수정 중인 글은 덮어쓰지 않는다.** 새 종류/자료를 선택하고 기존 글을 유지한 채 교체 확인과 생성 버튼을 안내한다. 체크하지 않으면 다시 만들 수 없다.
- 기존 수정 글 보호, 선택/종류가 다른 글의 복사 차단, 복사 직전/직후 최신 정보와 생성 근거 비교, 클립보드 미지원/거부 시 수동 복사를 재사용한다.
- 요청문을 다시 만들 때도 최신 자료를 읽는다. 임박 안내가 자정을 지나 기한 초과가 되면 같은 임박 안내를 복사하지 못한다.
- 자동 생성 시 누락 값은 기존처럼 `[입력 필요: …]`로 표시한다. 수신자/기간/내용/기한을 확인한 뒤 사용한다.
- 복사 처리 중에는 바로 생성으로 글을 교체하지 않는다. 생성/이동 직전 기록이 다시 바뀌면 요청문 영역에서 오류를 표시하고 글을 유지한다.
- 다른 프로젝트로 이동할 때는 기존처럼 해당 프로젝트 화면을 만든다. 프로젝트 사이의 미저장 초안을 영구 보관하는 기능은 추가하지 않았다.

## 저장과 범위

- 새 저장 키/형식 변경은 없다. 자료 상태·단계·보고서·이력은 바꾸지 않는다.
- 메일 발송/계정 연결/AI/보낸 기록은 이번 합의에 포함하지 않았다. 버튼은 요청문 초안을 준비한다.
- 홈의 기존 할 일 제목 이동은 유지한다. 이번 바로가기 버튼은 할 일 탭에 추가했다.
- 한 행 목록 안에 작은 버튼을 배치한다. 좁은 화면은 줄바꿈하며 모바일 버튼 높이는 44px다.

## 확인 범위

- 변경 JavaScript 4개 구문 검사, diff 공백 확인.
- 임시 브라우저 탭에서 앱과 자료 요청 화면이 열리는 것, 요청문 종류 네 개, ‘마감 임박 안내’ 선택 시 설명과 대상 0건/생성 비활성 표시의 초기 배치를 확인했다.
- 사용자 원래 탭을 새로고침하거나 저장 기록을 변경하지 않았다. 현재 기록에는 바로가기 대상 자료가 없어서 실제 버튼→자동 초안 생성·직접 수정 글 보호·복귀의 전체 실행은 확인하지 않았다.
- 자동 테스트 추가·실행은 하지 않았다. 상태/기한 경계·다른 창 변경·전체 이동/복사·모바일 실행 확인은 남아 있다. WEB-040의 217개 결과를 이번 결과로 사용하지 않는다.
