# WEB-047 계수 출처 표시 바로잡기

기준: 사용자가 활동량·계수의 1차/2차 뜻을 확인한 뒤, 계수 화면을 ‘해당 공급자·공정 계수 / 외부 데이터셋 계수’로 고치라고 요청했다. WEB-046의 출처 기록 기능에 대한 용어 교정이다.

## 왜 고치는가

‘1차 · 직접 만든 계수’는 직접 만들기만 하면 1차 계수가 되는 듯한 오해를 준다. [GHG Protocol Product Life Cycle Accounting and Reporting Standard, 8.3.5~8.3.6](https://ghgprotocol.org/sites/default/files/ghgp/standards/Product-Life-Cycle-Accounting-Reporting-Standard-EReader_041613_0.pdf)는 연구 대상 공정의 활동량을 1차·2차로 설명하지만, 계수는 1차·2차 분류가 필수는 아니라고 명시한다. 계수에는 어디에 맞춘 자료인지, 외부 데이터셋을 사용했는지가 더 직접적인 안내다. 이 용어 교정이 한국 환경성적표지 등 모든 제도의 계수 분류 기준을 대신하지는 않는다.

## 동작

- 받은 자료 입력에서 계수 출처 선택지를 ‘해당 공급자·공정 계수 / 외부 데이터셋 계수’로 보인다. 전자는 조사 대상과 관련된 공급자 또는 공정에 맞춘 계수라는 뜻이며, 단순히 자체 작성했다는 뜻이 아니다.
- 외부 데이터셋 계수를 고르면 기존처럼 DB·데이터셋 이름·버전·연도·제공처를 필수로 적는다. ‘아직 모름’은 그대로 둘 수 있다.
- 받은 자료 요약, 승인 자료 CSV, 새로 열거나 만드는 보고서에도 같은 말로 표시한다. 과거 보고서의 저장된 원자료 사본은 변경하지 않는다.
- 활동량의 1차·2차 구분은 유지한다. 활동량 출처와 계수 출처는 따로 기록한다. 계수값을 입력하거나 환경영향을 계산하는 기능은 추가하지 않는다.

## 기존 기록과 저장 형식

기존 `receipt.provenance.factorSource`의 저장값 `'1차'`와 `'2차'`는 그대로 둔다. 선택지의 값과 기존 검증·백업 형식도 바꾸지 않는다. 표시할 때만 각각 새 이름으로 바꾼다. 따라서 기존 브라우저 기록과 JSON 백업을 다시 쓸 필요가 없다. 이 값은 **앱 내부의 이전 저장 코드**이며, 표준이 계수를 반드시 1차·2차로 판정한다는 주장이 아니다. 앞으로 저장 형식 자체를 바꾸려면 별도 이관이 필요하다.

## 확인 기준

- 기존 `'1차'/'2차'` 값을 읽고 다시 저장해도 원래 값이 유지된다.
- 선택지·요약·CSV·보고서에서 사람이 보는 표현을 확인한다.
- 외부 데이터셋의 필수 정보 검사와 기존 자료 검토·승인 흐름이 그대로 동작한다.
- JavaScript 구문·전체 자동검사 **229개**·공백 검사를 통과했다. 실제 브라우저 클릭과 좁은 화면 배치는 별도 확인 항목이다.

면접 설명: “활동량은 조사 대상 공정에서 나온 실제 자료인지 구분하고, 계수는 공급자·공정에 맞춘 것인지 외부 데이터셋인지 보여 줍니다. 계수까지 무조건 1차·2차라고 부르면 오해가 생겨 화면 용어를 고쳤고, 기존 기록은 표시만 바꿔 보존했습니다.”
