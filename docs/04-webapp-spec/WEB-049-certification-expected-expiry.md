# WEB-049 인증·등록 예상 만료일

기준: 설계서 v02 F-12의 만료일 규칙. 사용자가 인증일의 뜻을 확인한 뒤 우선 기능을 만들어 달라고 요청했다. 현재 `발급·확인일`은 인증서 발급일과 고객 확인일을 함께 받으므로, 고객 제출에는 만료일을 계산하지 않는다.

## 왜 만드는가

인증·등록 번호와 발급일만 적어 두면 유효기간을 놓치기 쉽다. 발급일에서 예상 만료일을 바로 볼 수 있게 해 담당자가 발급 문서의 날짜와 대조하도록 돕는다. 이 날짜는 **시연 프로그램의 계산값**이며 기관이 발급한 인증서나 등록 목록의 실제 만료일을 대신하지 않는다. 특히 [International EPD의 공개 EPD 예시](https://api.environdec.com/api/v1/epdlibrary/files/8168b86f-ab27-4bd3-16f7-08dbca69748b/data)는 게시일과 유효 종료일이 단순히 정확히 5년 차이가 나지 않으므로 공식 날짜를 확인해야 한다.

## 사용 흐름과 계산 대상

1. 프로젝트의 ‘인증·등록’에서 진행 유형을 **인증**, 제도를 **환경성적표지** 또는 **저탄소제품**으로 고르고 승인·등록 상태와 발급일을 입력하면 `발급일 + 3년 − 1일`의 예상 만료일을 표시한다.
2. 진행 유형을 **등록**, 제도를 **International EPD**, **EPD Norway**, **UL EPD** 중 정확한 이름으로 고르면 `발급·등록일 + 5년`의 예상일을 표시한다. 자유 입력과 추천 목록을 함께 둬 기존 요구명 입력을 보존한다.
3. 고객 제출의 확인일, 승인 전 기록, 다른 제도 이름, 유형과 제도의 잘못된 조합, 날짜 오류에는 계산하지 않고 이유를 안내한다.
4. 입력 중에도 예상일을 보고, 저장 후 다시 열거나 프로젝트 완료 후 조회할 때에도 저장된 정보에서 같은 예상일을 계산해 보여 준다. 공식 증명서·등록 목록의 실제 만료일 확인을 항상 안내한다.

윤년인 2024-02-29에서 국내 3년 계산은 달력상 2027-03-01을 거쳐 하루 전인 **2027-02-28**이다. 앱의 날짜 계산은 UTC 달력을 사용해 컴퓨터 시간대의 영향을 받지 않는다.

## 데이터 보존과 범위

예상 만료일은 현재 인증 기록에서 읽을 때 계산하며 저장하지 않는다. 기존 `certification.v1` 구조, 백업·복원, 변경 이력과 프로젝트 단계는 그대로다. 이전에 저장된 정확한 제도명·유형·발급일에도 표시되며 값은 임의로 채우지 않는다. 이번 기능은 만료 임박 상태, 갱신 알림, 점검일, 실제 만료일 입력·확정, 인증 취소를 만들지 않는다. 제도 규칙은 실제 업무에 적용하기 전 당시의 공식 원문과 발급 문서로 다시 확인해야 한다.

## 확인 자료

- 국내 3년은 설계서 v02의 규칙과 [환경성적표지 유효 인증현황](https://www.data.go.kr/data/15089157/fileData.do)의 시작·종료일 형식을 참고했다.
- EPD의 5년은 설계서 v02와 [EPD International의 5년 설명](https://environdec.com/news/sunset-date-for-gpi-v-2-5-and-pcrs-following-old-en-15804-2012-a1-2013), [EPD Norway PCR 예시](https://www.epd-norge.no/getfile.php/13162157-1741628312/PCRer/NPCR%20024%202016%20version%201.0%20Explosives%20and%20Initiation%20Systems.pdf), [UL PCR 예시](https://code-authorities.ul.com/wp-content/uploads/sites/2/2014/09/ULE_PCR_Part_B_Processed_Glass_v13.pdf)를 참고했다. PCR·프로그램의 최신판과 개별 EPD의 유효일은 직접 확인 대상이다.

## 시험과 면접 설명

국내·EPD의 계산, 윤년, 고객 제출·미승인·이름 불일치·잘못된 날짜 제외를 자동검사로 확인했다. **전체 232개 통과**, JavaScript 구문·Git 공백 검사 통과, 로컬 서버의 HTML·새 스크립트 HTTP 200을 확인했다. 사용자의 브라우저에서 직접 클릭·모바일 배치를 확인하는 일은 남는다.

면접 설명: “신청일이나 우리 프로젝트 완료일은 인증 유효기간의 출발점이 아닙니다. 인증·등록이 승인된 뒤 기록한 발급일로만 예상 만료일을 계산하고, 고객사의 단순 확인일에는 적용하지 않았습니다. 최종 효력은 발급 문서의 실제 유효일을 확인하도록 안내합니다.”
